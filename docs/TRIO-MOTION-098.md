# 0.9.8 셋소호 정지·걷기 적용

[적용 지시](OPUS-IDLE-WALK-INTEGRATION.md)를 따라 승인된 48장을 게임에 연결했다. 그림은 `docs/art/chibi-refresh/approved/`에서 읽기만 하고 다시 그리지 않았다. 상인과 초상화는 그대로다.

## 무엇이 바뀌나

- 세트, 소망, 호루스는 서 있을 때 방향별 정지 그림으로, 걸을 때 방향별 걷기 세 포즈로 그린다. 순서는 `0 → 1 → 2 → 1`, 한 단계 180ms다.
- 멈추면 바로 그 방향의 정지 그림으로 돌아가고, 다음 걸음은 포즈 0부터 시작한다. 걷는 중에 방향을 바꾸면 걸음 위상은 이어진다.
- 벽을 따라 미끄러지면 계속 걷는다. 벽에 완전히 막혀 좌표가 안 변하면 정지 그림으로 서서, 누른 방향만 바라본다.
- 카드가 열리면 선다. 서 있는 NPC는 서 있다. 동행 중인 세트와 호루스는 소망이 걸을 때 걷고, 멈출 때 멈춘다.
- **호루스 정면 걷기만** 승인된 오프셋으로 그림 전체를 옮긴다. `(+1,0) (0,-1) (-1,0) (0,-1)`이고 단위는 원본 걷기 셀 픽셀이다. 게임에서는 `원본 1px × 표시 높이 / 330`만큼 움직인다. 회전이나 좌우 흔들림은 넣지 않았다.
- 옛 그림에 있던 1 논리 픽셀 위아래 흔들림은 셋소호 경로에서 뺐다. 상인 같은 옛 그림 NPC는 예전 그대로다.

## 크기와 기준점

- 게임 표시 높이는 정지와 걷기 모두 **24 논리 픽셀**이다. 한 칸이 16이니 1.5칸이고, 머리부터 발까지다. 옴보스 신전 앞과 안채 방에서 문, 가구와 비교해 정했다.
- 패커 `tools/art/pack-trio-motion.py`가 정지는 `192/628`, 걷기는 `192/330` 배율로 똑같이 줄인다. 그래서 서 있을 때와 걸을 때 보이는 키가 192 아틀라스 픽셀로 같다. 프레임마다 알파 영역을 꽉 채워 늘리지 않는다.
- 출력은 `data/art/characters/trio-motion.png` 한 장, 2018×1192다. 프레임 표는 `data/sprites.json`의 `looks.<누구>.motion`에 들어간다. 각 프레임은 `[x, y, 너비, 높이, 발x, 발y]`다. 원본 해시를 manifest와 대조하고 나서 패킹한다.
- 발 기준점은 manifest의 pivot을 그대로 옮겼다. 정지는 310,662, 걷기는 180,370이다. 이 점을 타일 아래 가운데에 세운다. 이동 좌표, 발 충돌, 상호작용 범위, 가림 순서는 바꾸지 않았다.
- 옛 `pocket-chibi.png`와 `atlas`는 상인과 예전 경로를 위해 남겨 두었다. `pack-pocket-sprites.cjs`는 실행하지 않았다.

## 바꾼 코드

| 파일 | 내용 |
|---|---|
| `src/core/data.js` | `motion.file`도 함께 불러온다 |
| `src/core/check.js` | 사각형, 이미지 경계, 발 기준점, 방향마다 포즈 세 장, 순서, 시간, 오프셋 수를 검사한다 |
| `src/world/render.js` | `motionPerson()`: 정지와 걷기 선택, 순서, 호루스 오프셋, 부드러운 축소, 발 그림자 |
| `src/world/player.js` | 실제로 움직였는지와 걸은 시간 `walkT`. 멈추면 0. 동행도 같은 값을 받는다 |
| `src/ui/window.js` | NPC는 `moving:false`, 동행은 실제 이동 상태를 넘긴다. 카드가 열리면 선다 |
| `src/ui/hud.js` | 말 걸기 말풍선을 더 커진 머리 위로 올린다 |

## 확인

- `checkData()` 오류 0. 세 캐릭터 × 4방향 × 정지, 걷기 4단계를 게임 렌더러로 직접 그려 한 장에 모았다. [포즈 표](consult/trio-motion-098/poses.png)
- 폰 412×900, 2배 화면: [신전 앞 셋](consult/trio-motion-098/yard.png), [세트 방 동행 걷기와 멈춤](consult/trio-motion-098/companion.png)
- 실제 키 입력으로 걷기 위치와 상태를 추적했다. 걷는 동안 `moving=true`이고 `walkT`가 늘어난다. 키를 떼면 `moving=false`, `walkT=0`이다.
- `verify-full-map.cjs`, `verify-pocket-sprites.cjs`를 돌렸다. 결과는 커밋 메시지에 남긴다.

## 남은 확인

- 이동 속도는 초당 4.2칸 그대로이고, 걸음 한 주기 720ms 동안 3칸을 간다. 몸 1.5칸에 비해 보폭이 큰 편이라 빠르게 걸으면 발이 조금 미끄러져 보일 수 있다. 지시대로 180ms로 연결했다. 사용자가 폰에서 보고 원하면 걸음 시간이나 거리 기준 위상으로 조정한다.
- 정지와 걷기는 서로 다른 생성물이라, 전환 순간 얼굴 크기와 옷 길이가 아주 조금 달라 보일 수 있다. 같은 높이로 맞췄고, 원본은 고치지 않았다.

## 0.9.9 전신 보기도 정지 스프라이트로

사용자 요청으로 파티 카드, 전신 크게 보기, 소망 카드의 전신 그림을 승인된 정면 정지 그림으로 바꿨다. `data/art/portraits/{set,somang,horus}-idle-full.png`는 원본 `approved/idle/*-front.png`를 알파 경계에서 12px 여유만 두고 자른 것이다. 크기 조정이나 다시 그리기는 하지 않았다. 대화 상반신과 소망의 다문 미소·활짝 웃기는 그대로다. 정지 그림은 표정이 하나라서 전신 화면에서는 표정 버튼을 뺐다. 예전 전신 PNG는 지우지 않았다.
