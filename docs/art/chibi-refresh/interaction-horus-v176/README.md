# 호루스 상호작용176 — 4방향×2프레임 확인 대기

사용자 요청 “이제 호루스 상호작용8장 하자”에 따라 최신 main의 ASTRA-PLAN 2단계 진행 순서, ASTRA-HANDOFF의 시안·검수 지침과 pose-guides를 다시 읽고 제작했다. 세트175는 이번 사용자 응답으로 채택됐으며 호루스176은 별도 확인 대기다.

## 파일과 재생

- `png/horus-{front,back,left,right}-{0,1}.png`: 투명RGBA8장,620×720. 발 기준점(310,662), 기준 키576.
- front/back/left/right = 게임 down/up/left/right.
- 0 손 뻗기 시작 →1 닿음. 각150ms, 한 번 재생 후 같은 방향 정지.
- `previews/horus-interaction-four-directions.gif`: 네 방향을 동시에 보여 주며 정지1200ms→시작150ms→닿음150ms를 반복하는 확인용.
- `previews/idle-interaction-walk-light.png`, `idle-interaction-walk-dark.png`: 방향별 정지 / 상호작용0·1 / 걷기0·1·2.
- 비교 시 걷기는 기준 키330→576과 발 기준점에 맞춰 표시한다. 게임용 걷기 파일은 바꾸지 않았다.

## 제작 기준

베이스는 `../final/horus/`의173 최종 정지4장·걷기12장.168 피부 팔레트와173 비율이 이미 반영된 파일이며 비율 변환을 중복 적용하지 않았다. 네 방향의 실제 정지와 걷기를 열고, 방향별 `../pose-guides/horus-<방향>-guide.png`를 밑그림 참조로 넣었다. 문양 때문에 좌우를 따로 그렸다.

서서 무릎을 편 채 단정하게 손을 내민다. 정면은 오른손을 몸 가까이 모았다가 앞으로 내밀며 원근으로 짧아진 손바닥이 보인다. 뒷면은 오른팔을 앞으로 들고 머리 옆에서 손이 문에 닿는다. 옆모습은 먼 쪽 팔이 진행 방향으로 뻗고 가까운 팔은 몸 옆에 둔다. 물체·효과는 넣지 않았다.

방향별 두 프레임 생성 원본은 `sources/`에 있다. 정면·왼쪽은 생성 초안의 몸 길이가 짧아 최신 정지 원본 위에 새 팔 동작을 국소 반영했다. 머리나 몸을 따로 늘이거나 줄여 검사 수치에 맞추지 않았다. 뒷면·오른쪽은 생성 결과를 균등 배율로 정렬했다. 내보내기에서 알파8/255 이하 잔여값을 제거하고 알파0.85 이상을 불투명으로 정리했다.

## 검수

최종PNG8장 모두 `python3 tools/art/fit-scale.py <PNG> --who horus --view <방향>` 결과 **맞음**. `checks/delivery-summary.json`과 방향별 리포트에 수치를 남겼다. 정면·왼쪽은 정지 원본 발 위치를 그대로 유지했으며 도구의 별도 발 정렬 출력으로 다시 덮어쓰지 않았다.

정지·걷기와 나란히 놓은 밝은/어두운 비교, 목·어깨·팔꿈치·손목·치마 연결 확대, 발 확대와 실제GIF의 세 프레임을 직접 확인했다. 좌우의 짧은 팔·손 크기를 함께 비교하고, 정면 화면오른쪽·왼쪽 옆모습에만 눈 문양이 있는지 확인했다. 최종 베이스48장 해시는 모두 그대로다.

보조검사 `checks/sprite/`는 정면·왼쪽4장 같은 범위, 뒤·오른쪽4장 옷 색 차이 판정이다. 보조 분류가 실제 흰 치마와 다른 피부·금장 색을 잡으므로 전체 통과로 쓰지 않았다. 흰 치마 영역을 별도로 확인한 `checks/white-kilt-color.json`의 중앙값은 원본(250,238,223), 뒤(250,240,226), 오른쪽0(250,241,229)·1(250,244,233)이다. 따뜻한 아이보리 명암을 직접 비교했다. 몸 안 가는 투명줄과 흰 테두리 판정도 리포트에 남겼다.

아트 채택과 게임 적용은 별도다.176은 사용자 확인 대기이며 런타임 파일을 변경하지 않았다.
