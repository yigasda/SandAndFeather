# 셋소호 최종 베이스 스프라이트 — 48장

사용자 최종 채택: “완벽해 고생했어! 이제 베이스 스프라이트는 끝났네”. **이 폴더만 사용한다.** 이전 시안·구버전·중복 묶음은 사용자 요청으로 삭제했으며 git 기록에서 복원 가능하다.

| 캐릭터 | 정지 | 걷기 | 합계 |
|---|---|---|---|
| 세트 `set/` | 상하좌우4장 | 방향별3장×4=12장 |16장|
| 소망 `somang/` | 상하좌우4장 | 방향별3장×4=12장 |16장|
| 호루스 `horus/` | 상하좌우4장 | 방향별3장×4=12장 |16장|

각 캐릭터의 `idle/`와 `walk/`에 투명RGBA PNG 원본을 넣었다. **원본과 바이트 동일하며 이번 정리에서 그림·크기·색·픽셀을 수정하지 않았다.** `back`=상, `front`=하, `left`=좌, `right`=우. 걷기 파일 끝0·1·2가 프레임 번호다.

## 게임 적용 규격

- 정지620×720, 발 기준점(310,662), **referenceVisibleHeight576**.
- 걷기360×400, 발 기준점(180,370), **referenceVisibleHeight330**.
- 각 프레임 알파 영역에 맞춰 제각각 크기를 늘리지 않는다. 위 공통 기준 키로 배율을 계산하고 발 기준점을 맞춘다. 예전 정지 기준628은 사용하지 않는다.
- 걷기 순서0→1→2→1,180ms. 호루스 정면은 이 순서에 대응하는 전체 스프라이트 위치 보정[(1,0),(0,-1),(-1,0),(0,-1)]을 유지한다. 나머지는(0,0).
- 정지: 세트148, 소망151, 호루스166. 걷기: 세트·소망163, 호루스166. 호루스 정면 정지·걷기3장의105% 확대는 **파일에 이미 반영되어 있으므로 다시 확대하지 않는다.**
- `manifest.json`: 파일별 경로·크기·발 위치·해시·채택 원본의 git 위치. `path`는 저장소 루트 기준, `relativePath`는 이 폴더 기준.
- 아트 최종 채택과 게임 적용은 별개다. 게임 파일은 이번 작업에서 수정하지 않았다. `runtimeEligible=false`는 기존 패커의 무검토 적용을 막는 값이며 아트 반려를 뜻하지 않는다.

## 다운로드와 확인

`downloads/`에 캐릭터별16장 ZIP3개와 전체48장 ZIP이 있다. ZIP의 `manifest.json`에 적용 명세가 포함된다. `previews/`는 확인용 정지→걷기GIF와 밝은/어두운 배경PNG이며 게임 스프라이트로 사용하지 않는다.

이전 버전 복구: manifest의 `sourceGitCommit`·`sourceGitPath`로 `git show <commit>:<path>`를 사용한다. 이전 자료를 현행 최종 폴더에 섞지 않는다. 전달물 재생성은 `python3 tools/art/package-final-trio.py`.
