# 픽셀동화 가로 메뉴 적용

기준: `3b830b0b977b4a463cc234d12ca62bb854de8932`. 최초 검토 이후 2026-10-22 사용자가 승인한 헤더 두 부품을 포함하여 0.9.94 릴리스 대상으로 검증했다. 아래 초기 탭 검사와 추가 헤더·배포 검사를 구분한다.

## 실제 탭과 적용 범위

- 세계: 실제 맵과 HUD. 팝업으로 바꾸지 않으며 변경하지 않는다.
- 일행: 기존 앞장 3명, 동행 선택, 인연/자세히 버튼과 저장 동작을 그대로 둔다. 현재 앞장/동행 표시 아래 두 열로 배치하고 각 목록은 스크롤할 수 있다.
- 인연과 유대: 승인된 1842×854 배치와 실제 기능을 보존한다. 추가 승인된 헤더 두 부품, 그 자산 경로와 이전 rail crop만 변경한다.
- 임무: 작은 모험/매일 의뢰/배움/축제와 챗 메모/일지를 두 열에 배치한다. 기존 지우기/꺼내기/업적 동작을 그대로 둔다.
- 지도: 실제 minimap canvas와 위치 표식을 왼쪽에, 실제 안내/탐사 수첩/오벨리스크 이동을 오른쪽에 둔다. 등록된 map part를 복제하거나 생략하지 않는다.

## PNG 부품 매핑

- 공통 창: body.background, header.underlay, header.background-restored, window.frame.
- 헤더: header.lower-rail, header.left-junction, ornament.header-lotus. 승인된 장면 배치 좌표를 유지한다. 추가 승인된 rail/junction 두 부품 외의 PNG는 변경하지 않는다.
- 메뉴: nav.*.frame / face-restored와 icon.home / heart / rings / scroll / map / close. 현재 탭에는 기존 초록 선택 프레임을 재사용하고, 프레임과 채움의 모서리는 함께 12px 9-slice로 보존한다.
- 목록/지도 패널: panel.record1.fill / frame / corner-ornaments를 동일한 56px 원본 슬라이스로 겹쳐 사용한다. 밀도 높은 매일 의뢰 행은 세 레이어의 모서리를 모두 32px로 같은 비율로 표시한다.
- 실제 버튼: tab.neutral.fill / frame, tab.selected.fill / frame를 동일한 16px 9-slice로 겹쳐 사용한다.
- 글자는 실제 한국어 폰트와 원래 게임 데이터를 사용한다. 전체 화면 PNG를 배경으로 붙이거나 CSS로 장식을 다시 그리지 않는다.

## 보존 방식

새 모듈은 cozy(픽셀동화) + 가로 + party/quests/map 최상위 메뉴에만 활성화한다. 기존 .sf_pop, 버튼, 이벤트 리스너, 목록 노드와 canvas를 그대로 사용한다. 회전/테마 변경 시 임시 레이아웃 그룹을 풀어 원래 DOM 순서를 복원한다. 장면 자산 90개와 manifest의 112개 배치 수를 유지한다. 기존 세로/보조 카드 CSS가 쓰는 rail PNG는 별도로 원래 바이트를 보존한다. 별도 승인된 헤더 두 PNG만 교체하고, 두 가로 렌더러에서 새 rail을 자르지 않도록 처리한다. 그 외 PNG와 인연 장면 배치는 보존한다.

## 검사

### 초기 탭 적용 검증

- 수정 JS의 ES module 문법 검사 완료.
- 실제 실행 검사는 GitHub Actions의 격리된 SillyTavern에서 한다. 로컬 게임 실행이나 조립 이미지를 런타임 증거로 사용하지 않는다.
- 대상: 일행/임무/지도 1842×854, 844×390 캡처, 실제 탭/앞장/동행/상세/업적/탐사/스크롤 동작, 회전 복원, 세로/다른 테마/세계/인연 장면 기준 비교.
- 검증한 게임 코드: `1fb78789d3b4258b89a49809d3f51296124f2db3`.
- [최종 GitHub Actions 실행](https://github.com/yigasda/SandAndFeather/actions/runs/39700536665): 통과. 실제 탭 이동/반복 이동, 앞장/동행 변경과 재표시, 자세히, 업적, 탐사 수첩, 닫기/Escape, 스크롤, 세로 회전과 classic 테마 전환/복원, 기존 지도 canvas 동일성 검사를 포함한다. 사용자 저장 데이터에 접근하지 않고 격리된 기본 데이터만 사용했다. 게임 페이지 오류는 없었다.
- [읽을 수 있는 기준 캡처](https://github.com/yigasda/SandAndFeather/actions/runs/39699082403)는 최초 기준 SHA를 실행했다. CI 호스트에 공식 Ubuntu 한국어 대체 글꼴을 설치하여 세로/다른 테마에 글꼴 변경을 넣지 않았다.
- [같은 최종 코드의 맞춤/픽셀 검토 캡처](https://github.com/yigasda/SandAndFeather/actions/runs/39700109097): 1842×854 및 844×390에서 일행 3명/동행 3개 선택과 매일 의뢰 4행이 모두 보임을 확인했다. 이 실행의 업적 팝업 개수 가정은 테스트 오류였고, 최종 실행에서 실제 기존 교체 동작에 맞게 수정했다. 게임 코드는 바꾸지 않았다.
- 세로 390×844 일행/임무/지도 PNG는 기준과 픽셀 단위로 동일했고, 원래 DOM의 위치/크기/텍스트도 같았다. 세계 390×844 및 844×390 역시 같은 DOM 위치/크기/텍스트를 유지했다. 세계의 픽셀 차이는 기존 애니메이션 표식의 작은 영역에만 있었다. 인연 장면과 모든 기존 PNG/manifest는 소스 변경이 없다.
- 최종 화면은 실제 런타임 캡처로 검토했다. 세로와 대표 다른 테마 classic의 복원은 표적 검사이며, 모든 테마/게임 기능의 전체 회귀 검사를 대신한다고 주장하지 않는다.
- 위 검사는 헤더 교체 전 기준이다. 2026-10-22 추가 승인에 따라 rail/junction 두 PNG를 원본 크기로 교체했다. 배치는 그대로이며, 이전1597×985 rail용 crop은 두 렌더러에서 제거했다. 기존 세로/보조 카드 CSS의 header.lower-rail.png는 그대로 두고 새 header.lower-rail-landscape.png를 가로 장면 manifest에서만 사용한다. 이 추가 변경의 런타임 캡처와 배포 전 검사는 아래에 기록한다.


### 승인 헤더와 보존 검증

- 최종 런타임 자산·코드 기준은 `7527fb1bd7615e50cba5bb81d63d9dc3bc0da7b1`이다. 이후 `04d73fe236c53d2ebcc679318c9f20aa65b87597`까지의 변경은 테스트 세 파일뿐이며 게임 코드·자산은 동일하다.
- 새 rail은 1783×11, junction은 29×38이다. 기준 배치 [35,108,1818,119] 및 [24,109,53,147]을 유지한다. 기존 1597×985 rail용 crop을 제거하고 새 가로 rail을 직접 IMG로 표시한다.
- [헤더 보존 실행](https://github.com/yigasda/SandAndFeather/actions/runs/39725117589): 인연/일행/임무/지도 16개 화면을 확인했다. 세로 4개와 classic 가로 4개는 이전 화면과 픽셀 단위로 같고, 픽셀동화 가로 8개는 승인된 헤더 교체 결과와 같다. 원래 세로 rail 파일은 원본 바이트 그대로 남긴다.

### 배포 전 전체 검사와 실패 원인 분리

- [필수 전체 실행](https://github.com/yigasda/SandAndFeather/actions/runs/39724691089)은 30개 호출 중 17개 성공, 13개 실패였다. 이를 전체 통과로 기록하지 않는다. 실패 직후 배포를 보류하고 원인을 확인했으며, 게임 동작을 바꾸거나 허용오차를 느슨하게 하지 않았다.
- 궁 검사: 새 SillyTavern에서 초기 Save/캐릭터 준비보다 먼저 고정 2.5초 대기가 끝나 테스트가 시작하지 못했다. 실제 Save 또는 캐릭터 준비를 기다리도록 테스트를 수정했다. 추가로 방패 8에 랜덤 피해 4+4가 들어가면 체력 손실이 없어도 정상인데 반드시 손실을 기대하던 검사 자극을 수정했다. 첫 타 5±1은 유지하고 둘째 타만 6±1로 하여 남은 방패 2..4를 반드시 넘게 했다. 게임 전투 수치는 그대로다. [수정 검사](https://github.com/yigasda/SandAndFeather/actions/runs/39730809562)는 사전 온보딩 없는 새 호스트에서 21항목 모두 통과했다.
- 문 이동 11개: [기존 main과 후보의 같은 조건 비교](https://github.com/yigasda/SandAndFeather/actions/runs/39730184495)에서 실제 입력 0.16과 112×112 조이스틱 크기는 같았다. 테스트의 20ms 요청이 실제로 약 50ms 유지되어 최소 이동량 약 0.05376칸이 ±0.02칸 목표 구간을 계속 넘어갔다. 프레임 중에는 목표 안에 도달했지만, 중립 입력 뒤 측정에서는 양쪽을 오갔다. 복귀 중 문 전환이나 입력 정지는 없었다.
- 문 테스트는 실제 CDP 터치를 유지하고, 중립 예약의 20ms 타이머를 활성 터치 응답 이후가 아니라 전송 즉시 시작하도록 수정했다. 두 전송의 완료를 기다린 뒤 측정하며 실패/불확실한 전달은 브라우저를 종료한다. 0.02 복귀 기준, 0.05 독립 이동 허용오차, 입력 하한, 반복 한도와 기존 판정문 40줄은 그대로다. [단일 경로 증명](https://github.com/yigasda/SandAndFeather/actions/runs/39731187856)은 80항목 통과, 20회 복귀 모두 오차 0.02 미만, 470개 활성→중립 입력 쌍의 순서/중립 이상 0건이다. 최소 입력의 실제 유지시간 중앙값은 16.7ms였다.
- [실패했던 11경로 표적 재검사](https://github.com/yigasda/SandAndFeather/actions/runs/39731935628): 각 경로 80항목, 총 880항목 모두 통과했다. 11개 변경 JS 문법 검사도 통과했다. 검사한 테스트 소스는 `04d73fe236c53d2ebcc679318c9f20aa65b87597`이다.
- 최초 테마 검사의 이미지 준비 대기 시간 초과는 원인이 확정되지 않았다. 이후 같은 판정과 대기 조건으로 [진단 실행](https://github.com/yigasda/SandAndFeather/actions/runs/39729328031)의 테마 8그룹, 아래 배포 묶음의 테마 8그룹이 모두 통과했다. 새 상태에서 아이템 5종을 넣고 가로 인연을 처음 연 별도 검사도 119개 이미지가 모두 로드되어 숨은 지연 로딩 이미지 가설은 재현되지 않았다. 이 시간 초과를 코드로 해결했다고 주장하지 않는다.
- 위 진단 실행의 최초 문 비교는 분리 테스트 폴더에 src가 없어 게임 실행 전에 중단됐다. 그 실패를 main의 이동 실패 증거로 사용하지 않으며, 유효한 문 비교 증거는 별도 실행 39730184495이다.
- 전체 검사를 무작정 반복하지 않았다. 변경되지 않은 검사 결과와 런타임 파일 동일성을 보존하고, 실패 항목과 이후 자산 경로 변경에 해당하는 화면/동작만 다시 확인했다.

- 검증한 Git tree: `058abd08afe10a247cef4fe6662cbb9c89d16264`. 버전 0.9.94, 총 747파일, 루트는 README.md/data/docs/index.js/manifest.json/src/style.css뿐이다. 테스트 도구·진단 결과·임시 복구 파일은 포함하지 않는다.
- 묶음에서 화면 16개와 헤더/탐색/보존 37항목, 픽셀동화 9그룹, 테마 8그룹, 전체 지도 13그룹이 통과했다. 게임 페이지 오류와 AI 생성 요청이 없었다. 선택적 외부 NarrativeArchive 탐색의 404 외에 캡처의 HTTP 실패는 없었다.
- 모든 실행은 격리된 GitHub Actions 호스트와 테스트 데이터로 진행했다. 사용자의 실제 저장 데이터나 채팅을 사용하지 않았다.
- 공개 전 main/release 참조를 다시 확인하고 강제 덮어쓰기 없이 갱신한다. main과 release가 동시에 바뀌면 이 검사 결과만으로 덮어쓰지 않고 차이를 다시 확인한다.
