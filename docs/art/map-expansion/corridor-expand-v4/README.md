# 139 — 안쪽 복도 양끝 겹침 수정 검토본

137번은 사용자 반려: 새 벽과 원본 벽의 투시가 달랐고, 깔개·줄눈이 겹쳤다. 137번 이미지를 게임에 적용하지 않는다. **139번은 새 검토본이며 미채택·게임 미적용.**

## 수정

- 원본 `../exits-v2/inner-corridor-wide-v1.png`의 좌우 끝560×724를 각각 직접 입력하고, 해당 끝의 바깥160px만 새로 연장했다.
- 기존137번의 좌우 확장 스트립을 교체했다. 서로 다른 투시를 섞는 알파 블렌딩, 깔개 중복, 바닥선 복제 보정을 재사용하지 않았다.
- 경계 변위(약−3~4px)를 등록하고 바깥90px 이내에서 줄였다. 원본 영역은 변경하지 않았다.
- 전체2492×887, 원본2172×724 위치(160,64), 좌우각160·위64·아래99 유지. 원본 영역 RGB 변경픽셀0.
- 문턱 앞 유효폭 약 왼쪽140px/오른쪽150px. 안쪽으로 갈수록 원근에 따라 좁아진다. 좌표 제안은 `coordinates.json`.

## 검증/한계

실제 원본 끝부분, 새 좌우 스트립 합성본, 좌우 확대본, 최종 전체본을 직접 확인했다. 겹친 깔개 테두리와 꺾인 벽선이 없는지 비교했다. 숫자상 원본보존을 투시 검증으로 대신하지 않는다. 인게임 이동·가림 검증은 하지 않았다. 사용자 확인 후 나머지4회랑 진행.

`node build.cjs` → `node previews.cjs`. 입력인137번은 중앙 원본 및 위아래 확장 영역에만 사용하며 반려된 양끝 스트립은 덮어 교체한다. 제작 입력을 보존하는 목적이지137번 승인 의미가 아니다.

## 실패 원인 기록

137번은 검수에서 접합 문제를 봤는데도 수치상 원본보존과 납품 진행을 우선해 전달했다. ‘검토본’ 표시는 눈에 보이는 결함을 사용자에게 넘길 이유가 아니다. 원근이 다르면 블렌딩으로 감추지 말고 해당 확장부를 원본 선에서 다시 이어 그린다. 알려진 중복 선·잘림·투시 차이가 남으면 업로드와 완료 보고를 멈춘다.

추가 자체 확인: `139-original-preserved-compare.png` 원본/전체 같은 배율 비교, `139-trio-scale-static.png` 셋소호 보이는 키 약156px(약2칸) 배치, `139-phone-width-static.png` 960px(약12칸) 크롭을480px로 표시. 모두 정적 크기 검토이며 런타임 적용/가림 검증이 아니다. 이웃 장면과 실제 이동 전환은 검증하지 않았다.
