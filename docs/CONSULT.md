# 모래와 깃털 — 상담용 소개서

> 이 문서를 받은 AI에게: 소망이 만들고 있는 SillyTavern 확장을 소개하는 글이야.
> 기능 아이디어, 구조 점검, 조언을 부탁하려고 줬어. 끝까지 읽고 맨 아래 **상담 받고 싶은 것**에 답해 줘.
> 저장소: https://github.com/yigasda/SandAndFeather
> 더 자세한 기획은 저장소의 `SPEC.md`, 화면 시안은 `docs/mockups/`.

---

## 1. 한 줄로

세트·호루스와 RP하는 SillyTavern 채팅 옆에서 돌아가는 **이집트 오픈월드 게임 확장.**
원신처럼 마을을 직접 걸어 다니고, 마을의 장소마다 서로 다른 장르의 게임이 들어 있어.
시간은 RP 채팅을 따라 흐르고, 게임에서 생긴 일은 짧은 문장으로 채팅에 들어가.

## 2. "네 장르 + 원신 방식 + 걷는 2D 맵"이 무슨 뜻이냐면

### 네 장르 = 네 가지 놀이
| 이름 | 비슷한 게임 | 하는 것 |
|---|---|---|
| 🌾 생활 | 스타듀밸리, 동물의 숲 | 텃밭, 낚시, 시장, 요리, 축제, 선물, 하루 결산 |
| 📜 육성 | 프린세스 메이커 | 능력치, 한 주 일정 짜기, 칭호, 호루스 옆에서 판결 |
| 🐍 원정 | 다키스트 던전, 하데스 | 밤마다 저승 두아트로 내려가는 로그라이크. 세트·호루스·소망 파티, 공포 수치, 마지막에 뱀 아펩 |
| 🏛 경영·전략 | 문명, 삼국지 | 이집트 전략 지도, 한 달에 한 턴, 나일 범람 경제, 세력 평판, 마아트와 혼돈의 균형 |

### 원신 방식 = 메뉴가 아니라 장소
네 장르가 "메뉴 버튼 네 개"로 있는 게 아니야. **하나의 세계 안에 장소로 놓여 있어.**
- 시장에 걸어가면 생활, 필사실에 가면 육성, 두아트 문에 가면 원정, 신전 집무실 지도 탁자에 가면 경영.
- 그 위를 원신식 장치가 감싸: 매일 의뢰, 신화 이야기 장, 지역별 탐사율 %, 뽑기 항아리, 도감, 모든 모드 경험치가 모이는 모험 등급.
- 지역은 옴보스 마을에서 시작해서 나일 강변, 테베, 에드푸, 델타, 사막, 누비아, 하늘, 저승으로 넓어져.

### 걷는 2D 맵
위에서 내려다보는 픽셀 타일 맵. 옛날 포켓몬이나 스타듀밸리처럼 생겼어.
폰에선 화면 패드, PC에선 방향키로 소망 캐릭터를 움직이고, 가까이 가서 "말 걸기"를 눌러.

## 3. 채팅과 이어지는 방식

- **채팅이 시계야.** 봇 답장 끝에 붙는 트래커 줄을 읽어서 게임의 날짜, 시간대, 장소를 맞춰. AI 호출 없이 정규식으로.
  `<tracker> 🌇 05:48 오후 | 하티르 여드렛날, 2년 | 옴보스 → 서쪽 별채 | ☀️ 맑음 </tracker>`
- 달력은 고대 이집트 달력이야. 30일짜리 달 열두 개와 덧붙는 닷새. 범람기, 파종기, 수확기의 세 계절.
- **숫자는 게임 안에만.** 체력, 호감도, 곡물 같은 수치는 프롬프트에 절대 안 넣어. 대신 짧은 영어 문장으로 상황만 알려 줘.
  - 넣지 않는 것: `Maat: 42 / Set attitude: Wary`
  - 넣는 것: `The granaries are running low and petitioners crowd the gate.`
- 주입 블록은 80단어 안팎, 새로 생긴 일만. 캐릭터의 감정이나 대사는 지시하지 않아.
- **이야기는 채팅이 맡아.** 신에게 말을 걸면 게임 속 대화창이 아니라, 장소와 상황을 넣어 주고 채팅 RP로 넘겨.
- 게임이 플레이어를 멋대로 죽이지 않아.

## 4. 지금 어디까지 됐나

**1단계 "엔진과 마을" 끝.**
- 게임 창 열기, 접어서 작은 칩으로 두기
- 옴보스 마을 지도 한 장: 세트의 신전, 필사실, 훈련장, 시장, 텃밭, 부엌, 선착장, 두아트 문
- 걷기, 벽에 막히기, 카메라 따라가기, 장소 가까이에서 말 걸기 카드
- 세트, 호루스, 상인이 서 있음. 아직 말은 못 걺
- 트래커로 날짜·시간대·장소 맞추기. 밤엔 화면이 어두워지고 계절마다 강과 밭 색이 바뀜
- 프롬프트에 한 줄 주입: `[Egypt — Hathyr 8, Akhet, evening. Ombos, the west wing.]`
- 채팅마다 따로 저장, 확장 설정 서랍, 밝은 테마와 어두운 테마

**2단계 "첫 고리"도 끝.** 선착장에서 하루 한 번 건지기, 가방, 열어 보기, 이 일로 세트나 호루스에게 말 걸기 → 입력칸에 첫 문장과 프롬프트에 영어 한 줄. 처리한 하루와 행동 기록부, 재생성에도 안 사라지고 다음 턴엔 빠지는 사건 전달, 데이터 오류 알림.

그림은 전부 코드로 그린 임시 픽셀이야. 나중에 스프라이트 그림으로 바꿀 수 있게 나눠 뒀어.
`docs/mockups/` 그림들은 목표 시안이고, 지금 화면은 그보다 단순해.

## 5. 앞으로의 단계

다른 AI 상담 뒤에 순서를 바꿨어. RP와 이어지는 고리를 먼저, 장르는 그 위에.

1. 엔진과 마을 — **끝**
2. 첫 고리 — **끝**. 기록부, 가방, 사건 전달, 선착장에서 건지기, 말 걸기 → 채팅
3. 작은 모험 엔진 — 추적·운반·조사·거래 같은 행동 유형과 갈림길, 무작위 조립, 최근 기억, 첫 모험 "숨은 정원", 모험 등급 첫 버전. 그다음 AI가 같은 형식으로 새 모험을 써 주는 기능을 하나 붙여서 재미 확인
4. 생활 — 하루 결산, 텃밭, 시장, 낚시, 요리, 축제 하나
5. 육성
6. 원정 — 짧은 태양의 배 호위부터
7. 경영·전략 — 마을 단위 결정부터
8. 원신 층 넓히기 — 강 건너 유적과 배 수리, 지역, 오벨리스크, 도감. 뽑기는 맨 나중

## 6. 꼭 알아야 할 제약

- **SillyTavern 확장이야.** 브라우저에서 도는 자바스크립트 모듈뿐. 서버 없음, 빌드 도구 없음, 외부 라이브러리 거의 없음.
- **폰에서 써.** 안드로이드 Termux에서 돌리는 SillyTavern. 작은 화면, 터치, 가벼워야 함.
- **AI 호출은 돈이 들어.** 그래서 게임 대부분은 AI 없이 규칙과 데이터로 돌아가야 해.
- **소망은 코드를 못 읽어.** 코드는 Claude Code가 짜고 소망은 직접 해 보고 의견을 줘. 그래서 데이터는 전부 `data/` 아래 JSON으로 빼서 소망이 손으로 고칠 수 있게 하는 중.
- 소망이 RP 채팅을 압축해 두는 다른 확장 **NarrativeArchive**가 따로 있어. 화면 디자인은 그쪽과 같은 결: 크림 베이지 바탕, 주황 강조, 둥근 카드. 기능은 서로 섞지 않아.
- 소망의 RP 줄거리, 특정 사건이나 대사는 게임 데이터에 넣지 않아. 신화 이야기는 일반 이집트 신화로.

## 7. 코드 구조

```
index.js            진입점. SillyTavern 이벤트만 연결
style.css           화면 전체 스타일
manifest.json
data/               소망이 고칠 수 있는 데이터
  calendar.json     이집트 달 이름, 계절, 시간대, 한국어 날짜 말
  places.json       지역 이름과 별칭, 방 이름 한영
  maps/ombos.json   옴보스 지도: 타일 글자 줄, 건물, 장소, 사람
src/core/           엔진
  st.js             SillyTavern 접근을 한 곳에
  settings.js       전역 설정
  state.js          채팅별 게임 저장, 버전
  bus.js            팩끼리 주고받는 이벤트 버스
  data.js           JSON 불러오기
  clock.js          이집트 달력 계산, 날짜 글 읽기
  tracker.js        트래커 읽어서 날짜·장소 맞추기
  inject.js         프롬프트 블록 만들기, 단어 상한
src/world/          걷는 세계
  map.js            지도, 충돌, 가까운 장소 찾기
  player.js         소망 위치와 이동
  input.js          키보드와 터치 패드
  render.js         캔버스 그리기: 타일, 건물, 사람, 시간대 빛, 계절 색
src/ui/             화면
  window.js         게임 창 열기·접기·닫기, 매 프레임
  hud.js            날짜 카드, 미니맵, 버튼, 탭
  popups.js         지도 위에 뜨는 카드
  drawer.js         확장 설정 서랍, 마술봉 메뉴
```
2단계부터는 `src/packs/life/`, `growth/`, `duat/`, `realm/`처럼 모드를 팩으로 얹을 계획이야. 팩끼리는 직접 부르지 않고 이벤트 버스로만 주고받아. 하나가 망가져도 나머지는 돌게.

## 8. 상담 받고 싶은 것

### 기능 아이디어
1. 네 장르를 **하나의 하루 리듬**으로 묶으려면 어떻게 해야 할까? 지금 생각은 "챗의 하루 = 게임의 하루", 하루 행동력 "태양 기운"으로 무한 반복을 막는 것.
2. 채팅 RP와 게임이 서로 **더 재밌게 주고받는** 방법. 게임 일이 채팅을 해치지 않고 양념이 되는 방식이면 좋겠어.
3. 원신식 장치 중에 이 확장에 특히 잘 맞는 것과 빼는 게 나은 것.
4. 이집트 신화와 고대 이집트 생활에서 게임으로 만들기 좋은 소재.
5. 큼직하고 게임 같은 재미를 주는 것. 자잘한 기능 여러 개보다 한 번 해 보면 "오" 하는 것.

### 확장 구조 점검
6. 위 파일 구조와 팩 방식이 여덟 단계까지 버틸 수 있을까? 미리 바꿔 둘 곳이 있을까?
7. 채팅 메타데이터에 게임 전체를 저장하는 방식의 위험. 데이터가 커지면 어떻게 될까?
8. 폰에서 캔버스 게임을 돌릴 때 주의할 점: 성능, 배터리, 터치.
9. 트래커를 정규식으로 읽는 방식이 깨지기 쉬운 지점.

### 조언
10. 단계 순서가 괜찮은지. 먼저 하는 게 나은 단계가 있는지.
11. 혼자, 코드를 못 읽는 사람이 AI와 이런 큰 확장을 만들 때 실패하기 쉬운 지점과 피하는 방법.

## 9. 답할 때 부탁

- 한국어로, 편하게.
- 아이디어는 **우선순위**를 붙여서. 왜 재밌는지 한두 줄로.
- 위 원칙 중에 바꾸자고 하고 싶으면 그 이유를 같이.
- 괄호는 되도록 쓰지 말아 줘. 소망이 괄호를 싫어해.
- 코드를 줄 필요는 없어. 구현은 Claude Code가 해.
