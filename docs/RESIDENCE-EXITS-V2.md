## 적용 순서 및 주의점

1. `tools/maps/residence.py`의 해당 9개 `day`/`night` 파일명에 `exits-v2/` 접두사를 붙인다. 전역 `ART`는 바꾸지 않는다. 다른 방 그림 경로까지 바뀌면 안 된다.
2. 위 표를 기준으로 `exits`, `entry`, `solid`를 함께 맞춘다. 픽셀→타일은 `x / (이미지너비 / 맵너비)`, `y / (이미지높이 / 맵높이)`. 연못은 x·y 비율이 다르므로 일괄 80으로 나누지 않는다.
3. 우물 마당 양옆 문턱은 기존보다 위로 이동했다. 대야·탁자·벤치 충돌을 유지하되 문 앞 바닥을 막고 있는 긴 벽 충돌을 분할한다. 새 트리거로 들어갈 수 있도록 문 앞 접근 공간을 확보한다. 북쪽은 아치 아래 바닥에서 전환되도록 조정하며 기둥·화단을 통과시키지 않는다.
4. 회랑 5곳은 기존 천장선 아래의 안쪽 통로다. 문턱 y305–350, 접근 트리거 y340–385. 끝 기둥 받침은 계속 고체로 두고 그 아래 바닥에서 접근한다. **동쪽 우측 항아리는 이번에 제거했다.** 해당 항아리 충돌만 제거하고 기둥 받침 충돌은 유지한다. 하나로 묶인 충돌이라면 분할한다. 연못은 아래 확장 명세를 별도로 적용한다.
5. 방문 회랑 아래 계단은 가운데 x855–1270이며 계단 기둥은 그 양옆이다. 기존 세 방문과 목적지는 유지한다. 계단 복귀점은 트리거 밖 위쪽이다.
6. 기존 출구 이름표는 유지한다. `exit_signs`의 방향 판정이 화면 끝 좌표에 의존하므로, 회랑 끝 트리거는 좌우로, 새 연못 아치는 위쪽으로 이름표가 표시되는지 확인한다. 연결 키 east와 실제 이동 방향 up을 혼동하지 않는다.
7. 생성기를 실행하여 `data/maps/*.json`, `data/scene-art.json`을 갱신한다. 원본 PNG 위에 화살표나 좌표를 그리지 않는다. 밤 그림은 이미 출구 불빛을 포함한다.
8. 출구 31개 왕복, 낮밤 전환, 새 도착점에서 즉시 되돌아가지 않는지, 폰 화면에서 길이 읽히는지를 확인한다. 이 아트 변경에서는 게임을 실행하거나 통행을 검증하지 않았다.

## 연못 확장 — 크기와 연결을 함께 변경

이번 사용자 후속 요청은 연못에 한해 기존 크기 유지 원칙을 변경한다. 기존 1448×1086 이미지를 **(0,0)에 그대로** 놓고 오른쪽 x1448–1931만 추가했다. 낮밤 최종 크기는 **1932×1086**이다. 기존 모든 가구·연못·기둥·화단의 픽셀 좌표는 그대로다.

- 새 아치 문턱 `[1530,490,1735,550]`, 트리거 시작값 `[1550,495,1715,545]`, 복귀 발 위치 `[1635,625]`, 복귀 방향 `down`. 아치로 들어가는 방향은 `up`이다. `east` 연결 키와 목적지 `temple_inner_corridor` / `west`는 유지한다. 화면 오른쪽 끝에서 자동 전환하지 않는다.
- 현행 맵 18×14에 넓어진 이미지를 그대로 끼우면 건축과 캐릭터의 상대 크기가 달라진다. **24×14로 확장하는 방안을 권장**한다. 원래 x 비율은 1448/18≈80.4444px/칸, 새 비율은 1932/24=80.5px/칸, y 비율은 1086/14≈77.5714px/칸이다. 정확한 비율을 요구하는 런타임이면 이미지 표시 배율과 캔버스 폭도 함께 검토한다.
- 기존 랜드마크·충돌·출구는 원래 픽셀 위치를 기준으로 새 타일 좌표를 환산한다. 특히 원래 남쪽 출구를 새 캔버스 중앙으로 옮기지 않는다. 원래 남쪽 트리거 `[538.98,1031.7,909.02,1086]`, 도착점 `[724,923.1]`을 유지하는 것을 기준으로 한다.
- 새 오른쪽 영역의 외벽·화단·기둥 충돌을 추가하고 아치 중앙 바닥은 열어 둔다. 문턱은 통과 가능한 낮은 턱이다. 도착점은 트리거 밖이며 왕복 직후 재전환되지 않아야 한다.
- 위 수치는 미술 기준의 제안이다. `tools/maps/residence.py` 수정, 데이터 재생성, 31개 출구 왕복 테스트는 오푸스 후속 작업이다. 이번 커밋에는 런타임 변경이 없다.

## 보존·검증

- 저장된 낮밤 PNG를 다시 읽어 원본 1448×1086 영역과 RGBA 비교: **차이 0픽셀**. 원본 자체 파일도 변경하지 않았다.
- 연못만 가로 확장했다. 나머지 7장은 원래 크기를 유지한다. 모든 원본 PNG 파일은 변경하지 않았다.
- 동쪽 회랑은 이전 검토본 `fe4d6f4` 대비 항아리 패치 `[2100,215,2172,352]` 밖 RGBA 차이 0이다. 다른 6장 보정본도 이전 커밋과 픽셀 동일하다.
- 연못 이외의 국소 보정은 선언한 편집 영역 밖 RGBA 차이 0. `validation.json`에 원본/출력 SHA-256, 보존 영역, 확장 크기를 기록했다.
- 연못 생성 레이어만 최종 캔버스에 정렬한 뒤 원본 전체를 정확히 복사했다. 원본은 리사이즈하지 않았다. 국소 수정은 영역 안쪽 8px 페더링 방식이다.
- 낮밤 출입구 위치와 제안 좌표는 동일하며 밤에는 약한 등불을 넣었다. 연못 낮밤·동쪽 회랑은 사용자 채택 완료. 나머지 6장의 검토 상태는 유지하며 런타임은 모두 미적용이다.
