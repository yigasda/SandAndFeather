## 픽셀 좌표

**좌상단 (0,0), x 오른쪽·y 아래.** 사각형은 `[왼쪽, 위, 오른쪽, 아래]`, 오른쪽/아래는 미포함. 아래 좌표는 그림 위에서 지정한 문턱과 접근 영역이다. 트리거와 도착점은 **적용 시작값**이며 발 충돌 크기를 포함한 실제 통과 검증 전이다. 낮밤은 같은 좌표를 사용한다.

## 적용 순서 및 주의점

1. `tools/maps/residence.py`의 해당 9개 `day`/`night` 파일명에 `exits-v2/` 접두사를 붙인다. 전역 `ART`는 바꾸지 않는다. 다른 방 그림 경로까지 바뀌면 안 된다.
2. 위 표를 기준으로 `exits`, `entry`, `solid`를 함께 맞춘다. 픽셀→타일은 `x / (이미지너비 / 맵너비)`, `y / (이미지높이 / 맵높이)`. 연못은 x·y 비율이 다르므로 일괄 80으로 나누지 않는다.
3. 우물 마당 양옆 문턱은 기존보다 위로 이동했다. 대야·탁자·벤치 충돌을 유지하되 문 앞 바닥을 막고 있는 긴 벽 충돌을 분할한다. 새 트리거로 들어갈 수 있도록 문 앞 접근 공간을 확보한다. 북쪽은 아치 아래 바닥에서 전환되도록 조정하며 기둥·화단을 통과시키지 않는다.
4. **10월 11일 변경:** 회랑 5곳의 낮은 돌출 문틀을 제거하고 기존 끝 기둥 밖, 기존 천장선 아래에 안쪽 통로를 냈다. 문턱은 y305–350, 접근 트리거는 y340–385로 올라갔다. 기존 끝 기둥 받침(y 약 300–335)은 계속 고체로 두고 그 아래 바닥에서 출구로 접근하게 한다. 화면 끝 전체가 출구이던 긴 트리거를 표의 구간으로 좁힌다. 동쪽 회랑 우측 항아리는 원위치에 있으므로 그 아래 바닥 접근부에서 전환한다. 연못 회랑도 돌출 입구를 없애고 천장 아래로 통로를 연결했다. 원래 우측 기둥/받침은 유지하고 출구쪽 끝 벽과 잘린 화단 부분만 통로로 바뀌었다. 문턱은 y500–570, 접근 트리거는 y560–610이다. 이 구간의 기둥 충돌과 벽 충돌을 구분하여 맞춘다.
5. 방문 회랑 아래 계단은 가운데 x855–1270이며 계단 기둥은 그 양옆이다. 기존 세 방문과 목적지는 유지한다. 계단 복귀점은 트리거 밖 위쪽이다.
6. 기존 출구 이름표는 유지한다. `exit_signs`의 방향 판정이 화면 끝 좌표에 의존하므로, 안쪽으로 이동한 좌우 트리거도 좌우 이름표로 분류되는지 확인한다.
7. 생성기를 실행하여 `data/maps/*.json`, `data/scene-art.json`을 갱신한다. 원본 PNG 위에 화살표나 좌표를 그리지 않는다. 밤 그림은 이미 출구 불빛을 포함한다.
8. 출구 31개 왕복, 낮밤 전환, 새 도착점에서 즉시 되돌아가지 않는지, 폰 화면에서 길이 읽히는지를 확인한다. 이 아트 변경에서는 게임을 실행하거나 통행을 검증하지 않았다.

## 보존·검증

- 최종 9장 크기 원본과 일치. 원본 파일은 수정하지 않았다.
- 선언한 출구 편집 사각형 밖 RGB/알파 픽셀 차이 0. `validation.json`에 원본/보정본 SHA-256과 변경 픽셀 수를 기록했다.
- 생성 결과를 원본 위 출구 부분에만 합성했다. 경계 안쪽 8px만 페더링하고 원본 캔버스는 리사이즈하지 않았다. 생성 레이어 중 중앙 회랑(2171×724), 방문 회랑(2170×725)은 합성 전에 2172×724로 정렬했다. 최종 원본 보존 영역에는 이 정렬이 적용되지 않는다.
- 낮밤 두 쌍은 같은 편집 사각형과 통행 좌표. 밤에는 문 안쪽에 약한 따뜻한 불빛을 넣었다.
- 동쪽 붉은 깔개, 서쪽 청색 별 깔개/천이 통로 안에 보인다. 기존 천장선과 끝 기둥이 입구의 테두리가 된다. 방문 회랑의 세 방문과 아래 계단, 기존 가구, 중앙/상단 출구는 유지했다.
- 선택 사항인 세 방·부엌·식사 공간·성소·열주 계단의 아래 문은 이번 변경에서 유지했다.
