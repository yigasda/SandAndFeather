# 사막 오브젝트 제작·게임 적용 지침서

2026-10-16 · 계획 v1 · 아스트라 작화 / 오푸스 구현

**배경 작화는 사용자 채택 완료 단계다. 이제 채택 맵을 보존하면서, 실제로 조작·획득·상태 변경되는 부분만 제작한다.** 이 문서는 제작·적용 계획이며, 장치 구현이나 충돌 검사 완료 보고가 아니다.

기준: [05–20 통합 지침](ASTRA-DESERT-05-20-GUIDE.md)의 맵별 카드, 분리 계약, P01–P16, 탐험·생활 10기능, 검수 절 전체. 이후 사용자 채택과 수정이 우선한다. [공통 프롬프트](ASTRA-MAP-PROMPTS.md)는 변경하지 않는다. 적용 담당자는 [오푸스 인수인계](OPUS-HANDOFF.md)의 최신 검사·배포 절도 읽는다.

## 1. 이번 계획의 결론

1. 바위·벽·모래·고정 장식은 대부분 그대로 둔다. 캐릭터를 가려야 하는 곳만 전경 마스크를 만든다.
2. 문·상자처럼 제자리에서 바뀌는 것은 **맵에 맞춰 그린 상태별 국소 교체 조각**을 우선한다.
3. 반사판 머리·봉인석·획득 유물처럼 돌아가거나 이동·소멸하는 것은 **깨끗한 빈자리 + 개별 오브젝트**로 만든다.
4. 광선·선택 표시·활성 빛·바람은 별도 효과다. 모든 조합의 전체맵을 그리지 않는다.
5. 문양의 의미와 장치 논리를 먼저 정하고, 그 논리가 읽히는 그림을 만든다. 생성된 장식 문양을 사후에 정답으로 삼지 않는다.
6. 기존 맵에서 추출하거나 해당 위치를 수정해서 투시를 맞춘다. 독립 소품을 먼저 그려 억지로 끼워 넣는 방법은 기본안이 아니다.

### 연결에서 특히 확인할 점

기존 계획: 01↔05↔12↔13↔14, 01↔09, 01↔19, 04↔07/08, 02↔15↔16, 02↔11↔17↔18, 02↔10↔20. 03의 관측은 같은 맵 안이다. 18→19는 **정보 연결**이며 직통 문이 아니다. 15↔17 지름길은 아직 제안이다.

사용자는 20의 아래쪽 구역에서 보물방을 추가했고, 보물방 위 계단 밖으로 야외 전망맵을 추가했다. 따라서 **보물방 위 계단은 최신 지시에 따라 전망맵과 연결**한다. 앞서 그 계단을 20 귀환으로 해석했던 설명은 폐기한다. 20↔보물방은 남은 입출구 중에서 배치해야 하며 정확한 문턱은 미확정이다. 같은 계단에 두 목적지를 겹치지 않는다. 구현 전 이 접점 하나를 실제 채택 그림으로 확인하고 부족한 연결부만 결정한다.

### 원본 기준

05·07–11·14–20의 일반 최종 경로는 `docs/art/desert-번호-approved-2026-10-16/approved-final.png`다. 12는 해당 폴더의 `corridor-01.png`, `corridor-02.png`; 01은 `desert-01-method-2026-10-16/approved-final.png`와 `desert-01-open-approved-2026-10-16/approved-final.png`; 03은 `desert-03-ridge-approved-2026-10-16/approved-final.png`를 쓴다. 파일명 규칙만으로 존재·채택을 추정하지 말고 실제 manifest를 확인한다.

이번 추가 원본은 [추가 채택 목록](art/desert-late-approved-2026-10-16/manifest.json)에 파일·크기·해시·채택 근거를 기록한다. 전체 그림 채택과 패치/투명 PNG의 게임 사용 승인은 별개다.

**화질 보존:** 수정본을 연속으로 다음 베이스로 쓰지 않는다. 최초 채택 원본 + 승인된 변경 좌표를 기준으로 작업한다. 새 결과에서 필요한 영역만 원본에 반영하며, 보존 영역 픽셀 차이 0을 검사한다. 검증 전에는 ‘픽셀 동일’이라고 쓰지 않는다. 원본 보관 파일을 덮어쓰지 않고 별도 게임용 파생본을 만든다.

## 3. 무엇을 그릴지 판단하는 기준

| 종류 | 제작 방식 | 예 |
|---|---|---|
| 고정 배경 | 원본 유지. 새 PNG 불필요 | 모래, 벽, 고정 석관, 바위, 장식 항아리 |
| 고정 조사 대상 | 기존 그림 + 클릭 영역 + 필요시 읽기 확대본 | 비문, 기록판, 벽화 |

압력판·큰 가림돌·수로 밸브·모래 기계·시간제한·자동 회전은 기존 문서에서도 후속이다. 이번 필수 제작 목록으로 끌어오지 않는다.

## 6. 문양과 퍼즐 규칙을 먼저 잠그는 절차

### 문양 사전

장치별로 `glyphId / 실루엣 / 의미 / 회전 허용 / 사용 장소 / 단서 근거`를 한 표에 등록한다. 최초 제안은 태양·별·물결·깃털처럼 서로 다른 소수 실루엣이지만 **최종 목록은 미확정**이다. 앙크와 고리 달린 십자가는 새 제작에서 제외한다. 기존 05의 승인 예외를 새 장치에 확대하지 않는다.

09는 소수 기호 순서 입문, 13은 기록 비교 심화, 14는 배운 규칙 응용이다. 19는 관찰·회전 응용이며 장식 별 전체가 조작 기호는 아니다. 벽화는 분위기용 영역과 실제 읽을 단서 영역을 나눈다. 문양 면과 조사 확대본은 같은 원본에서 파생해 서로 다른 기호가 되지 않게 한다.

각 퍼즐 제작 전에 개발자 표를 만든다: 초기 상태, 허용 조작, 단서 위치/내용, 해결 조건, 틀렸을 때 반응, 초기화, 완료 유지, 보상 1회 지급, 귀환 경로. 정답표는 플레이어 배경에 넣지 않는다. 지식 없이도 방 안 자료로 풀 수 있고, 단서를 먼저 찾은 순서도 인정한다.

### 반사광

논리 방향, 화면에서의 반사면 방향, 실제 광선 접점을 각각 기록한다. O0–O3 그림이 동서남북과 자동 대응하지 않는다. 입력 광선→반사 출력 표를 구현 담당자가 검증한 뒤 그 각도로 머리를 그린다. 3/4 물체 PNG를 화면에서 단순 회전하면 투시·광원·그림자가 틀어지므로 방향별 그림 또는 검증된 투영 방식을 쓴다.

15의 채택 수신부는 높은 뒤쪽 단에 있다. 반사판에서 위층 수신부로 향하는 높이 성분을 논리/표현에 반영할지 먼저 시험한다. 화면의 선 하나만 연결됐다고 물리 반사가 맞다고 하지 않는다. 해결되지 않으면 장치 접점·반사면 기울기 조정을 검토하며 채택 건축이나 수신부를 임의로 아래층으로 옮기지 않는다.

광선은 매 상태에서 광원→반사면→수신부/차단점으로 갱신한다. 틀린 방향도 벽에서 끝나거나 비껴가는 모습이 보여야 한다. 배경 햇빛은 고정 환경광이며 정답 광선이 아니다. 기둥이 광선을 막는지, 광선 높이에서 통과 가능한지 명시한다.

## 7. 상자 5개 — 32장 없이 독립 개방하기

채택 6장은 `closed-all.png`, `open-C1.png`…`open-C5.png`로 보존한다. C1 왼쪽 위, C2 오른쪽 위 큰 상자, C3 왼쪽 아래, C4 오른쪽 아래 안쪽, C5 오른쪽 아래 바깥쪽이다. 생성 완료 순서와 ID를 혼동하지 않는다.

### 제작 방법

1. 닫힌 원본을 좌표 기준으로 고정한다. 열린 5장의 전체 배경은 재생성 때문에 미세하게 다를 수 있다. 전체 화면 교체는 하지 않는다.
2. 각 그림에서 해당 열린 상자와 뚜껑·접촉 그림자·필요한 배경 복원 범위만 선택한다. 닫힌 상자의 실루엣까지 모두 덮는 교체 영역이어야 잔상이 안 남는다.
3. 같은 위치의 닫힘/열림 패치를 동일 캔버스·오프셋으로 정렬한다. 몸통이 생성 과정에서 이동했다면 기준 원본에 맞춰 국소 보정한다. 미세 차이를 흐림으로 숨기지 않는다.
4. 패치 경계는 같은 원본 픽셀로 연결한다. 반투명 테두리 아래에 닫힌 상자가 비치지 않게 한다. 필요하면 상자 없는 바닥을 만들고 닫힘/열림 오브젝트를 모두 분리하는 대안으로 전환한다.
5. 패치가 서로 겹치는지 검사한다. 특히 C4/C5는 상대편 상자를 패치에 포함하면 안 된다. 겹침이 불가피하면 공통 빈바닥과 개별 물체 방식이 낫다.
6. 패치의 바닥 부분은 캐릭터보다 먼저, 상자와 열린 뚜껑의 가림은 발 위치에 따라 처리한다. 패치 전체를 캐릭터 위에 그려 사각형으로 인물을 지우지 않는다.

게임은 `chests[C1..C5].claimed` 같은 **제안 필드**로 각각 저장한다. 열기/지급 처리는 상자별 중복 실행을 막고 저장 성공과 실패 복구를 함께 설계한다. 한 번 받은 상자는 재입장·초기화·재접속해도 열린 빈 상태를 유지한다. 현재 채택 그림의 잠금장치가 별도 열쇠 퍼즐 확정을 뜻하지는 않는다. 열쇠/조건 추가 없이 개별 상호작용으로 여는 안을 기본 제안으로 둔다.

보상 내용과 양은 미정이다. 원래 보물지도 기능의 전역 `treasure.found`를 다섯 상자의 공용 완료값으로 재사용하면 첫 상자 이후 모두 잠기므로 금지한다.

**검증:** 닫힘 전체, 각 1개 열림 5상태, 전부 열림, C4/C5 동시 열림을 눈으로 검사한다. 로컬 패치가 확정되면 32조합은 자동 합성해 비대상 영역 불변·패치 간섭을 검사할 수 있다. 32개를 AI로 생성할 필요는 없다. 현재는 원본 6장 채택만 완료이며 패치 추출·32조합 검사·실제 지급은 미완료다.

## 8. 워프·문·원판·환경의 적용 규칙

### 전망맵 워프

최종 채택은 원본에서 재수정한 오벨리스크 버전이다. 오른쪽 동굴 위 빈터의 크기·위치를 고정한다. 중앙 오벨리스크/큰 원형 포털/모래 차원문은 미채택이다. 상호작용이 작다고 본체를 키우지 말고 클릭 영역을 별도로 둔다.

현재 배경에 본체와 청록 표시가 그려져 있다. 휴면은 무발광 또는 닫힌 홈, 활성은 열린 홈·작은 점등처럼 **색 외 차이**도 제공한다. 본체를 배경에 남기는 경우 기존 코드의 오벨리스크 스프라이트를 중복 렌더하지 않는 연결이 필요하다. 활성 빛만 분리하고 본체는 고정할 수 있다. 도착점은 받침 위가 아니라 접근 가능한 앞 바닥이며 동행까지 안전하게 등장해야 한다.

### 문과 보상 벽감

열린 빈 내부를 먼저 준비한다. 닫힌 문짝/덮개와 봉인, 내부 유물을 따로 조합한다. 열림 시 문틀이 사라지면 안 된다. 시각 상태와 충돌·출입 조건을 같은 상태 변경으로 갱신한다. 전환 도중 플레이어가 문 안에 있으면 안전 처리가 필요하다. 이미 받은 유물은 퍼즐 초기화로 재생성하지 않는다.

### 01·19 원판

01은 기존 닫힘/열림 2상태를 활용하며 중앙 밖 보존 검증 기록을 유지한다. 19 고리는 투시가 있는 타원이므로 전체 PNG를 평면 회전시키지 않는다. 원판 평면상의 문양을 회전해 다시 투영하거나, 필요한 안정 방향별로 제작한다. 고정 외곽·바닥·단서판·환경 그림자는 회전하지 않는다. 단서판 두 곳은 최신 위치 그대로 유지한다.

### 환경과 물

10 입구의 모래 덮개와 열린 계단은 국소 상태로 바꾼다. 발견한 출입은 날씨 때문에 갑자기 없어지지 않는다. 07/20/보물방의 수면은 원본 위에 낮은 강도의 파문부터 검토한다. 원본 물색·반사·바닥이 반복 무늬로 덮이지 않게 한다. 완전한 수면 애니메이션은 마스크·성능 검증 후 늘린다. 활성 효과/날씨 효과를 줄여도 길과 단서는 읽혀야 한다.

## 9. 현재 코드에서 확인한 범위와 필요한 확장

이번 작업은 아래 파일을 읽기만 했다. 전체 엔진 감사나 실행 검증은 하지 않았다.

| 근거 | 확인한 것 | 적용 때 필요한 일 |
|---|---|---|
| `src/world/reference-scene.js` | 원본 배경, `origin/scale/clip`, 낮밤, occluder 처리 | 독립 상태 PNG 패치·가동 장치와 기존 가림의 통합 설계 |
| `src/world/map.js` | 채팅 flags 기반 타일 overlays | 이 타일 기능이 임의 PNG 패치 지원이라는 뜻은 아님 |
| `src/packs/world/obelisk.js` | `obelisks` 등록, `obelisk:<id>` 활성값, 깨어난 곳 이동 | 새 맵 등록·본체 중복 방지·도착점 확인 |
| 같은 워프 파일 | 현재 이동은 `o.x, o.y+1` 사용 | 새 맵에서도 안전한지 검증. 별도 arrival이 필요하면 확장 |
| `src/core/treasure.js` | 기존 보물지도 한 건의 단서·지급·중복 방지 | 다섯 독립 상자 저장으로 그대로 쓸 수 없음 |
| `src/packs/world/treasure.js` | 기존 보상 카드/아이콘 표현 | 카드 표현은 재사용 후보, 월드 개방 그림은 별도 |

맵 데이터·개별 장치·렌더·저장 책임을 분리한다. 제안 순서: 배경과 상태별 바닥 복원 → 지면 효과 → 발 기준 물체/캐릭터 → 현재 상태의 가림 → 광선·국소 빛의 필요한 층 → 선택/UI. 기존 occluder가 원래 닫힌 상자 배경을 다시 그려 열린 상자를 닫아버리지 않도록, 가림 복원도 현재 상태를 참조해야 한다.

제안 데이터 항목: `assetId`, `mapId`, `instanceId`, `state`, `files`, `sourceRect`, `placementPx`, `anchor`, `pivot`, `lightPorts`, `collisionFootprint`, `hitArea`, `interactionSpot`, `occlusion`, `requires`, `rewardId`. 기존 엔진이 모두 지원하는 필드명은 아니다. 좌표 변환은 원본 px→scene origin/scale→월드→화면 한 경로로 통일한다. 타일칸과 원본 px를 섞지 않는다.

저장은 채팅별로 분리하고 현재 장치 방향·돌 위치·발견·완료·보상 수령을 각각 보존한다. 이전 저장에 새 필드가 없으면 안전한 기본값을 채우며 기존 완료/소유품을 잃지 않는다. 보상 버튼 연속 터치, 저장 실패 후 재시도, 로딩 중 재입력까지 고려한다. 퍼즐 해결 판정은 코드 규칙으로 하며 생성형 모델 판단에 맡기지 않는다.

## 11. 제작 순서와 완료 기준

### 0단계 — 원본·배치 계약

채택 PNG/해시를 고정하고 가동 물체가 이미 배경에 있는지 표시한다. 13 최신 채택 원본 기준, 20↔보물방↔전망맵 접점, 15 높이 있는 광선, 실제 캐릭터/카메라 배율을 확인한다. 각 미확정 사항은 관련 작업만 보류하고 나머지 준비는 진행할 수 있다.

### 1단계 — 투시·분리 방법을 작은 단위로 검증

보물방 상자 1개를 추출해 닫힘/열림·캐릭터 앞뒤·원본 보존을 확인한다. 이것은 이미 채택한 상자 디자인을 다시 고르는 단계가 아니다. 병행 가능 준비는 15 장치 배치도와 논리 방향표다. 첫 기능 시험은 기존 계획대로 15의 광원1/반사판1/수신부1로 한다.

### 2단계 — 재사용 가능한 최소 기능

15의 조작·오답·완료·초기화·저장을 끝낸다. 검증한 패치 방식으로 상자 나머지4개를 추출하고, 전망 워프는 기존 기능에 연결한다. 배경 전체 재생성은 하지 않는다.

### 3단계 — 운반과 결합

17의 돌1/소켓1/문1을 독립 검증한 뒤 16 결합을 구현한다. 16의 9상황을 확인하고 첫 유물→복원→전시를 연결한다. 필요한 미술만 순차 추가한다.

### 4단계 — 문양과 비밀 발견

09→13→14의 문양 사전·단서·문을 확정하고 제작한다. 18의 정보와 01/19의 출입·회전 퍼즐을 잇는다. 13 파일 문제 해결 전 다른 버전으로 제작하지 않는다.

### 5단계 — 생활·환경·전체 연결

07/08/10/20 생활과 환경 상태, 부속실 조사, 나머지 출입·전경을 적용한다. 낮밤·폰 화면·전체 여행·재접속·기존 맵 회귀 검사를 마친 뒤 배포한다. 신규 미술 장수는 각 단계의 확정 목록에서 계산한다.

## 12. 파일·메타데이터 전달

작업별 `sources/`(불변 채택 원본), `png/`(적용 후보 부품), `previews/`(상태 합성), `review/`(검증), `manifest.json`을 구분한다. 현재 전체맵 채택 PNG를 곧바로 적용 부품으로 표시하지 않는다.

파일 예: `chest-C1-open.png`, `chest-C1-occlusion-open.png`, `mirror-head-O0.png`, `niche-empty.png`. 같은 상태 가족은 캔버스와 피벗을 통일하고 열린 뚜껑이 들어갈 여백을 처음부터 포함한다. 맵 전체 크기의 투명 PNG를 작은 물체마다 만들지 않는다.

manifest 필수 항목: 원본 상대경로/해시, 사용자 채택 근거, 적용 맵/역할, PNG 크기, 로컬 원점과 맵 배치 좌표, 기준점/회전축/광선 접점, 충돌·선택·접근점, 가림 기준, 상태 목록, 별도 효과, 공용/맵별 여부, 미술 채택/패치 검수/런타임 적용 상태. 미정 숫자는 null 또는 ‘미정’으로 쓴다. 포토샵 원본이 없는데 PSD가 있다고 기록하지 않는다.

## 13. 검사와 배포 문턱

**미술:** 원본과 같은 배율·경계 확대 확인, 투시/크기/광원 일치, 이중선·후광·사각 자국 없음, 투명 PNG 밝고 어두운 배경 검사, 보존 영역 픽셀 차이0, 상태별 피벗 일치. 애니메이션이 없으면 안정 상태만 먼저 검사한다.

**공간:** 셋소호 실제 크기로 모든 장치 접근, 출입 양방향 걷기, 문/계단 앞 대기·회전 공간, 가림이 머리 전체를 지우지 않음, 동행이 길을 막지 않음, 상자 열린 뚜껑 뒤/앞 검사, 워프 도착점과 절벽 거리 확인. 하늘·원경은 보행 영역이 아니다.

**논리:** 15 오답·완료·초기화, 16 9상황, 17 돌 회수·문 갇힘, 19 고리·단서 일치, 상자 개별 지급/32조합 간섭, 날씨 뒤 출구 유지. 미발견 비밀 노출·필수 동행/확률/현실 시간 강제 없음.

**저장:** 중간 종료/불러오기/재입장/연속 입력, 보상 중복 방지, 초기화 뒤 수령 기록 유지, 채팅A/B 분리, 이전 저장 마이그레이션, 저장 실패 복구. 초기화는 장치를 되돌려도 받은 보상을 되돌리지 않는다.

**엔진/성능:** 활성 상태와 렌더 일치, 타일·원본 좌표 변환, 카메라 이동/확대에서도 경계 일치, 낮밤 위치 불변, 휴대폰에서 효과·터치·로딩·메모리 확인. 사막에 안채의 픽셀/칸 값을 그대로 강제하지 않는다.

게임 적용 때는 최신 OPUS-HANDOFF의 요구를 다시 확인한다. 현재 명시된 공통 검사는 `tools/art/verify-full-map.cjs`, `verify-cozy-ui.cjs`, `verify-ui-themes.cjs` 세 가지와 출구 걷기·깊은 입구 동선·낮밤·폰 화면이다. 기존 출구31곳 회귀 검사에 새 사막 출구를 추가한다. 실행에 필요한 ST/확장 환경을 갖춘 뒤 돌리고, 위 공통 스크립트만으로 새 퍼즐 검사가 끝났다고 하지 않는다.

런타임 변경 시 `manifest.json`/`src/core/settings.js` 버전을 함께 갱신하고 실제 배포 절차를 따른다. `main`의 미술·문서 저장과 `release` 배포는 별개다. **이번 지침서 작성은 게임 버전 변경·배포·검사 실행을 포함하지 않는다.**

## 14. 다음 작업자가 바로 시작할 일

1. 이 문서와 추가 채택 manifest를 읽고 필요한 원본 한 장을 연다.
2. 먼저 보물방 C1의 작은 교체 영역/가림을 정해 한 상자의 적용 가능성을 확인한다.
3. 오푸스는 15의 논리 방향표·투영·높이 연결을 시험해 아스트라가 그릴 머리 방향을 확정한다.
4. 나머지는 위 단계 순서대로 늘린다. 전체 사막·모든 소품을 다시 그리기 시작하지 않는다.
