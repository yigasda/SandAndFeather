# 아스트라 몹 작화 지침

> **봉인 항아리 최신 제작 기준:** [결과·실제 프롬프트·재개 지시](art/desert-sealed-jar-2026-10-16/REUSE.md). 사용자가 “훨씬 낫다” 평가 후 백업 요청. 팔다리 없는 항아리의 몸체·뚜껑으로 생명감을 표현하며, 도트 밀도는 유지하고 기존 장치 디자인은 복제하지 않는다. 다음 생성은 사용자 요청 범위에서만 진행한다.

2026-10-16 · 사막 몹 제작 및 이후 몹 작업의 공통 기준

**최우선 사용자 요구: “기존 필드몹보다 조금만 섬세한 도트.”** 기존 게임의 표현 체계를 유지하면서 형태를 읽는 데 필요한 디테일만 조금 보탠다. 도트풍 일러스트·상품 이미지·도감 삽화를 만드는 작업이 아니다. 이 문서 작성은 새 몹 생성이나 게임 적용 지시가 아니다. 다음 제작은 최신 사용자 요청 범위에서 한다.

## 1. 참고 원본의 역할부터 구분한다

| 참고 | 제공하는 기준 | 가져오면 안 되는 것 |
|---|---|---|
| 사용자가 지칭한 기존 필드몹의 실제 원본 | 픽셀 덩어리 크기, 윤곽, 명암 단계, 단순화 정도, 게임 표시 크기 | 파일 확인 없이 임의의 몹을 기준으로 대체 |
| 같은 지역의 최신 채택 맵 | 3/4 시점, 빛 방향, 사암·청동·모래 등 재질색, 발이 닿는 공간 | 배경의 높은 디테일 밀도를 작은 몹에 그대로 복사 |
| 현재 플레이어 그림과 실제 렌더 배율 | 함께 서 있을 때 크기·윤곽·디테일 균형 | 사람 전용 머리 비율·피부색·전투 캔버스 수치 |
| 고대장치 채택 몹 10장 | 승인된 도트 표현과 위에서 보는 장치 투시의 보조 참고 | 모든 몹을 장치처럼 만들기, 실제 필드 적용 완료로 단정 |
| 외부 게임·동물 사진 | 기능·해부·행동 발상 | 화풍·카메라·정교한 털 묘사·고유 디자인 복제 |

### 현재 확인된 자료와 한계

- [채택 사막맵](../사막맵/README.md), [파일·해시 목록](../사막맵/manifest.json): 현재 23개 공간, 상태 그림 포함 29장. 새 수정은 목록에서 최신 채택을 확인한다.
- [05–20 통합 문서](ASTRA-DESERT-05-20-GUIDE.md): 장소 역할·연결·문양/장치 규칙. 보상·휴식방이라는 이유를 무시하고 모든 방에 몹을 채우지 않는다.
- [고대장치 원본](../몹/하위몹/고대장치/): `ring`, `hourglass` 각 idle/prepare/attack/hit/disappear 5장. [manifest](../몹/하위몹/고대장치/manifest.json)는 채택과 게임 적용/기준점 정렬을 분리한다. 이번 지침 작성 시 ring-idle 원본을 직접 확인했다.
- [두아트 인수인계](ASTRA-DUAT-HANDOFF.md): 기존 채택 디자인·상태·반려 기준. 과거 제작 보류는 새 사용자 요청 범위의 작업을 막지 않는다.
- [ASTRA-PLAN](ASTRA-PLAN.md) 3단계: 적의 역할·아펩 비늘·위계. [필드 전투 계획](DUAT-FIELD-COMBAT-PLAN.md): 적용 계획이며 실제 구현의 증거가 아니다.
- **이 지침 작성 시 확인한 main(1735f1d)에서는 사용자가 말한 ‘기존 필드몹’의 실제 전투 스프라이트를 특정하지 못했다.** `data/duat.json`의 일반 4종은 이름·능력치 데이터이며 그림 원본이 아니다. `src/packs/duat/duat.js`에서 확인한 것은 카드 전투 경로다. `src/world/paint.js`의 jackal→duat_guardian은 장식 그림 경로이므로 전투 몹으로 오인하지 않는다. 이후 main이 바뀔 수 있으니 최신 코드로 재확인한다.
- 다른 세션의 자칼은 사용자 첨부 스크린샷에서 반려된 결과다. 새 화풍 기준으로 삼지 않는다. 스크린샷의 일반몹6종+수문장1종 목록도 이 문서만으로 사용자 승인된 종수·디자인이라고 단정하지 않는다.

**기준 원본을 찾는 순서:** 최신 main → 적 ID/렌더 호출 → 실제 이미지·아틀라스 경로 → 프레임 사각형·기준점·배율 → 화면에 나온 적과 대조. 아틀라스면 정확한 프레임을 추출하고 출처를 기록한다. 끝내 찾지 못하면 ‘기준 미확인’이라고 밝히고 사용자에게 어떤 기존 몹인지 확인한다. 그동안 관련 맵·후보·기록은 정리할 수 있지만, 임의 기준으로 생성부터 반복하지 않는다. 이미 사용자에게 확인받은 원본은 다시 묻지 않는다.

## 2. ‘조금만 섬세하게’의 뜻

- 기존 도트 크기감·큰 신체 비율·윤곽 굵기·명암 단계는 유지한다. 큰 PNG 해상도와 세밀한 도트는 같은 말이 아니다.
- 추가하는 것은 귀 앞뒤 구분, 등과 옆구리의 면, 집게의 벌어짐, 장치의 분리 구조처럼 **게임 크기에서 형태를 읽게 하는 정보**다.
- 털 한 올, 작은 비늘 전부, 촘촘한 균열, 금속 미세 반사, 여러 겹 중간색을 추가하는 것은 목표가 아니다.
- 원본 색을 보지 않고 팔레트를 임의 16색/32색으로 고정하지 않는다. 재질별 밝음·기본·그림자·깊은 접합의 역할을 확인하고, 추가 단계가 꼭 필요한지 판단한다.
- ‘원본보다 20% 자세하게’ 같은 측정 불가능한 수치로 완료를 판단하지 않는다. 실제 크기에서 기존 몹 옆에 놓았을 때 같은 게임으로 보이는지가 기준이다.

## 3. 몹 도트의 구체적인 모양

### 실루엣과 시점

1. 작은 크기에서 종·앞방향·행동이 먼저 읽혀야 한다. 내부 묘사를 가려도 몸·귀·꼬리·집게 같은 특징이 남는다.
2. 실제 필드 카메라에 맞춘 위에서 내려다보는 3/4. 머리 윗면·등·어깨·장치 윗면이 보이고 발은 같은 지면에 닿는다. 정면 눈높이의 동물 삽화로 바꾸지 않는다.
3. 네발 생물은 가까운/먼 다리의 겹침과 접지를 일관되게 한다. 모든 다리를 보여주려고 벌리거나 길이를 바꾸지 않는다.
4. 몹답게 보인다는 이유로 가시·갑옷·붉은 눈을 일괄 추가하지 않는다. 실루엣·자세·행동으로 적의 역할을 읽게 한다.

### 픽셀과 색면

- 윤곽뿐 아니라 내부의 밝음·그림자도 의도적인 픽셀 덩어리로 만든다. 가장자리만 계단지고 내부는 매끈한 일러스트면 실패다.
- 곡선은 일정한 리듬의 계단으로, 면은 서로 연결된 색 덩어리로 표현한다. 무작위 1픽셀 잡음·잘게 찢어진 색점·과도한 디더링을 피한다.
- 윤곽의 중간색 띠·반투명 후광·에어브러시 그라데이션을 최소화한다. 단, 원본을 측정하지 않고 알파를 일괄 이진화해 가는 부품을 훼손하지 않는다.
- 털은 가슴·등·꼬리의 큰 덩어리와 소수 실루엣 돌기로 표현한다. 석재는 윗면/옆면/접합 그림자, 금속은 적은 밝은 면으로 구분한다.
- 원본보다 복잡한 그림을 만든 뒤 축소·샤프닝·포스터라이즈로 도트처럼 보이게 하는 방식을 기본으로 삼지 않는다. 생성 단계부터 형태와 색면을 단순화한다.
- 실제 표시 배율에서 흐려지면 원본·게임 렌더 보간·브라우저 표시를 구별한다. 무조건 더 선명하게 재생성하지 않는다.

### 캔버스와 크기

투명 PNG를 기본으로 하고, 캔버스 크기와 실제 몸체 경계 크기를 별도로 기록한다. 사람용 620×720/1600×720 규칙을 몹에 자동 적용하지 않는다. 먼저 기존 필드몹의 화면 크기를 확인한다. 필드 전투 계획의 ‘하위몹 약 캐릭터 1.1배’는 해당 계획의 값이며 모든 생물에 강제하지 않는다. 상위 몹 위계도 맵의 통로·플레이어 배율과 함께 결정한다.

## 4. 낭비 없는 제작 순서

1. 최신 사용자 요청에서 종·수량·바꿀 부분을 확인한다. 기존 채택본과 반려본을 구분한다.
2. 기준 필드몹·플레이어·해당 맵을 직접 열어 본다. 기준 파일과 그 역할, 사용할 배율을 짧게 기록하고 사용자에게 알린다.
3. 기준 외형 한 장을 먼저 만든다. 사용자가 시안 여러 장을 요청했다면 그 수를 만들되, 공통 화풍을 고정하고 실루엣·형태 차이를 분명하게 한다. 최초 요청 수를 임의로 축소하지 않는다.
4. **단독 원본 + 맵 위 실제 표시 크기 비교본**을 확인한다. 같은 화면에 기존 몹과 플레이어도 놓되 가림 없이 비교한다. 실제 런타임 배율을 못 얻었으면 ‘가정 배율’이라고 표시하고 게임 검증 완료라 하지 않는다.
5. 외형 채택 후 필요한 방향·상태를 정하고 모션 제작으로 넘어간다. 외형 반려 중에 공격·피격까지 양산하지 않는다.
6. 반복 반려면 더 긴 프롬프트로 계속 생성하지 말고 기준 이미지·시점·색면·픽셀 크기 중 무엇이 어긋났는지 먼저 확인한다. 사용자 추가 지시가 오면 그 범위로 재개한다.

## 5. 모션 제작은 외형을 고정한 뒤

- 몸 비율·주요 부품 크기·팔레트·광원·픽셀 크기·기준점이 상태마다 일관돼야 한다. 자세 때문에 짧아 보이는 것과 몸을 축소한 것을 구별한다.
- idle: 살아 있는 기본 자세. prepare: 공격 방향·위험을 읽는 예고. attack: 실제 타격 부위가 이동. hit: 생존 상태의 충격 반응. disappear: 소멸/퇴장. 종마다 필요한 상태와 프레임 수는 별도로 정한다.
- 부유·통째 회전·확대축소는 보조 움직임이지 모든 모션의 대체물이 아니다. 고대장치의 몸체 분리와 생물의 관절 운동을 같은 방식으로 처리하지 않는다.
- 투사체·큰 먼지·발광은 별도 에셋으로 검토한다. 대기 원본에 큰 효과를 구워 넣어 실루엣을 가리지 않는다.
- 방향 수는 게임이 사용하는 방향과 사용자 요청으로 확정한다. 비대칭 장식·빛·부품이 있는 그림을 무조건 좌우 반전하지 않는다.

## 6. 프롬프트 조립 틀

[맵 공통 프롬프트](ASTRA-MAP-PROMPTS.md)는 수정하지 않는다. 그 문서는 배경용이다. 몹에는 시점·지역 색 조화만 가져오고 ‘전체맵’, 건축 디테일, 배경 밀도를 이식하지 않는다. 아래 대괄호는 실제 확인한 자료로 채운 뒤 사용한다.

```text
Create ONE production-oriented field enemy sprite, [species / silhouette / pose], transparent background.
Reference 1 is the VERIFIED existing field-enemy sprite and controls pixel-cluster scale,
outline weight, simplification, value-step structure and body proportions appropriate to this species.
The target is ONLY SLIGHTLY more detailed than this reference, not a painted illustration.
Reference 2 is the player scale reference. Reference 3 is the map and controls camera,
light direction and local material colors ONLY, not background-level detail density.
Use the same overhead three-quarter gameplay view; readable top planes and grounded feet.
[Describe a few large silhouette features and the enemy's role.]
Use connected deliberate color clusters and stepped internal shading, not only a jagged outline.
Add only [specific necessary structural details]. Keep fur/stone/metal in broad readable masses.
No strand-by-strand fur, tiny cracks, soft airbrush gradients, antialiasing halos,
photorealistic anatomy rendering, product-render lighting or decorative microtexture.
Maintain [verified canvas / body bounds / pivot / intended displayed size].
No scenery, UI, text or baked large attack effects.
```

서로 다른 생물과 장치에 같은 신체 비율을 강제하지 않는다. 체형은 대상 설계에 맞추고 도트 표현의 기준을 공유한다.

## 7. 전달 전 확인

- 기준 원본과 같은 실제 크기에서 같은 게임의 몹처럼 보이는가? 확대 그림이 예쁜 것만으로 통과시키지 않는다.
- 맵과 시점·빛 방향·발 접지/부유 높이가 맞는가? 몸체와 바닥 그림자는 구분했는가?
- 모래·그늘·어두운 바닥 모두에서 몸과 공격 부위가 읽히는가? 실루엣을 밝은 테두리로 감추지 않았는가?
- 털·금속·균열을 줄여도 종이 읽히는가? 작게 보이는 물체 안에 불필요한 디테일이 몰려 있지 않은가?
- 투명 배경의 밝음/어두움 위에 흰 테두리·잔여 배경이 없는가? 확인 확대는 최근접 보간을 쓰고 원본과 표시용 확대본을 구분한다.
- 모션 단계면 프레임별 몸체 크기·기준점·실루엣 움직임을 비교했는가?

자동 크기·해시 검사와 시각적 화풍 검수는 별개다. 실제 게임 검사는 오푸스가 적용할 때 수행한다. 합성 미리보기만으로 충돌·애니메이션 적용 완료라고 하지 않는다.

## 8. 원본 보존과 전달

- 원본·시안·채택·게임 파생본을 구분한다. 기존 채택 파일을 새 생성 결과로 덮어쓰지 않는다. 수정에는 사용자가 지정한 원본을 사용하며 반복 생성본을 무조건 다음 베이스로 쓰지 않는다.
- 새 PNG 자체를 작업별 폴더에 저장한다. 미채택은 후보로 명시하고 최종 몹 목록에 섞지 않는다. 사용자 채택 때 최종 경로/목록을 갱신하되 이전 원본도 보존한다.
- manifest는 source/reference 경로, 크기·몸체 경계·pivot·배율(확인/가정 구분), 방향·상태, SHA256, 채택 근거, 게임 적용 여부를 담는다. 불명확한 값은 추정 확정하지 않는다.
- 기록은 작업별 공통 프롬프트 하나와 시안별 차이로 간소화한다. 같은 긴 설명을 매 장 복제하지 않는다.
- **PNG 저장 → 필요한 파일만 커밋 → main 푸시 → 원격 커밋과 파일 존재 확인**을 끝낸 뒤 백업 완료라고 말한다. 다른 세션의 작업은 덮어쓰거나 강제 푸시하지 않는다.
- Drive에는 채택본만 올린다. 기존 파일 교체 요청이면 올바른 파일 ID를 확인해 교체하고 목록/메타데이터로 확인한다.
- 아스트라는 그림 제작·원본 보존까지 맡는다. 게임 데이터·렌더·충돌·배포는 별도 요청과 오푸스 적용 절차를 따른다.
