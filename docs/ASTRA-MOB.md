# 아스트라 몹 작화 지침

**목표는 “기존 필드몹보다 조금만 섬세한 도트”다.** 채택된 몹의 표현 체계를 유지하면서 새 몹의 형태와 행동을 설계한다. 최신 사용자 지시가 이 문서보다 우선한다.

압축 후에는 **현재 요청 → 아래 채택 원본·실제 프롬프트 → 해당 제작 절** 순으로 읽는다. 이미 확정된 화풍을 다시 찾거나 취향을 되묻지 않는다. 게임 표시 배율 미확인은 작화 재개를 막는 이유가 아니다.

## 2. 주제를 몹으로 설계하기

**장소의 소재 → 몸이 되는 형태 → 살아 움직이는 방식 → 공격 행동 → 작은 크기에서 읽을 특징** 순으로 설계한다. 이름·장식·큰 효과부터 붙이지 않는다.

| 사례 | 몸과 생명감 | 행동으로 연결 |
|---|---|---|
| 항아리 | 토기 자체가 몸. 뚜껑 틈·몸통 기울임·봉인천 반응으로 내부 존재를 암시 | 닫히는 휴면 → 힘 모으기 → 몸통째 튀어 부딪힘 |
| 방패병 | 큰 방패가 몸의 인상을 지배하고 빈 두건·짧은 발이 움직임 | 방어 → 뒤로 당기기 → 방패째 돌진 |
| 비석 | 두꺼운 석판과 짧은 돌발, 문양이 있는 앞면과 몸체의 무게 | 버티기 → 뒤로 젖히기 → 머리 끝으로 내려찍기 |
| 거울 | 가운데가 조이는 금테의 비율·두께·굴곡, 부유와 유리 표면 반사 변화 | 은빛 방어 → 표면에 빛 응축 → 빛 공격 → 유리·금테 파손 |

### 사물형 몹은 사물 자체의 조형부터

‘몹답게’라는 요청을 눈·팔다리·큰 영혼 추가로 단순 해석하지 않는다. 원래 사물의 틀·뚜껑·받침 같은 구조에서 **질량 배분, 굵고 가는 부분, 굴곡, 기울기**를 잡는다. 외부 시계 몹 사례도 시계 몸체의 비율·두께·실루엣을 관찰하는 참고였으며 눈이나 영혼을 복사하라는 뜻이 아니었다.

태양거울은 **허리가 조이는 금테·각진 하부·3/4 두께**로 몸집을 잡았다. 불길한 반사는 이 조형에 성격을 더하며, 몸체 설계를 대신하지 않는다.

이집트 분위기도 색만으로 만들지 않는다. 방패병에서는 유럽식 철투구·원형 보스 방패·금속 장화가 반려되었고, 긴 가죽 방패·해진 아마포·봉인 석판 등 형태와 재료로 방향을 잡았다. 역사적 복원 정확성을 주장하는 규칙은 아니다.

출현 장소는 [05–20 통합 문서](ASTRA-DESERT-05-20-GUIDE.md)와 연결한다. 휴식·보상방에 임의로 전투를 추가하지 않는다. 능력치·등급·필수 전투 여부는 그림 채택과 별도다.

## 3. 같은 주제의 시안을 다르게 만드는 법

**역할·화풍·시점·조명·대략적 크기·기본 자세는 고정하고 디자인을 비교한다.** 색이나 자세만 바꾼 것을 서로 다른 디자인으로 세지 않는다. 사용자가 주제를 좁혀 주면 그 범위 안에서 차이를 만든다.

| 차이 축 | 방패병 예 |
|---|---|
| 실루엣·비율 | 긴 둥근 윗부분 / 각진 목제 / 아래가 넓은 석판 |
| 구조·재료 | 가죽·목재·봉인 석재 |
| 특징 | 수선 바느질 / 연꽃 / 봉인띠 |
| 허용 범위 | 이집트 수호병이라는 역할 유지 |

새 몹에 다른 몹의 몸체·받침·장식을 그대로 이식하지 않는다. 같은 소재가 필요하면 새 주제에서 이유를 찾아 독립적으로 선택한다.

## 4. 도트·시점·재질 기준

### 도트 표현

- 윤곽뿐 아니라 **내부 밝음·그림자도 의도적인 픽셀 덩어리**로 만든다. 매끈한 일러스트 가장자리만 계단지게 만들지 않는다.
- 기존 채택본의 덩어리 크기·윤곽·명암 밀도를 유지한다. 큰 PNG 해상도는 세밀한 도트 품질의 증거가 아니다.
- 추가 디테일은 입구·깨진 단면·접합·윗면 등 형태를 읽게 하는 정보다. 털 한 올, 촘촘한 균열, 미세 금속 반사, 무작위 잡음을 늘리지 않는다.
- 팔레트를 임의로 16색/32색으로 고정하거나 ‘20% 더 자세함’ 같은 수치로 평가하지 않는다. 재질별 큰 색면의 역할과 실제 표시 크기를 본다.
- 복잡한 일러스트를 축소·샤프닝·포스터라이즈해 도트로 만드는 방식을 기본으로 삼지 않는다. 생성부터 색면을 설계한다.
- 반투명 테두리·에어브러시 후광을 줄이되, 알파를 일괄 이진화해 가는 부품을 훼손하지 않는다.

### 3/4 시점은 평면 회전과 다르다

위에서 내려다보며 **윗면과 옆면 두께가 보이는 입체 투시**를 맞춘다. 정면 그림을 화면 안에서 대각선으로 돌리는 것만으로는 이 투시가 생기지 않는다.

생물은 가까운/먼 다리의 겹침과 접지를 일관되게 한다. 부유형에는 지면에 서는 발을 강제하지 않는다. 종마다 체형은 달라도 카메라·광원·도트 표현의 기준은 공유한다.

### 재질과 분위기를 분리해서 지시한다

재질마다 고유한 색과 명암을 구분한다. 항아리는 토기의 큰 면과 뚜껑 구조, 방패병은 가죽·천·석판의 차이를 표현한다. ‘오래됨’은 마모와 손상으로, ‘불길함’은 형태·공간·빛의 이상으로 지시한다. 분위기를 위해 전체를 같은 색이나 어두운 덩어리로 뭉개지 않는다.

## 5. 프롬프트 작성과 참고 자료의 역할

**기존 채택 몹의 실제 프롬프트를 먼저 읽고 형식·작화 지시를 계승한다. 새 몹의 디자인은 독립적으로 설계한다.**

| 참고 역할 | 가져올 것 | 가져오지 않을 것 |
|---|---|---|
| 다른 채택 몹의 작화 | 도트 덩어리·내부 명암·윤곽 표현 | 그 몹의 팔레트·몸체·장식·팔다리 조건 |
| 같은 몹의 채택 외형 | 실루엣·비율·재질·주요 세부·시점 | 이전 반려 디자인으로 되돌아가기 |
| 다른 디자인의 동작 시트 | 자세·순서·움직임 원리 | 그 시트의 장비·재질·신체 디자인 |
| 채택 맵 | 지역 역할·카메라·빛 방향 | 배경의 디테일 밀도를 작은 몹에 그대로 복사 |
| 플레이어·런타임 원본 | 실제 표시 배율·피벗·프레임 영역 | 사람 전용 캔버스 규칙을 몹에 강제 |

봉인 방패병은 참고1에서 석판형 외형, 참고2에서 가죽형 동작만 가져왔다. 이처럼 참고별 역할을 명시하고, 서로 다른 캔버스 크기를 실제 몸체 크기로 따라 하지 않는다.

새 작업용 조립 순서는 다음과 같다. 이 틀을 과거 호출 원문이라고 기록하지 않는다.

```text
OUTPUT: [3 design candidates / one 2-row x 5-column motion sheet], transparent PNG.
REFERENCE ROLES: each reference controls [rendering / identity / motion] ONLY.
IDENTITY: silhouette, proportions, materials, characteristic construction, life mechanism.
STYLE: deliberate pixel clusters and stepped INTERNAL shading; elevated 3/4 volume.
DESIGNS: same pose/camera, meaningful differences within the user's theme.
OR MOTION: every cell in reading order; moving surface/parts and rigid parts distinguished.
CONSISTENCY: same physical body scale, proportions, palette and pixel density throughout.
DELIVERY: complete silhouettes, generous transparent margins, no text/panels/scenery.
EXCLUSIONS: only this creature's actual failure risks, not copied unrelated restrictions.
```

움직일 부분과 고정할 부분을 구체적으로 쓴다. 항아리의 ‘팔다리 없음’을 모든 다음 몹에 복사하지 않는다. 같은 몹의 모션은 외형 보존이 우선이다.

사용자 요청으로 **이전 거울 외형 탐색 프롬프트는 삭제**했다. 되살리거나 추정해 ‘실제 원문’으로 만들지 않는다. 현재 외형 `prompt.txt`는 마지막 색 수정문이며 독립적인 최초 생성문이 아니다. 채택 PNG와 재사용 지침을 함께 읽는다. 모션 수정 기록은 보존하되 재개 기준은 1절의 최종 통합 프롬프트다.

[맵 공통 프롬프트](ASTRA-MAP-PROMPTS.md)는 수정하지 않는다. 배경용 건축 디테일·전체맵 지시를 몹에 이식하지 않는다.

## 6. 모션의 고정 10칸 순서

**한 번에 2행×5칸을 생성한다.** 각 행은 왼쪽부터 읽는다.

| 행 | 1열 | 2열 | 3열 | 4열 | 5열 |
|---|---|---|---|---|---|
| 위 | 대기0 | 대기1 | 대기2 | 방어·휴면 등 | 준비0 |
| 아래 | 준비1 | 공격 계열0 | 공격 계열1 | 피격 | 소멸 |

대기3칸·준비2칸·피격·소멸의 **순서와 프레임 수는 공통**, 실제 자세는 몹 구조에 맞춘다. 4번은 방어가 보편적이지만 휴면 등 자연스러운 상태를 아스트라가 결정한다. 7·8번은 몸통 공격·돌진·내려찍기·빛 공격 등 모두 같은 공격 계열이다. 준비를 세 칸으로 늘리거나 별도 공격 슬롯을 추가하지 않는다. 선택한 특수 상태와 공격 종류를 짧게 알리고 진행한다.

### 몹별 적용 예

모바일에서도 읽기 쉽게 같은 칸 순서로 사례를 나눴다.

| 칸 | 항아리 | 방패병 |
|---|---|---|
| 1–3 대기 | 부유·기울임, 뚜껑 간격·천의 지연 반응 | 체중 이동, 두건 높이·방패 각도 변화 |
| 4 특수 | 휴면: 바닥에 붙고 뚜껑 닫힘 | 방어: 방패 뒤로 숙여 버팀 |
| 5–6 준비 | 몸을 당기고 뚜껑 간격을 좁힘 | 방패와 몸을 당겨 힘을 모음 |
| 7–8 공격 | 몸통째 튀며 뚜껑·천이 뒤따름 | 앞으로 딛고 방패째 돌진 |
| 9 피격 | 생존 충격 의도. 채택 시트에 파편이 생긴 한계 있음 | 살아서 비틀림, 방패 파손 없음 |
| 10 소멸 | 큰 토기 조각으로 분리 | 온전한 방패가 눕고 빈 천이 주저앉음 |

| 칸 | 걸음 비석 | 태양거울 |
|---|---|---|
| 1–3 대기 | 짧은 발과 몸의 작은 무게 이동 | **신전 내용은 유지**, 유리 표면 은빛 반사 띠가 위쪽→가운데→아래쪽으로 이동 |
| 4 특수 | 방어: 몸을 낮추고 버팀 | 방어: 넓은 은빛 반사로 표면을 가림 |
| 5–6 준비 | 몸통을 당겨 내려찍을 힘을 모음 | 표면 가장자리의 빛이 작은 발사점으로 모여 응축됨 |
| 7–8 공격 | 몸체를 앞으로 기울여 머리 끝으로 내려찍고 모래가 튐 | 표면 오라와 중심 섬광이 강해짐. **긴 광선은 별도 PNG** |
| 9 피격 | 살아 있는 몸의 비틀림 | 틀이 비틀리고 반사가 흐트러짐, 아직 파손하지 않음 |
| 10 소멸 | 비석이 큰 조각으로 무너짐 | 금테 일부와 유리가 깨지고 신전 반사·빛이 사라짐 |

### 연속 동작과 비율을 함께 검수한다

- 대기 세 칸은 실제로 구분되어야 한다. 어떤 부위·표면이 움직이는지 정하고 고정된 디자인은 유지한다.
- 공격을 강화하면 준비도 연결한다. 준비→공격의 발사점·방향·강도가 이어져야 한다.
- 피격은 생존, 소멸은 종료가 읽혀야 한다. 파손 소멸을 모든 몹에 강제하지 않는다.
- **상태별 개별 생성과 부분 수정 누적으로 화풍·비율이 달라질 수 있다.** 외형·움직임이 정해지면 통합 생성으로 일관성을 확인한다.
- 자세에 따른 원근 축소와 실제 몸체 크기 변화는 다르다. 같은 프레임 크기만으로 동일 비율을 보장하지 않는다. 빛의 크기를 몸 크기로 판단하지 않는다.
- 방향은 사용자 요청과 게임에 맞춘다. 비대칭 디자인·광원을 무조건 좌우 반전하지 않는다.

## 7. 부분 수정과 별도 효과

원본을 지정받으면 그 파일에서 시작한다. ‘각도만’ 같은 지시는 새 디자인을 생성하라는 뜻이 아니다. **사용자가 요청한 직접 회전·잘라 붙이기·합성은 원본 픽셀을 활용**한다. 비석 내려찍기는 넓은 원본을 30도 회전하고 모래를 더한 버전이 채택되었다. 그 외 그림 수정에는 사용 가능한 이미지 편집 도구 지침을 따른다.

거울은 **몸체의 표면 오라**와 **멀리 뻗는 광선**을 분리했다. 몸체 공격 프레임에는 발사점과 근접 섬광을, 별도 PNG에는 긴 빛줄기를 둔다. 광선의 방향·발사점·길이·피해 판정은 엔진에서 연결한다. 분리 에셋을 만들었다고 게임 적용을 완료한 것은 아니다.

국소 편집을 요청해도 생성 결과가 다른 부분을 바꿀 수 있다. 픽셀 동일성을 검사하지 않았다면 ‘다른 부분 픽셀까지 동일’이라고 말하지 않는다. 원본과 수정본을 보존하고 변경 범위를 비교한다.

## 8. 제작·검수·백업 순서

1. 최신 요청과 채택 목록에서 대상·수량·원본을 확인한다. 실제 입력 이미지를 열고 참고 역할을 구분한다.
2. 새 몹이면 주제와 행동을 정해 요청한 수의 디자인 시안을 만든다. 외형 선택 전에 모션을 양산하지 않는다. 반복 반려면 더 긴 프롬프트로 무작정 재생성하지 말고 실루엣·시점·재질·픽셀 표현 중 문제를 짚는다.
3. 외형 채택 후 고정 10칸을 한 번에 만든다. 부분 수정이 누적되면 전체 비율을 다시 확인한다.
4. 실제 파일의 RGBA·알파, 외곽 잘림, 여백, 프레임별 크기와 동작 차이를 확인한다. 투명 미리보기가 검게 보인다는 이유로 검정 배경이라 단정하지 않는다. 알파가 존재해도 불필요한 후광이 남을 수 있다.
5. 모래·그늘 등 실제 배경 위에서 실루엣·반사·광선을 확인한다. 효과로 몸체를 가리지 않는다.
6. 플레이어·기존 몹과 실제 표시 크기로 비교한다. 배율을 모르면 ‘가정 배율’로 표시한다. 프레임 추출·기준점·시간·충돌은 실제 적용 단계에서 검증한다. 단순 해시 검사와 시각 검수는 별개다.
7. **PNG 자체 저장 → 필요한 파일만 커밋 → main 푸시 → 원격 커밋·파일 존재 확인** 후 백업 완료라고 말한다. 다른 작업을 덮어쓰거나 강제 푸시하지 않는다.

원본·시안·채택·게임 파생본을 구분하고 기존 원본을 덮어쓰지 않는다. manifest에는 참고 역할·크기·SHA256·채택 근거·적용 여부와 확인한 피벗/배율을 기록하되 미확정 값을 꾸미지 않는다. 대기0 원본을 보존하며 생성된 시트 첫 칸과 픽셀 동일하다고 주장하지 않는다.

기록은 **현재 채택 목록과 재사용 가능한 원칙**을 중심으로 유지한다. 작업별 긴 프롬프트는 해당 폴더 한 곳에 저장하고 지침 본문에 복제하지 않는다. 사용자 삭제 지시는 따르되 삭제한 프롬프트를 새 문서에 다시 옮겨 놓지 않는다. Drive는 채택본만, 교체 요청 시 파일 ID와 반영 결과를 확인한다.

아스트라는 작화·원본 보존·전달을 맡는다. 게임 데이터·렌더·충돌·배포는 별도 요청과 오푸스 절차를 따른다.

초기 조사 main `1735f1d`에서는 사용자가 말한 기존 필드몹의 실제 전투 스프라이트를 특정하지 못했다. 당시 `data/duat.json`은 적 데이터, `src/packs/duat/duat.js`는 카드 전투 경로였고 `src/world/paint.js`의 jackal→duat_guardian은 장식 그림 경로였다. 이 기록은 **과거 런타임 확인의 한계**이지 현재 채택 작화 기준이 없다는 뜻이 아니다.
