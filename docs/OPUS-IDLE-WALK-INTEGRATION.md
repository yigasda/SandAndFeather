# 오푸스 적용 지시 — 승인된 셋소호 기본 자세와 걷기

작성일 2026-10-10. 사용자가 최신 시안을 승인하고 이 지시와 파일을 main에 올려 달라고 요청했다. 이 문서가 **기본 자세·걷기 선택에 대한 최신 기준**이다. 다른 인수인계의 초미니 스프라이트 설명은 과거 구현 기록이다.

**해야 할 일:** 승인된 세트·소망·호루스의 4방향 기본 자세와 걷기를 실제 게임에 연결한다. 아트 원본을 다시 그리지 않는다. 이번 커밋은 적용 지시와 파일 명세만 추가하며, 런타임 적용 완료를 뜻하지 않는다. 코드 조사 기준은 main `afbf12b`, 현재 확장 버전은 0.9.7이다. 작업 시작 시 최신 main을 받아 다른 작업자의 변경도 확인한다.

## 1. 먼저 읽을 파일

| 순서 | 파일 | 용도 |
|---|---|---|
| 1 | 이 문서 | 적용 범위, 선택 기준, 렌더링 수정, 검증 지시 |
| 2 | [APPROVED-IDLE-WALK-FILES.md](APPROVED-IDLE-WALK-FILES.md) | **48장 전체를 한 파일씩 나열한 원본 목록** |
| 3 | [approved-idle-walk-manifest.json](art/chibi-refresh/animations/approved-idle-walk-manifest.json) | 같은 48장의 경로, 방향, 프레임 번호, 크기, 기준점, 알파 경계, SHA-256, 재생 설정 |
| 4 | [walk-v4-horus-micro-motion/manifest.json](art/chibi-refresh/animations/walk-v4-horus-micro-motion/manifest.json) | 호루스 정면 최종 미세 움직임과 참조 PNG 해시 |

원본 이미지는 이미 main에 커밋되어 있다. Drive에서 이미지나 GIF를 내려받아 다시 자르지 말고 저장소 PNG를 읽는다. JSON의 모든 `path`는 저장소 루트 기준이다. `status`는 아트 승인 상태이며 게임 적용 상태는 `runtimeApplied: false`다.

## 2. 승인 상태와 이번 범위

- **기본 자세:** 81번 승인. `common-body-v2-dress-and-profile`의 12개 개별 PNG.
- **세트·소망 걷기:** 첫 걷기 시안 승인. `walk-v1`의 두 캐릭터 24개 개별 PNG 그대로.
- **호루스 뒤·좌·우 걷기:** `walk-v1`의 9개 개별 PNG 그대로.
- **호루스 정면 걷기:** 그림은 `walk-v2-horus-front`의 3개 개별 PNG. 여기에 `walk-v4-horus-micro-motion`의 1픽셀 배치 설정을 적용한 **91번 합본이 최종 승인**이다.
- 상인과 다른 NPC, 대화 초상화, 파티 전신 일러스트는 이번 승인 대상에 포함하지 않는다. 기존 것을 유지한다.
- 달리기·상호작용·조사·전투·주문·부상 등 나머지 바리에이션, 두아트 새 맵 제작은 아직 별도 작업이다. 기다리지 말고 이번 기본 자세·걷기를 먼저 연결한다.

그림체, 얼굴, 등신, 손발 크기, 세트의 곧은 측면 몸을 바꾸지 않는다. 세트 하의를 옛 긴 치마나 비대칭 치마로 되돌리지 않는다. 소망은 최신 하늘하늘한 흰 드레스와 풀어 내린 가슴 길이 곱슬을 사용한다. 호루스는 푸른 남색 짧은 머리, 기존 동공 크기, 작은 아래 안광, 캐릭터 왼쪽 눈 문양을 유지한다. 큰 위 안광을 추가하지 않는다.

`*-source.png`는 자르기 전 생성 원본이다. `*-preview.jpg`, `*-poses.jpg`, GIF는 검토용이다. 게임에는 투명 PNG 프레임을 패킹해서 사용한다. 호루스 `walk-v3-horus-soft-motion`은 고개가 그네처럼 흔들려 사용자가 거절했으므로 사용하지 않는다. v2 GIF만 재현하는 것도 최종 요청과 다르다. **v2 그림 + v4 배치 설정**을 함께 사용한다.

## 4. 방향과 프레임 번호

| 파일 이름 방향 | 게임 `dir` | 의미 |
|---|---|---|
| `front` | `down` | 정면, 화면 아래로 걷기 |
| `back` | `up` | 뒷면, 화면 위로 걷기 |
| `left` | `left` | 화면 왼쪽을 바라보는 측면 |
| `right` | `right` | 화면 오른쪽을 바라보는 측면 |

걷기 합본은 **4행 × 3열**이다. 행은 `down, up, left, right`, 열은 포즈 `0, 1, 2`. 각 셀은 360×400이고 좌표는 `[phase * 360, row * 400, 360, 400]`이다. 기존 게임의 정지 아틀라스 열 순서 `down, left, right, up`와 다르므로 배열 순서를 추정하지 않는다.

걷기 주기는 `0 → 1 → 2 → 1`, 미리보기에서는 단계당 180ms, 한 주기 720ms다. `0 → 1 → 2`만 반복하지 않는다. 포즈 1은 이동 중 가운데 자세이지 멈춘 상태의 기본 자세가 아니다. 멈추면 81번 `idle` PNG로 돌아간다.

## 5. 호루스 정면 1픽셀 예외 — 가장 중요

| 주기 단계 | 정면 그림 | x 오프셋 | y 오프셋 | 시간 |
|---|---|---:|---:|---:|
| 0 | `horus-front-0.png` | +1 | 0 | 180ms |
| 1 | `horus-front-1.png` | 0 | -1 | 180ms |
| 2 | `horus-front-2.png` | -1 | 0 | 180ms |
| 3 | `horus-front-1.png` | 0 | -1 | 180ms |

오프셋은 **원본 360×400 셀의 픽셀 단위**다. 게임 논리 픽셀이나 CSS 픽셀 1칸으로 더하지 않는다. 330px짜리 캐릭터를 게임 높이 `H`로 그리면 이동량도 `H / 330`배, 줌을 쓰면 줌 배율까지 곱한다. 50% 크기인 합본 GIF에서는 원본 1픽셀이 0.5픽셀이다.

이것은 머리만 회전시키는 효과가 아니라 전체 스프라이트의 작은 표시 위치 변화다. **추가 회전은 0도**다. 머리 기울임, 확대·축소, 사인파 좌우 흔들림을 추가하지 않는다. 정지 중과 다른 방향에는 적용하지 않는다. 이동 좌표, 발 충돌박스, 상호작용 판정, 그림자 기준점에는 이 오프셋을 더하지 않는다.

현재 `Renderer.person()`은 `Math.floor(step) % 2`만큼 논리 픽셀 높이를 바꾸는 옛 bob 효과를 더한다. 새 승인 프레임을 쓰는 셋소호 경로에서는 이 효과를 제거한다. 남겨두면 승인된 1픽셀보다 훨씬 크게 흔들릴 수 있다. 기존 NPC 렌더링 경로까지 무조건 바꾸지는 않는다.

## 6. 크기·기준점·패킹

| 종류 | 원본 셀 | 셀 안의 발 기준점 | 캐릭터 기준 높이 |
|---|---|---|---:|
| 정지 | 620×720 | 310, 662 | 628 |
| 걷기 | 360×400 | 180, 370 | 330 |

숫자는 원본 픽셀 단위다. 게임 표시 높이는 아직 실제 맵에서 검토하지 않았다. 같은 캐릭터의 정지와 걷기에 동일한 **보이는 높이**를 적용한다. 620×720과 360×400에 같은 `atlas.scale`을 무작정 넣으면 정지와 이동 때 크기가 바뀐다.

추천 처리: 기존 아트의 비율을 보존한 균일 배율로 새 정규 셀에 패킹하고 동일한 발 기준점으로 맞춘다. 예를 들어 게임 캐릭터 목표 높이를 `H`라 하면 정지는 `H/628`, 걷기는 `H/330`을 출발값으로 쓴다. 프레임마다 알파 영역을 새로 꽉 채워 확대하면 머리가 커졌다 작아지므로 사용하지 않는다. 실제 알파 경계는 파일별 JSON에 넣었다. 걷기 중 작은 발·옷 움직임을 크기 차이로 판단해 없애지 않는다.

현재 `person()`의 타일 시작 위치 `x,y`를 기준으로 시각적 발 앵커는 기본적으로 `x + 8*z, y + 16*z`에 맞춘다. 그림 좌상단은 이 앵커에서 원본 pivot에 해당 배율을 곱한 값을 빼서 구한다. 이미지 아래 투명 여백까지 발로 간주해 띄우지 않는다. 기존 `FOOT`, `feet()`, 맵 출입 좌표와 y 정렬 기준을 그림 크기에 맞춰 임의로 변경하지 않는다.

최종 화면 크기는 폰에서 승인된 두아트 비교 분위기와 확인한다. 종전 초미니 20×20 셀 크기를 새 아트에 그대로 강제하지 않는다. 정지↔걷기 전환 시 얼굴 크기와 의상 길이 차이도 실제 화면에서 확인한다. 원본은 시안에서 승인됐지만 정지와 걷기가 서로 다른 생성물이므로 이 전환의 완전한 일치는 아직 검증하지 않았다. 차이가 보이면 원본을 몰래 다시 그리지 말고 비교 화면으로 남긴다.

새 패커를 별도 파일로 만들고 `data/art/characters/` 아래 별도 런타임 아틀라스를 출력하는 방식을 권장한다. `tools/art/pack-pocket-sprites.cjs`는 옛 초미니 원본을 읽어 `pocket-chibi.png`를 덮어쓰므로 이번 새 그림 패킹에 그대로 실행하지 않는다. 그 파일을 유지해야 상인 등 기존 NPC의 폴백도 보존된다. 원본 `docs/art/` 파일에는 덮어쓰기 금지.

## 7. 현재 코드에서 바꿀 곳 — 파일별 지시

| 파일 | 현재 동작 | 오푸스가 할 작업 |
|---|---|---|
| `data/sprites.json` | `looks.*.atlas.file`, 방향별 단일 사각형, 공통 scale | 셋소호 정지/걷기를 명시적으로 등록. 새 애니메이션 메타데이터 추가 시 로더·검사기와 함께 확장. 기존 단일 프레임 NPC 호환 유지 |
| `src/core/data.js` | `loadSpriteArt()`가 `d.atlas.file`만 모아 decode | 새 걷기 아틀라스가 별도 파일이면 로드 목록에도 포함. 파일별 중복 로드 방지 및 기존 오류 처리 유지 |
| `src/core/check.js` | atlas의 방향별 단일 `[x,y,w,h]`만 검사 | 새 정지/걷기의 모든 rect, 이미지 경계, 프레임 순서, 양수 duration, pivot과 offset 유효성 검사 추가. 기존 NPC 검사 유지 |
| `src/world/render.js` | `setSprites()`가 한 방향당 캔버스 하나를 캐시 | 방향+상태+포즈별 캐시 또는 원본 아틀라스 참조로 확장. 프레임마다 이미지 decode나 캔버스 생성 금지 |
| 같은 파일 `person()` | 한 장에 옛 bob을 더함 | `idle/walk` 선택, `0,1,2,1` 주기, 명시적 발 pivot, 호루스 down 오프셋을 구현. 새 셋소호의 옛 bob은 끔 |
| 같은 파일 `draw()` | 플레이어와 NPC 객체를 모아 두 렌더 경로로 전달 | 실제 이동 여부와 애니메이션 상태 전달. 일반 타일 맵 경로와 `paintActors` 콜백 경로 둘 다 같은 선택 함수 사용 |
| `src/world/player.js` | `player.moving`은 입력 크기로 정해지고 `step += dt * 8` | 실제 이동량에 따른 걷기 여부/시간 처리. `SPEED`, `FOOT`, 출입 좌표는 스프라이트 때문에 변경하지 않음. 걷기 시작·정지·방향 전환 상태를 명확히 처리 |
| 같은 파일 `follower()` | 플레이어의 `moving/step`을 전달하는 구조 | 동료의 실제 위치 변화와 멈춤도 확인. 세트/호루스가 동료일 때 제대로 움직이고 멈추도록 유지 |
| `src/ui/window.js` | `draw()`가 NPC에 step 0, 동료에 moving에 따른 step을 전달 | `moving` 또는 명시적 애니메이션 상태를 people 객체에 전달. `step === 0`만으로 idle을 판별하면 첫 걷기 단계와 혼동되므로 피함 |
| 같은 파일 `frame()` | 걷기 30fps, 정지 8fps, 카드 4fps | 프레임 수가 아닌 경과 시간으로 걷기 위상을 계산. 카드/접기/백그라운드 복귀 시 한꺼번에 위상이 폭주하지 않도록 확인 |
| `src/world/reference-scene.js` | 기존 배경의 가림과 `paintActors` 처리 | 구조를 유지하며 새 크기의 캐릭터도 같은 발 위치로 가려지는지 확인. 그림 키를 가림 순서 좌표로 쓰지 않음 |
| `tools/art/verify-pocket-sprites.cjs` | 옛 16개 정지 그림과 상인을 대상으로 검증 | 참고용. 새 48개 소스와 걷기 상태 전환을 검증하는 별도 또는 확장 검증 마련. 옛 `r.art` 구조를 그대로 가정한 검사는 새 구조에 맞춤 |
| `manifest.json`, `README.md`, `docs/SESSION-HANDOFF.md` | 현재 런타임 버전 0.9.7 | **실제 적용·검증 후에만** 버전/완료 내역 갱신. 현재 이 문서 추가를 게임 적용 완료로 기록하지 않음 |

정확한 새 JSON 스키마는 오푸스가 현 코드와 맞춰 설계하되, 이 문서의 소스 선택·방향·재생 순서·pivot·오프셋 단위는 그대로 따른다. 그림을 바꾸는 일이 아니라 이 데이터를 런타임에 연결하는 작업이다.

## 8. 걷기 상태 처리

1. 방향은 기존 `down/up/left/right` 규칙을 유지한다. 호루스 비대칭 문양 때문에 좌우를 반전해 재사용하지 않는다.
2. 실제 이동이 시작되면 해당 방향 걷기를 재생한다. 벽에 완전히 막혀 좌표가 안 변하면 정지 자세를 사용하고 방향만 입력에 맞출 수 있다. 벽을 따라 미끄러져 이동하면 계속 걷는다.
3. 멈추면 해당 방향의 기본 자세로 전환하고 작은 배치 오프셋도 0으로 복귀한다. 걸음 가운데 포즈를 정지 이미지로 고정하지 않는다.
4. 이동 방향이 바뀌어도 같은 걸음 위상을 유지하는 것을 기본으로 한다. 방향 변경마다 무조건 0으로 리셋하면 빠른 조작에서 발을 내딛지 못한다.
5. 미리보기의 180ms를 기준으로 먼저 연결한다. 기존 `step`의 단위는 8/초여서 바로 인덱스로 쓰면 GIF 속도와 다르다. 실제 이동 거리와 보폭이 맞는지 확인하며 조정 내역을 기록한다. 그림을 맞추려고 이동 속도 4.2타일/초를 임의로 바꾸지 않는다.
6. 정지 NPC는 정지, 동행 중인 세트·호루스는 걷기, 대화창을 열거나 장면이 멈췄을 때는 정책에 맞게 정지한다. 카드 아래에서 혼자 발만 움직이지 않게 한다.

## 9. 구현 후 확인할 것

- 48개 소스 로드/패킹, 투명 배경, 아틀라스 rect 범위와 방향을 확인한다. 새 손발이 셀 끝에서 잘리지 않아야 한다.
- 셋 각각 4방향으로 걷기·멈춤·방향 전환을 확인한다. 세트·호루스는 동료로도 확인한다. 호루스 정면 문양은 화면 오른쪽이며 오른쪽 측면에 복제되지 않는다.
- 걷기 순서 `0,1,2,1`, 정상 frame duration, 정지 시 idle 복귀를 확인한다. 첫 위상 0도 움직임으로 처리한다.
- 호루스 정면은 최종 91번 GIF와 비교한다. 기존 논리 픽셀 bob, 추가 회전, head sway가 중복되지 않아야 한다. 1 source px를 1 logical px로 착각하지 않는다.
- 정지↔이동 시 키가 튀지 않는지, 세트 배가 다시 부풀어 보이지 않는지, 소망 치마/머리가 잘리지 않는지 폰 화면에서 확인한다.
- 옴보스 낮·밤, 안채 문/기둥 뒤, 전경 가림, 상호작용 범위, 출입·계단·동료 따라오기·충돌을 확인한다. 발 충돌 범위는 원래대로 유지한다.
- 정지 상인 등 기존 NPC와 폴백이 정상인지 확인한다. 새 걸음 때문에 상인 그림이나 기존 초상화가 바뀌면 안 된다.
- 기존 지도 회귀 검증은 변경 범위에 맞게 실행한다. 실제 브라우저가 없으면 화면 검증을 했다고 적지 않는다.
- 사용자에게 폰 크기의 실제 게임 움직임 결과와 적용 커밋을 전달한다. 사용자 환경에서 인라인 이미지가 안 보일 수 있으므로 결과 이미지는 접근 가능한 링크도 제공한다.

이 문서 작성 시에는 48개 파일의 존재·RGBA·크기·잘림 여부와 해시를 검사했다. 게임 로딩, 접지, 실제 맵 크기, 애니메이션 상태 전환은 오푸스 적용 후 검증할 항목이다.
