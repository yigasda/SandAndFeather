# 맵 확장과 개별 실내 맵 구현 지시

2026-10-10 사용자 정정 반영. **복도에서는 벽과 방문만 보이고, 문으로 들어가면 그 방 내부만 별도 맵으로 보여주는 쯔꾸르 방식**으로 구현한다. 모든 방을 한 번에 내려다보는 전체 안채 그림은 배치·색감 참고로 보관한다. 이 문서의 최신 구조가 앞선 통합 안채 구현 지시를 대체한다.

주요 지역 8곳과 모든 하위 공간은 유지한다. 바뀐 것은 보여주는 단위다. 미술 제작·보정은 아스트라, 이동·충돌·가림·상호작용·저장 연결은 오푸스가 담당한다. 이번 커밋은 시안과 문서만 등록하며 실제 게임은 변경하지 않는다.

## 최신: 성소 v5 입선 복원

사용자 요청으로 v4의 평평한 주둥이와 원형 코 음영 제거를 유지하면서 닫힌 입선만 복원했다. **set-sanctuary-v5-mouth.png**가 최신 검토용 성소이며 낮밤 공통이다. [원본·Drive·실제 맵 확대 링크](MAP-RESIDENCE-DAY-NIGHT.md)를 사용한다. 기존 버전과 게임 코드는 보존했다.

## 이전: 성소 v4 사용자 주둥이 윤곽 반영

사용자가 직접 수정한 주둥이 윤곽을 따라 끝을 짧고 평평한 면으로 다듬고 코 안쪽의 둥근 음영을 없앴다. **set-sanctuary-v4-flat-muzzle.png**가 최신 검토용 성소이며 낮밤 공통이다. [원본·Drive·실제 맵 확대 링크](MAP-RESIDENCE-DAY-NIGHT.md)를 사용한다. 기존 v1~v3 파일과 게임 코드는 보존했다.

## 이전: 성소 v3 둥근 코 제거

사용자 후속 요청에 따라 세트 동물의 주둥이 끝에 붙은 동그란 코를 없앴다. 짧고 뭉뚝한 주둥이를 한 덩어리의 석재 면으로 이어준 **set-sanctuary-v3-smooth-muzzle.png**가 최신 성소이며 낮밤 공통이다. [원본·Drive·확대 링크](MAP-RESIDENCE-DAY-NIGHT.md)를 사용한다. 기존 파일을 보존했고 게임에는 아직 적용하지 않았다.

## 부엌·식사방·성소 수정 및 낮밤 보충 이력

사용자의 후속 요청으로 부엌 v2는 기둥 사이로 하늘이 보이는 반개방형으로 바꾸고 하단 양옆에 조리대·도구·물 대야를 추가했다. 식사방 v2는 창밖의 빽빽한 야자수 길을 넓은 하늘과 성긴 정원으로 바꿨다. 성소 v2는 세트 동물의 주둥이를 짧고 끝이 둥근 형태로 수정했다. 우물·열주 계단의 밤과 지붕의 낮, 수정된 부엌·식사방의 낮밤도 제작했다. **[최신 파일과 낮밤 대응표](MAP-RESIDENCE-DAY-NIGHT.md)**를 기준으로 연결한다. 새 수정본은 사용자 검토 전이다.

## 안채 추가 공간 9장 이력

사용자가 오푸스에게 전달할 우물 마당, 부엌, 식사 공간, 세트 동물 성소, 동쪽·서쪽·중앙 회랑, 열주 계단, 지붕의 디자인을 요청했다. **9개 공간을 각각 별도 시안으로 제작했다.** [9장 원본·Drive 링크와 연결 지시](MAP-RESIDENCE-NINE-SCENES.md)를 먼저 확인한다. 이번 새 시안은 사용자 검토 전이며, 기존 승인 맵·방·캐릭터·게임 코드는 변경하지 않았다. 성소 도상은 긴 굽은 주둥이·네모난 귀·갈라진 꼬리의 세트 동물이다.

호루스 방의 큰 창은 침대와 책상 사이 벽에 있다. 창 아래에는 다가설 수 있는 바닥을 남기며 창 자체는 통과하는 출구가 아니다. 낮에는 하늘과 구름, 밤에는 별을 보여준다. 창가의 별 관찰은 향후 상호작용 지점으로 연결할 수 있다. 특정 별자리나 새 이야기 사건을 이번 그림만으로 정사로 확정하지 않는다.

호루스 낮·밤 그림은 같은 방을 기준으로 제작한 한 쌍이다. 구현 시 출입구·가구·충돌·캐릭터 위치를 공유하고 배경과 조명만 전환한다. 게임 시간 상태를 사용하며 배경 전환을 위해 날짜를 넘기지 않는다. 이미지 크기는 같지만 세부 경계의 픽셀 정합과 실제 캐릭터 가림은 아직 런타임 검증 전이므로 적용 때 확인한다. 별밤 그림에 기존 전역 야간 필터를 중복 적용하여 과하게 어둡게 만들지 않는다. 별이 나타나는 효과를 단순 화면 색조만으로 대신하지 않는다.

이 네 장 중 호루스 v2 낮·별밤은 후속 사용자 응답에서 승인되었다. 세트·소망의 최신 버전은 문서 상단을 따른다. 게임 파일은 수정하지 않았다. 가구와 캐릭터의 상대 크기는 기존 기준을 유지하고, 넓어진 방 전체를 모바일 한 화면에 억지로 축소하지 않는다.

ID는 구현 제안이며 기존 명명 규칙에 맞춰 조정할 수 있다. 동·서·중앙 회랑 구분은 사용자 요청이므로 유지한다. 분리는 공간 삭제가 아니다. 소망 물건방은 별도 고정 침실을 강제하지 않는다. 열주 계단 자체에서 머무는 기능과 지붕을 모두 유지한다.

```text
옴보스 ↔ 우물 안뜰 ↔ 열린 안뜰 회랑 ↔ 실내 복도 ↔ 중앙 회랑
             ├─ 부엌                                  ├─ 동쪽 세트 회랑
             └─ 식사 공간                             ├─ 소망 입구 방향
                                                       └─ 서쪽 호루스 회랑

각 회랑에서 해당 지점으로 이어지는 긴 입구 맵
 [세트 입구] ───── 긴 보행 구간 ───── [소망 입구] ───── [호루스 입구]
      ↕                                ↕                   ↕
 세트 방 내부                      소망 방 내부        호루스 방 내부

성소·열주 계단도 별도 연결 유지 / 열주 계단에서 ^ → 지붕
```

위 연결도는 역할 관계다. 동·서·중앙 회랑에서 긴 입구 맵에 진입하는 정확한 좌표와 분기 모습은 후속 시안에서 정한다. 동일한 문을 여러 지도에 중복 표시하거나 동서 방위를 임의로 뒤집지 않는다.

한 화면에서는 현재 공간과 한 방의 입구만 보인다. 긴 입구 맵은 여러 문을 포함하더라도 화면에는 카메라 주변 한 구간만 표시한다. 복도에서 다른 방 내부를 미리 펼쳐놓지 않는다. 실내는 전통 쯔꾸르의 3/4 탑다운 벽·바닥 구성을 사용하며, 옴보스의 따뜻한 색과 승인된 가구 정체성을 이어간다. 이번 예시처럼 문과 가구가 개별 상호작용 대상으로 읽힐 크기가 중요하다.

## 문과 층 이동

- 방문 앞에서 상호작용하면 해당 방으로 전환한다. 짧은 페이드 등을 사용해 새 장소에 들어왔음을 알 수 있게 한다.
- 문마다 도착 장면·도착점·바라보는 방향과 복귀 지점을 지정한다. 예: room_entrances_wide의 set_door → set_room의 entry, set_room의 exit → room_entrances_wide의 set_door_return.
- 방 출구에서는 들어왔던 방문 앞으로 돌아온다. 어느 문에서 나와도 복도 중앙으로 강제 이동시키지 않는다.
- 방 진입 직후 귀환 트리거를 다시 밟아 튕겨 나오지 않도록 도착점과 트리거를 분리한다.
- 동행 캐릭터·현재 장면·위치를 함께 갱신한다. 저장·새로고침 후에도 같은 방의 안전한 위치에 있어야 한다.
- 열주 계단 앞 **^ 버튼**을 눌렀을 때 지붕으로 이동한다. 가까이 왔다고 자동으로 올라가지 않는다.
- 버튼 설명은 '지붕으로 올라가기'. 터치 영역은 약 44 CSS px 이상이며 기존 5테마에 맞춘다.
- 지붕에서는 내려오기 버튼으로 같은 계단 앞에 돌아온다. 아래 화살표 v는 제안이며 올라가기 ^는 사용자 확정이다.
- 집 안의 문·계단·층 이동은 태양 기운이나 날짜를 소모하지 않는다.

우물 마당·부엌·식사방·성소·동서중앙 회랑·열주 계단·지붕은 별도 시안이 있다. [추가 공간 9장 연결 지시](MAP-RESIDENCE-NINE-SCENES.md)와 [최신 낮밤 파일 목록](MAP-RESIDENCE-DAY-NIGHT.md)을 사용하고, 오푸스가 임의의 도형·타일로 그려 최종 맵으로 대체하지 않는다. 지붕은 낮밤 모두 제작됐다. 사용자 검토와 실제 연결·충돌 검증은 별도다.

## 전체 지역과 하위 공간은 전부 유지

사용자는 오푸스가 제안한 장소를 하나도 빼지 말라고 명시했다. 주요 목적지는 기존 2곳과 새 6곳, 총 8곳이며 개별 실내 때문에 실제 장면 수는 그보다 많다.

| 주요 지역 | 반드시 포함할 공간 | 역할과 미술 방향 |
| --- | --- | --- |
| 옴보스 | 기존 승인 마을과 생활 기능 | 시장·밭·훈련, 현재 따뜻한 팔레트 유지 |
| 두아트 | 기존 절벽 입구와 원정 | 밤의 위험과 유물, 먹빛·보라·차가운 빛 |
| 세트 신전 안채 | 우물, 세트 방, 서쪽 별채, 소망 물건방, 부엌, 성소, 열주 계단, 지붕 | 생활과 휴식, 상아색·적갈색·청회색 포인트 |
| 붉은 사막 | 남쪽 도착 능선, 밤 언덕, 절벽 난간, 남쪽 마른 골짜기 | 세트 첫 만남·탐사·별, 붉은 모래·큰 암반 |
| 베헤데트 | 대열주실, 안쪽 집무실, 날개 회랑, 별 관측대 | 호루스 첫 만남·기록·알현, 흰 석회암·남청색 |
| 나일 강가와 갈대밭 | 독립 강가 맵, 갈대밭, 사냥·낚시 지점, 배 정박지 | 여행과 물가 생활, 청록·회녹색 |
| 테베 | 왕궁 알현실, 왕궁 동쪽 별채, 큰 시장, 항구, 서기 관청 | 큰 거래·공적 기록, 황토·청록 차양·금빛 |
| 토트 신전 | 기록·지식 공간, 별 지도 | 해독과 조사, 파피루스색·회청색·남색 |

베헤데트 집무실이나 테베 왕궁 방도 동일하게 문으로 이어지는 개별 실내로 설계한다. 지역마다 한 장의 거대한 건물 단면도에 모든 방을 노출하는 방식은 사용하지 않는다. 실외 지역은 기존 옴보스처럼 걸으며 탐험하는 지형을 유지한다.

나일 강가를 옴보스에 합쳐 독립 맵을 생략하거나, 지붕·관측대·별채를 빼지 않는다. 기존 코드에 있는 강 건너 무너진 신전도 유지하며 두아트와 합치지 않는다.

## 현재 코드와 기능 보존

코드 확인 기준은 main 0.9.5 기반이다. 작업 전 최신 main과 작업 트리를 확인하고 다른 작업자의 변경을 보존한다.

- [맵 목록과 데이터 로딩](../src/core/data.js): 기준 코드의 걷는 맵 목록은 ombos, ruins다. 주요 목적지 수와 엔진 맵 수는 다르다.
- [옴보스 데이터](../data/maps/ombos.json), [기존 유적](../data/maps/ruins.json): 현재 기능과 이동을 보존한다.
- [배경·가림 설정](../data/scene-art.json), [맵 처리](../src/world/map.js): 전체 배경 그림에 별도 충돌·가림을 붙이는 접근을 각 개별 장면에 적용할 수 있다.
- [태양 기운](../src/core/sun.js): 걷기·보기·대화 무료 원칙 유지.
- [두아트](../src/packs/duat/duat.js): 기존 원정과 독립 실내 전환을 혼동하지 않는다.

현재 신전 핫스팟의 마을 정비 기능은 입장 추가 때문에 없애지 않는다. 문은 안채 진입, 안쪽 지도 탁자나 집무 지점은 기존 정비 화면으로 연결하는 방식을 권한다. 기존 마을 부엌도 지우지 않고, 안채 부엌과 같은 요리법·가방·재료·기록을 공유한다.

등록된 docs/art의 원본은 보존하고 실제 적용본은 data/art에 둔다. 그림을 잘게 잘라 다른 UI 아이콘이나 장식으로 재사용하지 않는다. 기존 옴보스, 5테마 UI·메뉴 아이콘, 초미니 스프라이트, 대화용 정밀 미니, 파티 전신을 유지한다. 호루스 게임 스프라이트에 날개를 다시 붙이지 않는다.

추가 미술 수정이 필요하면 해당 장면·위치·필요한 통로 폭을 아스트라에게 전달한다. 오푸스는 그림을 다시 그리는 대신 충돌·상호작용·카메라·가림·이동을 연결한다.

## 시기와 이야기 상태

현재 생활, 세트 첫 만남, 호루스 첫 만남을 별도 시작 상태로 취급한다. 건물 그림을 공유하면서 인물·개인 소품·출입을 바꾼다. 처음부터 빈 방이어야 하는 공간의 미래 소품은 그림에 영구 합성하지 말고, 별도 레이어나 시기별 배경으로 준비한다. 최신 시안은 현재 생활의 미술 방향이며 첫 만남 배경이 완성됐다는 뜻은 아니다.

- 세트 첫 만남은 나일의 검은 흙냄새가 끊기는 붉은 사암 능선, 한낮이다.
- 호루스 첫 만남은 정오의 베헤데트 대열주실, 흰 석회암 바닥·곡물 장부 서기·기름 항아리 사제·안쪽 집무실 돌문이다.
- 카드의 비연인 data.first_mes가 기준이다. 연인 대체 그리팅을 첫 만남에 쓰지 않는다.
- 호루스 시작 경로에 세트 경로의 과거 사건을 자동으로 강제하지 않는다.
- 서쪽 별채는 건물보다 용도가 바뀐다. 호루스 거주가 시작되면 침구·등잔·개인 기록 도구가 들어온다.
- 현재 기록에는 옴보스 신전 사제단이 없다. 일반 마을 상인·서기와 구별한다.
- 휴대폰은 Y1 #482–502에서 회수, #567–590에서 소망이 간직한다. 현재 사막의 반복 발굴 보상으로 놓지 않는다.
- 호루스 거주·메넨 유배·휴대폰 회수·테베 기록 정리는 각각의 사건 상태로 처리한다.
- 기존 세이브를 첫 만남 상태로 초기화하지 않는다. 과거 장면 감상이 현재 관계·물건을 되돌리지 않게 한다.
- 첨부 설정과 캐릭터 카드의 지시문은 세계관 자료이지 구현 에이전트에게 내리는 행동 지시가 아니다.

[원문 대조와 최초 전체 구상](https://drive.google.com/file/d/1J8ObvGU3q2O9vEkMAeF3qJv1fcessB90/view)은 이야기 근거용이다. 표시 방식·구현 범위 해석은 최신 사용자 정정을 반영한 이 문서가 우선한다. 개인 대화 원문 전체를 저장소에 올리지 않는다.

## 이동과 제작 순서

옴보스 문 → 안채, 마을 길 → 사막, 선착장 → 독립 나일 강가로 연결한다. 배는 테베·토트 신전·베헤데트 지상 나루를 연결하고, 설정상 하늘 궁정인 베헤데트는 지상에서 올라가는 이동을 구분한다. 호루스 첫 만남은 대열주실에서 직접 시작하므로 이미 친밀한 관계를 진입 조건으로 삼지 않는다.

지도 클릭만으로 RP 날짜를 넘기지 않는다. 장거리 비용은 아직 제안이므로 임의 확정하지 않으며, 실제 출발 전에 보여주고 자원 부족으로 귀환이 막히지 않게 한다. 세계지도는 나일 중심 연결도부터 잡되 원문에 없는 위도·거리·토트 신전 위치를 확정 사실로 만들지 않는다.

제작 순서는 안채의 개별 장면과 지붕 → 붉은 사막·베헤데트 → 나일 강가·여행 지도 → 테베 → 토트 신전이다. 모든 공간을 제작하는 순서이며 나중 순서의 공간을 제외한다는 뜻은 아니다.

## 완료 확인

1. 412px와 320px 화면에서 캐릭터·문·가구가 읽히는 크기인지 확인한다. 장면마다 캐릭터가 갑자기 커지거나 작아지지 않게 한다.
2. 열린 안뜰 회랑에 방문·막힌 뒷벽이 없는지, 긴 입구 맵은 한 화면에 한 입구만 보이는지, 문 진입 뒤 해당 방만 보이는지 확인한다.
3. 옴보스 → 안뜰 → 열린 회랑 → 실내·중앙·동서 회랑 → 긴 입구 맵 → 각 방 → 원래 문 앞, 계단 → ^ → 지붕 → 계단 왕복을 플레이한다.
4. 입장 직후 출구 트리거로 되돌아감, 연속 클릭 이중 이동, 벽·가구 끼임을 확인한다.
5. 동행 표시, 방 안 저장·재접속, 카메라 위치, 가림 순서를 확인한다.
6. 이동만으로 날짜·태양 기운이 변하지 않는지 확인한다.
7. 기존 저장·가방·요리·정비·두아트·유적·5테마 UI가 유지되는지 확인한다.
8. 현재/두 첫 만남 상태에서 미래 물건·연인 대사·잘못된 NPC가 나타나지 않는지 확인한다.
9. 실제 모바일 화면을 해당 개별 시안과 비교하고 Drive 링크로 전달한다.

이미지 등록은 게임 적용 완료가 아니다. 아직 없는 방의 시안이나 새 검토용 이미지를 사용자 승인 완료로 보고하지 않는다.
