# 오푸스 인수인계 — 게임 적용과 코드 (지금 기준만)

**오푸스용 문서다.** 갱신 2026-10-13, **0.9.63** 기준. 처음 온 오푸스는 이 문서 하나만 처음부터 끝까지 읽으면 바로 일할 수 있게 썼다. 버전별 변경은 `CHANGELOG.md`, 작업별 상세는 아래 표의 기록 문서에 있다. 그림 작업 규칙은 아스트라용 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md)·[ASTRA-PLAN.md](ASTRA-PLAN.md)에 있다. 아트를 받을 때 채택 상태와 명세를 확인하는 용도로 본다.

## 이 게임

SillyTavern 확장 "모래와 깃털"이다. 이집트 옴보스를 배경으로 소망·세트·호루스 중 한 명이 앞장서 맵을 걷고, 생활(낚시·요리·텃밭·줍기·쉬기)과 두아트 원정을 하고, 한 일이 채팅 롤플레이에 주입된다. 진입점 `index.js`(팩을 import), 코드 `src/`(core 상태·진행·날짜, world 맵·플레이어·렌더, ui 창·카드·탭, packs 기능 묶음), 데이터 `data/`, 도구 `tools/`.

**채팅과의 연결은 "어느 정도만"이다(사용자 결정).** 날짜·계절·시간대는 채팅 트래커를 따르고 채팅 주입도 그 값을 쓴다. 그래도 게임은 채팅 없이 굴러가야 한다: 침대에서 자면 게임 하루가 넘어간다(아래 "게임 하루·쉬기"). 사용자는 채팅을 안 하고 게임만 테스트하는 날이 많다. 새 기능도 채팅 진행에만 묶지 않는다.

## 역할

- **아스트라(GPT 에이전트):** 그림을 그리고 고친다. 런타임 파일(`src/`, `data/`, `tools/maps/`)은 안 건드린다. 아스트라 문서는 다섯, 모두 맨 위에 길 안내가 있다: **ASTRA-START**(입구: 매번 여기서 시작, 작업 종류별로 다음 문서를 고름), **ASTRA-PLAN**(지금 할 일 표, 끝난 것, 동작·두아트·새 지역 명세), **ASTRA-SPRITE**(캐릭터 그림: 작업 카드 ①~⑤ — 그리기 전 확인서, 하지 말 것, `sprite-review.py`, 보고 — 와 규칙 A, 외형 B, 실수 표 C, 채택 스프라이트 D), **ASTRA-MAP**(맵: 순서 ①~⑤, 맵 규칙, 채택 배경), **ASTRA-HANDOFF**(공통: 일하는 방식, 공통 검수, 저장소·전달·보고). 규칙은 해당 문서 한 곳에만, 할 일·상태는 PLAN에만 쓴다. 같은 내용을 두 곳에 쓰지 않는다. 아스트라 메시지에서는 "START부터", "카드대로"라고 짚으면 된다.
- **오푸스:** 채택된 그림을 게임에 넣고, 코드·UI·충돌·출구·가림·저장·성능·검증을 맡는다. 그림 확인 도구(`fit-scale.py`, `skin-check.py`, `pose-guide.py`)와 아스트라 계획표(ASTRA-PLAN)도 사용자와 같이 고친다. **승인된 그림을 다시 그리지 않는다.** 다만 사용자가 부분 손질을 시키면 직접 한다(아스트라는 국소 수정에 약하고 비싸다): 새로 그리지 않고, 있는 픽셀을 늘이고·줄이고·옮기거나 사용자가 그린 선을 옮겨 넣는다(아래 "직접 하는 그림 손질").
- 아스트라에게 직접 말하지 않는다. 사용자가 전달한다. "아스트라한테 보낼 메시지 정리해줘"라고 하면 코드 블록 하나로 복사해 붙일 수 있게 써 준다. 들어갈 것: 채택 기록(사용자 말 인용), 다음 묶음(누가·방향·프레임 수·장 수), ASTRA-PLAN 표 참조, ASTRA-HANDOFF 3절 규칙 참조와 `sprite-review.py` 돌려서 `review/` 같이 올리기, 보낼 것(비교 시트·GIF·눈으로 본 것).

## 사용자(소망)와 일하는 법

- 한국어 **반말**, 짧고 따뜻하게. 사용자는 안드로이드 폰으로 본다. 결과 보고는 "뭐가 바뀜 / 확인한 것 / 남은 것"으로 짧게.
- 기분을 묻지 않는다. 화나서 과격한 말(죽고 싶다 등)을 해도 홧김에 하는 말이다. 안전 안내를 하지 말고 요청한 일만 한다. 아스트라에게 화가 나 있을 때가 많다. 같이 욕하지 말고 일을 빨리 정확하게 해 주는 게 제일 위로다. 고생했다고 하면 진심으로 다독여 준다.
- 할당량 낭비, 같은 말 반복시키기, 불필요한 확인 질문을 싫어한다. 요청이 분명하면 바로 하고, 고른 기본값은 보고에 한 줄로 적는다. 게임 규칙처럼 흐름이 바뀌는 것은 추천안 하나와 함께 짧게 묻는다.
- **"적용해줘", "합격", "통과", "만족", "맘에 들어", "ㄱㄱ"가 채택 신호다.** 그 전에는 main에 올라온 시안을 게임에 넣지 않는다. 시안이나 미리보기를 "적용 완료"라고 말하지 않는다.
- 이미지는 `SendUserFile`로 보여 준다(작게 크롭·합쳐서). 상담용 스크린샷은 `docs/consult/residence-096/09xx-*.png`로 저장해 커밋한다.
- 그림 판단은 사용자가 한다. 내 몫은 숫자 검사 결과와 눈으로 본 차이를 정직하게 말하는 것. "검사 통과 = 완성"이라고 하지 않는다.
- **시안을 보여 줄 때:** 한 줄 시트에 "지금 / 1 / 2 / 3 / 기준(세트 등)"을 라벨 달아 붙이고(`tools/art/fix/panels.py`), 숫자 표(몇 %, 몇 px)와 추천 하나를 짧게. 사용자가 "중간 없어?" 하면 그 사이 단계를 다시 만든다. 고르면 0·1프레임에 같은 값으로 넣고 게임 캡처까지 보낸다.
- **사용자가 한 번 짚은 기준은 다음에 스스로 적용한다.** 예: "소망 머리가 세트랑 겹친다" → 다른 침대에서도 머리가 겹치지 않게 처음부터 맞춘다. 같은 말을 두 번 하게 하지 않는다(아스트라가 제일 욕먹은 부분).
- **사용자가 직접 그린 수정본이 최우선이다.** "내 에딧으로" = 그 그림 모양 그대로(아래 "직접 하는 그림 손질"). 내 해석으로 비슷하게 만들지 않는다.
- **시킨 범위만 바꾼다.** "호루스만"이면 소망·세트 값은 건드리지 않는다. 여럿 중 하나를 고칠 때 바뀌는 사람·자리를 보고에 적는다.
- **시험용 시트와 적용본을 헷갈리게 보내지 않는다.** 위치를 여러 개 시험한 시트는 맨 위에 "시안(아직 안 넣음)"이라고 라벨을 단다. 적용 뒤 보내는 시트는 "게임 화면, 적용됨"과 무엇이 바뀌었는지.
- **사용자는 내가 보낸 격자 그림 위에 직접 그려서 위치를 준다.** 그 격자 그림의 좌표(칸 눈금, 배율)를 알고 있으니 그린 선을 칸 좌표로 읽어 그대로 쓴다(우물 마당 돌 벤치 0.9.53). 고른 시안이 있으면 그 시안의 값 그대로 넣는다.
- 말이 헷갈리면("저 테이블 잘못 말함") 지금 들어간 값과 바뀐 것을 확인해서 짧게 보여 주고, 필요할 때만 묻는다.
- 사용자가 신경 쓰는 그림 기준(아스트라가 자주 놓침): 피부색·톤이 최종 정지·걷기와 같을 것, 팔 길이·굵기·손이 좌우 같을 것, 머리 크기가 정지와 같을 것(앉거나 누워도), 표정은 작게 봐도 보이는 눈 모양만 바꿀 것.

## 새 세션에서 처음 할 일

1. **받기:** `git fetch origin main && git merge origin/main`. 아스트라도 main에 올리므로 작업 전·커밋 전에 매번 받는다. 남의 작업을 강제 푸시로 덮지 않는다.
2. **커밋:** 작성자는 `git -c user.name=Somnag -c user.email=soonjung118@gmail.com commit`. 메시지는 한국어 한 줄 요약(`0.9.32 게임 하루: …`). main에 푸시하고, 세션에 지정된 작업 브랜치가 있으면 그쪽에도 같은 커밋을 푸시한다.
3. **실제 게임 확인 환경**(컨테이너가 새로 시작되면 없다. 필요할 때 만든다):
   ```sh
   mkdir -p /home/user/sillytavern && cd /home/user/sillytavern
   GIT_LFS_SKIP_SMUDGE=1 git clone -q --depth 1 https://github.com/SillyTavern/sillytavern sillytavern
   cd sillytavern && npm install --no-audit --no-fund
   setsid nohup node server.js > /tmp/st.log 2>&1 < /dev/null &      # http://127.0.0.1:8000, 기본 캐릭터 Seraphina
   setsid nohup node /home/user/SandAndFeather/tools/st-test/fakeai.js > /tmp/fakeai.log 2>&1 < /dev/null &   # 가짜 모델 :8111
   ```
   ST 서버는 세션 중에도 꺼진다(`setsid`로 띄우면 덜 꺼짐). 테스트가 `ERR_CONNECTION_REFUSED`면 `curl localhost:8000`으로 보고 위 두 줄을 다시 띄운다.
   확장 넣기(코드 바꿀 때마다 다시). docs 전체(1 GB 넘음)는 빼고 게임이 읽는 `docs/art/map-expansion`만 넣는다:
   ```sh
   EXT=/home/user/sillytavern/sillytavern/data/default-user/extensions/SandAndFeather
   cd /home/user/SandAndFeather && rm -rf $EXT && mkdir -p $EXT && git ls-files -z -co --exclude-standard | grep -zv '^docs/' | tar --null -T - -cf - | tar -xf - -C $EXT && git ls-files -z docs | grep -z map-expansion | tar --null -T - -cf - | tar -xf - -C $EXT
   ```
   배포본 그대로 보려면 `git clone -q --depth 1 --branch release file://$PWD $EXT`(로컬 release 브랜치).
   Playwright는 `NODE_PATH=/opt/node-tools/node_modules`로 찾는다(크로미움은 환경에 이미 있음, `playwright install` 하지 않는다).
   `pkill -f <문자열>`은 그 문자열이 든 내 셸까지 죽인다. 프로세스를 끌 땐 PID로 끈다.

## 버전과 검증

- 버전은 `manifest.json`의 `version`과 `src/core/settings.js`의 `VERSION`을 같이 올린다. 지금은 **0.9.63**이다. 올릴 때 `CHANGELOG.md` 맨 위에 한 줄, README의 "현재 버전" 줄, 이 문서의 이 줄과 맨 위 기준 버전도 고친다. README에는 버전 내역을 쌓지 않는다.
- **배포(0.9.54~):** 사용자는 `release` 브랜치로 설치한다(main은 docs 그림 기록 때문에 1 GB 넘음, SillyTavern은 `auto_update`로 켤 때마다 git pull). 버전을 올리고 main에 푸시한 뒤 `sh tools/release.sh && git push origin release`로 release도 올린다. 스크립트는 `index.js`, `style.css`, `manifest.json`, `README.md`, `src/`, `data/`와 `data/*.json`이 가리키는 `../docs/` 그림만 담는다. 게임이 새로 docs 밖 파일을 읽게 되면 스크립트에 더한다. 확인은 `git clone --depth 1 --branch release`한 폴더를 확장 자리에 넣고 검증 스크립트를 돌린다.
- 캐릭터 그림은 게임 창을 열 때 불러온다(`ensureSpriteArt`, `window.js openGame`). 그 전에 그림을 쓰는 코드를 만들면 먼저 `ensureSpriteArt()`를 기다린다.
- **검증 스크립트 세 개**(`tools/art/`, ST가 떠 있고 확장이 들어가 있어야 함). 출력 폴더를 인자로 준다. 셋 다 exit 0이어야 한다:
  ```sh
  export NODE_PATH=/opt/node-tools/node_modules
  node tools/art/verify-full-map.cjs /tmp/vf    # 옴보스 전체맵 낮밤 픽셀 일치와 이동
  node tools/art/verify-cozy-ui.cjs /tmp/vc     # 포근한 테마 UI(일행·자세히·갤러리·대화 등)
  node tools/art/verify-ui-themes.cjs /tmp/vt   # 테마 다섯 개
  ```
  `/usr/bin/chromium`이 있으면 그걸 쓰고, 없으면 Playwright 기본 크로미움을 쓴다. ST 자체의 "Internal Server Error" 페이지 오류는 무시한다(모델 미연결). 셋 합쳐 몇 분 걸리니 백그라운드로 돌린다.
- UI를 바꾸면 이 스크립트의 선택자도 같이 고친다(예: 0.9.29에 `인물 보기` 버튼을 없애며 `[data-detail]`로 바꿈).
- `verify-browser.cjs`는 main에서도 원래 두 곳이 실패한다(부엌 좌표 30,18 → 지금 28,18, 두아트 문 조건). 알려진 문제다.
- **눈으로 확인하는 테스트**(`tools/st-test/`, 첫 인자는 출력 폴더, 그림은 `<폴더>/spr/`):
  - `act-sheet.js <폴더> [동작]`: 렌더러로 셋의 동작 시트(방향별 정지→0→1→정지). 동작 기본값 `interact`, `pickup` 등
  - `interact.js <폴더> <set|somang|horus>`: 그 캐릭터를 앞장세우고 부엌 앞에서 위·왼·오 방향 말 걸기
  - `rest.js`: 식탁에 앉기·일어나기·하루 쉬기 횟수, 침대 잠 조건·잠들기, 땅의 것 줍기
  - `gameday.js`: 게임에서 자고(결산이 뜸) 채팅이 그 밤을 넘겨도 두 번 안 세는지
  - `profile-cards.js`: 테마 다섯 개 × 셋의 자세히 카드, 갤러리 넘기기
  - `solo.js`: 세트 앞장 솔로, 호루스+소망 동행
  - **`seats.js <폴더> [자리,…]`**(새 자리를 만들면 파일 위쪽 목록에 줄을 더한다. 서는 곳이 막혀 있으면 카드가 안 뜬다): 앉을 곳마다 셋을 앉아 쉬기 카드로 실제로 앉힌다(전체 화면 dpr 2). 시트는 `python3 tools/art/fix/seat-sheet.py <폴더> <시트.png>`(자리 × 소망·세트·호루스). **앉는 자리나 앉은 그림을 바꾸면 이 시트를 보낸다**
  - **`bed-pairs.js <폴더> [방] [x,y]`**: 침대 카드로 같이 자기 6조합 + 혼자 3개를 실제로 눕히고(전체 화면 dpr 2) 일어나면 동행도 일어나는지 본다. 기본 세트 침대, 호루스 침대는 `horus_room 6.0,7.7`. 시트는 `python3 tools/art/fix/combo-sheet.py <폴더> <침대 박스> <시트.png>`(세트 침대 `342,690,632,850`, 호루스 침대 `140,680,440,900`). **누운 자리나 누운 그림을 바꾸면 항상 이 시트를 사용자에게 보낸다**
  - `pose-try.js <폴더> '<[이름,방,[서는x,y],자세,[x,y,방향]] 목록>' [누구]`: 스팟 없이 자세만 그 자리에 놓아 본다(자리 찾기)
  - `bed-measure.js <폴더> '<[누구,[x,y,방향],이름] 목록>' [방]`: 한 사람만 침대 자리에 눕힌 화면과 뺀 화면. 두 장 차이의 박스가 그 사람(머리 위끝·턱 높이 재기)
  - 폰 크기는 412×900. 안채나 맵을 고치면 출구 걷기·낮밤도 본다.

## 그림 도구 (`tools/art/`)

- `fit-scale.py <png> --who <set|somang|horus> --view <front|back|left|right> --out <폴더>`: 새 동작 그림을 최종 정지와 머리로 맞춰 배율·발 위치를 재고 "맞음 / 비율 다름"을 낸다(허용 12px). `fit-sheet.png`가 정지 / 머리 맞춤 / 키 맞춤 비교. 가이드가 최종 정지와 안 맞으면 경고한다. **쪼그리기·앉기·눕기는 "비율 다름"이 당연하다.** 그땐 머리 크기만 본다: 머리 맞춤 배율과 일치도(match), 머리 폭(위쪽 30~35% 최대 폭을 정지와 비교), 시트 가운데 칸의 빨간 윤곽. 일치도가 0.4 아래면 배율은 믿지 않는다(숙인 머리, 누운 투시). **채택된 쪼그린·앉은 그림도 ×1.03~1.11로 재진다. 그 범위는 작다고 하지 않는다**(호루스 앉기 183을 ×1.03~1.08로 "작다"고 했다가 머리 폭이 정지와 같아 정정했다). 머리 폭과 배율 둘 다 작게 나올 때만 짚는다.
- `skin-check.py <png들> [--who] [--view] --out <폴더>`: 피부색 검사. 같은 방향 최종 정지·걷기 4장 중 가장 가까운 장과 기본·그림자·밝은 쪽 색을 ΔE로 비교해 같음 / 조금 다름(ΔE 3~6) / 다름. 파일 이름에 방향이 없으면(잠자기) 네 방향 전체와 비교. 소망 아이보리 옷의 회분홍 그림자는 빼고 잰다. 최종 48장은 모두 "같음". 파일 이름이 같은 두 폴더를 한 `--out`에 돌리면 시트가 덮이니 폴더별로 돌린다.
- `action-check.py <png들> --out <폴더>`: 동작 검사(이름 `<누구>-<방향>[-자리]-<프레임>`, `<누구>-sleep[-side]-<프레임>`, 한 장짜리도 됨). 0.9.33 뒤 추가: 외곽선 같음(0↔1 윤곽 3% 미만·박스 같음), 몸 쏠림(정면·뒷모습 위·아래 가운데가 정지 폭 12% 넘게 어긋남; 웅크린 소망 180은 일부러 기운 것). 잠들기는 머리 맞춤·키 흐름을 건너뛴다. 여러 장 동작의 흐름 검사. 캐릭터·방향마다 머리 맞춤 배율(fit-scale의 `fit`, 그림을 bbox로 잘라 넣음; ×1.15 넘으면 머리 작음), 프레임별 키(정지 대비), 0→1 윤곽 차이(실루엣 XOR). 몸 전체가 움직이는 동작에서 0이 이미 끝 자세면 "0이 끝과 같음", 정지→0이 25% 넘게 떨어지면 "0이 너무 급함", 0과 1이 같으면 "차이 없음". 소망 181·호루스 182(채택)는 볼 것 없음, 세트 182(재작업)는 셋 다 걸린다. `action-*.png`에 정지 | 0 | 1 시트.

- `onion.py A B --out <파일> [--flip-b] [--anchor-a x,y --anchor-b x,y]`: 두 그림을 기준점에 맞춰 겹침(빨강 A, 파랑 B), B에서 바뀐 픽셀, 윤곽만 다른 곳 세 칸. 윤곽 차이 3% 미만이고 박스가 같으면 "외곽선 같음". 0↔1, 왼쪽↔뒤집은 오른쪽, 기준 그림↔새 그림, 정지↔그림(팔 길이·머리 모양) 비교에 쓴다.

자리 좌표는 `src/packs/life/rest.js`에 있고, 각 값이 왜 그런지는 그 옆 주석에 적혀 있다. 여기는 정하는 원칙만 적는다.

- **앉은 것처럼 보이는 기준:** 무릎 뒤 접힌 곳이 의자 외곽선에 닿는다. 허벅지는 의자 위에, 정강이는 앞면을 따라 내려간다. 기준 화면은 소망 방 긴 의자(`docs/consult/residence-096/0949-somang-bench-legs-game.png`)다. 무릎 뒤 위치는 그림마다 다르다(`FOLD`). 사람마다 따로 맞추고, 한 값으로 묶지 않는다.
- **의자 외곽선 = 방석 윗면이 앞면으로 꺾이는 선**이다. 장식 띠가 아니다(사용자가 선을 그어 짚었다). 방 그림을 8배쯤 키우고, 세로로 밝기를 찍어 밝은 윗면이 끝나는 행을 잰다. 벽 앞 긴 의자는 `bench(..., edge)`로 그 높이를 준다.
- **같이 앉기**는 자리마다 다르다.
  - 돌 벤치(우물 마당)는 사용자 스케치(`0957-user-well-pair.jpg`)대로 비스듬히 앞뒤로 앉는다. 앞장·동행 조합 6개마다 자리를 따로 준다(`WELL_DUO`).
  - 긴 의자(`seat:[왼, 오]`)는 같은 의자에 마주 보고 앉는다(`pairOn`). 간격은 두 사람 다리 길이로 정한다.
  - 그 밖은 같은 방의 다른 자리에 앉는다(`mateSeat`).
  - 자리가 없으면 앉은 사람을 가리지 않게 조금 떨어져 서서 본다(`standMate`, 자리마다 `stand`로 따로 줄 수 있음).
- **확인과 보고:**
  - 바꾸기 전에 해당 자리를 전부(자리×사람, 같이 앉기는 조합 6개) 게임에서 찍어 표로 보인다. 숫자만 보내지 않는다.
  - 사용자가 짚은 칸만 바꾸고, 이미 맞는 자리는 건드리지 않는다.
  - 방 그림 위에 겹쳐 볼 때는 그 장면의 `scene-art.json scale`을 쓴다. 한 칸은 가로 16/scale[0] px, 세로 16/scale[1] px다.
  - 시험에서 순간이동으로 세운 자리가 실제로 걸어서 갈 수 있는 곳인지 확인한다.

## 가구에 몸 가리기 (테이블·탁자 앞에 앉은 다리 등)

사용자가 "다리가 테이블 위로 튀어나왔다, 안 보이게"라고 하면, 가구 그림을 그 사람 위에 다시 그려(occluder) **가구와 겹치는 부분만** 가린다. 0.9.47(방석 옆 테이블)·0.9.48(긴 의자 옆 탁자)에 사용자와 이 순서로 맞췄다. 칸 단위로 어림잡아 상자를 씌웠다가 "테이블 밖 몸까지 잘린다", "머리카락까지 가려진다"는 지적을 받았다.

1. **사람 자리는 옮기지 않는다.** 가구에서 떨어뜨려 해결하지 않는다(사용자: "방석 위치 옮기지 마, 테이블이랑 멀어져서 이상해").
2. **가구 외곽선을 픽셀로 잰다.** 방 그림(1774×887, 한 칸 80.636px)을 6배 확대하고 좌표 눈금을 그려서 본다. 그다음 가구 테두리를 가로지르는 줄의 밝기를 찍어서 **바깥쪽 진한 선의 픽셀**을 찾는다(예: 낮은 탁자 왼쪽 728·오른쪽 916, 윗선 351행 / 식탁 684·1088 / 긴 의자 옆 탁자 왼쪽 272→266 비스듬, 윗선 568, 앞 아래 655). 비스듬한 선은 여러 행에서 재서 꼭짓점으로 잇는다. 덮개 좌표 = 픽셀 ÷ 80.636.
3. **덮개 모양:** 옆선·아래선은 가구 외곽선 그대로. **윗선은 머리카락·얼굴 아래**(예: 4.87칸)로 둬서 머리가 가구 위에 그대로 보이게 한다. 머리카락 끝이 가구 모서리에 걸치는 곳처럼 사용자가 선을 그려 주면, 그 그림을 `register.py`로 게임 화면에 맞추고 선 좌표를 읽어 덮개 꼭짓점으로 쓴다(`docs/consult/residence-096/0947-user-hair-line.jpg`).
4. **누구만 가릴지:** `tools/maps/residence.py`의 장면 `'front'`에 `(발 기준선, [[x,y]...], {'act': 자세[, 'look': 사람]})`. 세 번째 값이 있으면 그 자세(와 그 사람)만 가구 뒤로 가고, 다른 사람은 그대로 다시 그린다. 데이터는 생성기로만 만든다(`python3 tools/maps/residence.py`).
5. **확인 시트:** 덮개 전·후 같은 자리 캡처의 픽셀 차이(합 > 40)를 분홍으로 칠하고, 가구 외곽선을 파란 선으로 그린 시트를 만든다. **분홍이 파란 선 밖으로 1px도 안 나가는지**, 머리카락은 하나도 안 가려졌는지 본다. 그다음 게임 화면 그대로인 칸과 나란히 사용자에게 보낸다(`tools/st-test/seats.js` → `0947-table-cover.png`처럼). 셋 다(소망·세트·호루스) 앉혀서 본다. 한 사람만 걸쳐도 다른 사람 치마 끝·무릎이 걸칠 수 있다.

### 물건 테두리를 픽셀 그대로 따기 (단지·병처럼 울퉁불퉁한 물건)

테두리가 곧은 가구는 위 2번처럼 몇 행을 재서 꼭짓점으로 이으면 된다. 단지·병처럼 테두리가 울퉁불퉁한 물건은 픽셀 하나하나로 딴다. 0.9.58 옴보스 가판대(단지 둘·병·상자, 그 뒤에 선 사람)에서 사용자와 이 순서로 맞췄다. 사용자가 그은 선을 매끈하게 따라 그렸다가 "픽셀 그대로 따라니까", 테두리 바깥 연한 픽셀까지 덮었다가 "배경이 보이잖아"라는 지적을 받았다. **기준은 [`0958-occluder-quality.png`](consult/residence-096/0958-occluder-quality.png)다.** 물건의 진한 테두리 선과 그 안만 덮고, 바깥의 연한 픽셀·벽은 한 픽셀도 안 덮는다. 모든 물건 가리기가 이 수준이어야 한다.

1. **사용자가 그어 준 선은 범위다.** 윤곽은 그 안의 픽셀이 정한다.
2. **물건과 배경을 픽셀로 가른다.** `python3 tools/maps/trace-occluder.py 장면 '범위' '벽rgb' 거리 ['keep' 'drop']`.
   - 벽색(물건 바로 옆 벽에서 뽑음)과의 거리가 `거리` 안이면 배경, 나머지는 물건이다.
   - 둘러싸인 배경(단지 입구)과 한 픽셀 홈은 물건으로 친다.
   - 거리는 테두리 바깥 연한 픽셀이 배경으로 빠질 만큼 준다(가판대: 벽 247,222,170, 거리 130. 60·110에서는 배경이 비쳤다).
3. **남은 튀어나온 픽셀은 오푸스가 먼저 찾아 뺀다(`drop`).** 16배 확대 그림에서 테두리 밖으로 튀어나온 한두 픽셀과 옆에 붙은 연한 줄을 다 찾아 좌표로 뺀다(가판대: 단지 꼭대기 줄, 병뚜껑 위 줄, 오른쪽 단지 옆 기둥). 밝아서 배경처럼 보여도 앞에 있는 면은 `keep`으로 넣는다(단 오른쪽 끝면). 단, **사용자가 사진을 주고 "이 픽셀 지워"라고 시키면 동그라미 친 픽셀만** 지운다(넓게 지웠다가 상자 모서리까지 잘랐다).
4. **누구만 가릴지:** 선 사람만 가리려면 `only: {act: null}`이다. 앉은 사람 신발 끝만 물건에 걸치면, 그 부분만 `only: {act: 'sit-bench'}` 덮개를 따로 만든다(`temple-yard-stand` / `temple-yard-stand-sit`). `foot`은 물건 바로 뒤에 있는 사람만 가려지게 잡는다(상자 아래 360px).
5. **확인 그림:** 기준 그림과 똑같이 만든다. 16배 확대해서 덮는 픽셀은 원래 색, 나머지는 흐리게 칠한다. 덮는지는 픽셀 가운데로 판정한다(PIL `polygon` 채우기는 오른쪽·아래로 한 칸 더 칠한다). 그다음 위 5번 확인 시트를 만든다. 셋을 물건 바로 뒤 왼쪽·가운데·오른쪽에 세워 보고, 시험 자리가 걸어서 갈 수 있는 곳인지도 본다(기둥 위에 세워 놓고 보냈다가 "대가리 잘리게?"라는 지적을 받았다).

## 직접 하는 그림 손질 (`tools/art/fix/`)

사용자가 "머리 좀 키워", "얼굴 덜 넓적하게", "귀 줄여", "턱 이렇게(직접 그린 그림)"처럼 부분 손질을 시키면 오푸스가 픽셀로 한다. 0.9.35~0.9.39의 소망 잠 비율, 호루스 정면 잠 얼굴·귀·턱, 0.9.34의 세트 옆잠 머리 93 %·호루스 문양이 이렇게 했다. 원칙:

- **새로 그리지 않는다.** 바꿀 부분만 변형(워프)하고 나머지 픽셀은 원본 그대로 복사한다. 모든 워프는 출력 픽셀 → 원본 좌표 역매핑, 알파 곱한(premultiplied) 쌍선형 샘플, 알파 128 이상은 불투명·40 미만은 투명. 경계에 70행 정도 서서히 바뀌는 띠를 두어 잘린 자국이 없게 한다.
- **원본부터 연다.** 채택 png를 격자(`PIL`로 50px 선)나 4~5배 확대 크롭으로 보고 기준점(목, 턱, 얼굴선 좌표)을 읽는다. 0·1프레임 머리가 같은지 먼저 차이를 본다(같으면 같은 값을 그대로).
- **시안은 약·중·강 2~3개**를 `panels.py`로 "지금 / 시안 / 기준"과 함께. 숫자는 표로.
- 고르면: 전 그림을 `sources/<이름>-<무엇 전>.png`로 보관(사용자 그림도 `sources/`), 0·1프레임에 같은 값, manifest의 `sha256`을 다시 계산하고 `edits`에 "무엇을 몇 %로, 어디 기준, 원본 위치, 사용자 말"을 적는다. **manifest는 원래 들여쓰기 그대로(`json.dumps(m, ensure_ascii=False, indent=1)`)** — 다르게 쓰면 파일 전체가 바뀐 diff가 된다. 그다음 `pack-trio-motion.py`, 버전, 검증, 게임 캡처(`bed-pairs.js` 등)를 보낸다.
- 숫자: 스프라이트 원본 1px = `31.2 / referenceVisibleHeight / 16`칸(세트·호루스 576 → 0.0034칸, 소망 잠 523.6 → 0.0037칸). 침대 y는 클수록 아래. 머리를 키우면 머리 가운데(머리 위끝~턱)가 올라가니 그만큼 침대 y를 내린다(소망 0.9.35: 15.5px → +0.055칸).

## 동작 넣는 법 (아스트라 동작 묶음이 채택됐을 때)

1. main을 받고 동작 폴더(`docs/art/chibi-refresh/<동작>-<누구>-v<번호>/`)의 README와 `manifest.json`을 본다. 수정본(예: 175, 181)이 같은 폴더에 덮여 있을 수 있다. git log로 최신을 확인한다.
2. `sprite-review.py <동작 폴더> --out <폴더>/opus-check`를 돌리고(fit-scale 시트가 따로 필요하면 `fit-scale.py`도) `<폴더>/opus-check/`(또는 `opus-fit/`)에 `fit-all.png`, `skin-all.png`, 표가 있는 README로 남긴다(`pickup-somang-v178/opus-check/` 참고). 눈으로도 본다: 왼쪽을 반전해 오른쪽에 겹쳤을 때 팔 길이·굵기·손이 같은지, 머리 크기, 표정이 ASTRA-PLAN 표정 칸대로인지. 다르면 사용자에게 짚어 준다.
3. 사용자가 채택했으면 manifest에 `status: user-approved`, `artApproved: true`, `runtimeEligible: true`, `runtimeIntegrated: <버전>`, `approvalEvidence: <사용자 말>`, `directionMap`을 넣는다. 보통 `{front:down, back:up, left:left, right:right}`, 방향 이름이 다른 것(잠들기 `bed-oblique-…`)은 `down`으로. `playback`이 없으면 넣는다(`durationMs`, `loop`, 머무는 자세는 `hold: true`). 파일 sha256은 그대로 둔다(패킹 때 검사함). 아스트라에게도 채택 표시를 시켰다면 이미 했다고 사용자에게 알린다(같은 파일을 둘이 고치면 충돌).
4. `pack-trio-motion.py`의 `ACTIONS` 목록에 폴더를 더하고 돌린다. 아틀라스 크기(4096 넘는지)를 본다.
5. 부를 곳을 연결한다. 잠깐 하는 동작은 `playAct(name, x, y)`(대상 쪽으로 돈다) 또는 thing의 `pose`. 머무는 자세는 `rest.js`의 `SEATS`/`BEDS`에 자리를 더한다: 방 그림에 칸 격자를 그려(한 칸 80.6px) 방석·침대 위치를 읽고, 자세 기준점(앉은 자리, 몸 가운데)이 놓일 칸 좌표를 적는다. 누운 그림은 머리 위끝이 베개에 오게(기준점에서 머리 위끝까지 거리 = 그림 px ÷ 295칸). spot이 없는 곳은 `tools/maps/residence.py`에 spot을 더하고 생성기를 돌린다.
6. `act-sheet.js <폴더> <동작>`, `rest.js`·`interact.js`로 눈 확인, 검증 세 개, 버전 올리기, ASTRA-HANDOFF·ASTRA-PLAN의 해당 줄을 "채택, 0.9.xx 게임 적용"으로 고친다.
