# 작화 시작표 — 새 그림·부분 수정·재시도마다 적용

이 문서는 실행 순서다. 상세 지침을 대체하거나 생략하지 않는다. 최신 사용자 지시가 우선하고, 그 범위 안에서 최신 채택 기준과 상세 지침을 따른다. 최신 생성 파일·업로드 파일을 채택본으로 추정하지 않는다.

## 1. 시작 전에

1. [현재 작업](ASTRA-DRAW-STATE.md)과 [START](ASTRA-START.md)를 읽는다. 컨텍스트 압축 뒤에는 완료 범위·반려 범위·다음 한 단계를 먼저 복구한다.
2. [PLAN](ASTRA-PLAN.md)의 해당 동작·캐릭터 표정 표, [SPRITE](ASTRA-SPRITE.md)의 작업 카드와 외형·실수 항목, [HANDOFF](ASTRA-HANDOFF.md)의 공통 검수를 실제로 읽는다. 첫 진입에는 관련 문서 전체를 읽고, 각 생성 전에는 해당 항목과 변경 사항을 다시 확인한다. 제목 검색만으로 읽었다고 기록하지 않는다.
3. 해당 캐릭터의 정면 및 필요한 좌우 정지·걷기, 색 표·눈 견본·머리 기준을 이미지로 연다. 같은 세션에서 이미 직접 본 이미지가 유효하면 재사용하되 파일 경로를 기록한다. 압축으로 시각 맥락이 사라졌거나 기준이 바뀌면 다시 연다.
4. 원본 전신 가이드와 동작에 맞춘 머리 가이드를 열고 위치·크기·각도를 확인한다. 실제 밑그림으로 사용한다. 참고 첨부만 하고 자유 작화한 것은 가이드 사용으로 기록하지 않는다. 도구상 구현하지 못했다면 그대로 미수행이라고 적고 방법을 바꾼다.
5. 아래 기록 양식의 생성 전 항목을 채운다. 이미 승인된 계획 안에서는 기록을 작업 폴더에 남기고 진행한다. 같은 계획을 매 프레임 재승인받지 않는다. 필요한 새 승인과 이미 받은 승인을 구분한다.

## 2. 생성 요청에 반드시 반영

- 외형 기준과 동세 참고의 역할을 분리한다. 현재 전투 재작화는 **원본 정지·걷기 = 외형·비율**, **기존 전투 그림 = 동세·표정 의도만**이다. 잠자기는 사용자가 허용한 보조 화풍 참고다.
- 머리/몸·팔다리·손발 비율, 얼굴·눈 형태, 피부·눈·옷·머리색, 외곽선 굵기, 명암 단계와 디테일 밀도를 원본에 맞춘다.
- 하이라이트는 채택 대기 수준의 큰 면과 적은 양. 갈래마다 잔빛줄기를 추가하지 않는다. 동작에 따라 조명·색을 바꾸지 않는다.
- 호루스는 승인된 짧고 두툼한 삐죽머리, 왼쪽 눈에는 문양 없음. 좌우는 캐릭터의 해부학적 좌우로 판단한다. 화면 좌우와 혼동하지 않고 원본의 보이는 볼로 확인한다. 중복 문양·흰 동공 반짝이·가슴천·긴 뒷머리를 추가하지 않는다.
- 자세와 표정은 PLAN의 해당 캐릭터·동작 칸 및 최신 사용자 수정대로 구체적으로 쓴다. 세트 고유 기술은 다문 입·집중한 눈빛·힘 있는 내려꽂기. 호루스 지침은 멍함도 탈진도 아닌 절제된 피로.
- 팔·손 개수와 관절, 의상, 승인 무기 디자인·길이·날카로움, 투명 여백과 기준점을 지정한다. 무기를 넣으려고 신체를 축소하거나 팔을 늘리지 않는다.
- 부분 수정은 수정 영역과 보존 영역을 명시한다. 요청 밖 변화가 생기면 수정 완료가 아니다.

## 3. 결과가 나오면 — 다음 그림 전에

1. 정지·걷기와 실제 캐릭터 배율을 맞춘 비교 PNG를 만들고 직접 연다. 칸 크기에 각 그림을 따로 맞춰 비율 차이를 숨기지 않는다. 캔버스 크기와 신체 크기를 혼동하지 않는다.
2. 얼굴·머리·손·문양·수정 경계를 확대해서 본다. 원본과 색·선·비율·의상·디테일을 대조한다.
3. 기존 대기 → 새 동작 → 대기 및 필요한 걷기 연결을 확인한다. 정지 화면과 게임 표시 크기, 밝은/어두운 배경을 확인한다.
4. SPRITE의 자동 검사를 실행하고 원본 결과를 보존한다. 측정 실패는 실패로 기록한다. 검사를 통과시키려고 수치를 꾸미거나 그림을 임의로 변형하지 않는다. 자동 통과는 시각적 합격을 뜻하지 않는다.
5. 불일치는 수정하고 다시 확인한다. 같은 부위가 반복 실패하면 해당 부위를 확대해 수정하는 방법으로 전환한다. 같은 반려가 두 번이면 원본·방법부터 재검토한다.
6. 비교 기록을 저장하고 현재 작업의 상태·다음 행동을 갱신한다. 사용자 채택 전에는 검토본이다. 확인하지 못한 항목은 미확인으로 남긴다.

## 4. 경로 입구

- 원본: `docs/art/chibi-refresh/final/<who>/idle/`, `walk/`
- 색·눈: `docs/art/chibi-refresh/palette/palette.md`, `eyes.png`
- 머리: `docs/art/chibi-refresh/notes/hair-reference.png`, 호루스는 `horus-hair-short.jpg`도 확인
- 전신 가이드: `docs/art/chibi-refresh/pose-guides/` 및 README
- 오푸스 도구: `tools/art/pose-guide.py`, `head-check.py`, `sprite-review.py`
- 현재 로컬 자료 묶음과 전투 출처: [현재 작업](ASTRA-DRAW-STATE.md)에 기록. 로컬 경로가 없으면 존재한다고 주장하지 않는다.

`head-check.py` 기본 머리 범위는 가시 영역 상단 45%다. 턱·귀까지 완전한 얼굴 마스크도, 자동 3/4 투시도 아니다. 전신 원본을 함께 보고 해당 동작에 맞춘 위치·각도를 별도로 설정한다.

## 5. 작화별 기록 양식

작업 폴더의 `review/<파일명>-draw-record.md`에 생성 전 항목부터 작성한다. 빈 양식을 완료 증거로 삼지 않는다. 생성 후 결과를 덧붙인다.

```text
상태: 준비 / 생성 / 검수 / 수정 필요 / 사용자 검토 / 채택 / 반려
대상: 캐릭터·방향·동작·프레임·출력 경로
사용자 지시와 승인 범위:
읽은 문서: 경로 + 해당 절 + 이번 동작의 표정/자세 요구
실제로 연 원본: 파일 경로 + 외형/동세/표정/보조 참고 역할
가이드: 파일 경로 + 생성 명령/좌표/각도/배율 + 실제 사용 방식
생성 요청: 전달한 참고 파일들과 실제 지시문 저장 경로
수정 범위 / 보존 범위:
캔버스 / 캐릭터 배율 / 기준점:
--- 생성 후 ---
출력 파일 / 버전 / 해시:
직접 연 비교 PNG / 확대 / 연결 GIF 경로:
외형·비율·선·색·머리 디테일:
표정·동세·손 개수·관절·의상·무기:
문양 위치·모양·개수:
밝은/어두운 경계 / 게임 크기 / 부분 수정 밖 변화:
자동 검사 명령·보고 경로·실패 또는 미확인:
발견한 차이와 재수정 결과:
사용자 채택 근거（未채택이면 검토본）:
다음 한 단계:
```
