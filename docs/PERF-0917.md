# 0.9.17 렉과 메모리 점검

사용자 제보: 오랜만에 업데이트했더니 느리다. 걷기가 느린 건지, 렉인지.

## 측정 방법

실제 SillyTavern에 412×900, 2배 화면을 띄웠다. CDP로 CPU를 4배 느리게 해서 폰을 흉내 냈다. 화살표 키로 실제로 걸으면서 초당 프레임, 느린 프레임, 실제 이동 속도(칸/초)를 쟀다. 원래 이동 속도는 4.2칸/초다. 메모리는 풀어 둔 그림의 가로×세로×4바이트를 더하고, JS 힙을 함께 봤다.

## 원인

1. **옴보스 그리기:** 매 프레임 1392×1130 전체 지도를 화면 배율로 키워 통째로 그렸다. 캐릭터가 건물·야자수 21곳의 가림 영역 근처에 있으면, 그 영역마다 지도 전체와 화면 크기 캐릭터 레이어를 다시 그렸다. 셋소호가 커진 0.9.16 이후 겹치는 가림 영역이 늘었다. 안채 방은 가림 영역이 없어서 빨랐다.
2. **느려지면 걷기도 느려짐:** 한 프레임 이동 시간을 최대 0.05초로 잘랐다. 그래서 20fps 아래로 떨어지면 실제 이동 속도도 함께 줄었다. 사용자가 느낀 "걷기가 느리다"가 이것이다.
3. **메모리:** 쓰지 않는 옛 두아트 그림 두 장(각 6MB)을 처음부터 풀어 두었다. 옴보스 낮밤도 방 안에서 계속 들고 있었다. 지도 그림마다 같은 크기의 복사본 캔버스도 하나씩 더 만들었다.

## 고친 것

- 지도 그림은 화면에 보이는 부분만 잘라서 그린다. 가림 영역도 그 영역 상자만 다시 그린다. 낮에는 캐릭터를 따로 레이어에 그리지 않고 화면에 바로 그린다. 저녁과 밤의 그늘이 필요할 때만 상자 크기만큼 레이어를 쓴다.
- 이동은 실제 지난 시간만큼 한다. 최대 0.2초이고, 0.05초씩 나눠 충돌을 검사해서 얇은 벽을 뚫지 않는다.
- 시임 처리가 없는 그림은 복사본을 만들지 않는다. 옴보스·두아트·재질 그림도 그 지도에 있을 때만 풀고, 떠나면 놓아준다.

## 결과 (CPU 4배 느리게)

| 위치 | 전 fps / 이동 | 후 fps / 이동 |
|---|---|---|
| 옴보스 시장 쪽 | 8.9 / 1.63칸 | 40.7 / 4.17칸 |
| 옴보스 신전 앞 | 14.3 / 2.76칸 | 41.5 / 4.14칸 |
| 옴보스, 세트 동행 | 7.7 / 1.55칸 | 51.1 / 4.13칸 |
| 안쪽 복도 | 45.6 / 4.14칸 | 59.5 / 4.19칸 |
| 세트 방 | 55.4 / 4.12칸 | 53.8 / 3.73칸, 침대에 닿음 |

옴보스 한 프레임 그리기는 CPU 제한 없이 9.3ms에서 0.42ms가 됐다.

풀어 둔 그림 메모리는 세트 방 기준으로 약 52MB에서 16MB가 됐다. 전에는 두아트 6, 재질 6, 옴보스 낮밤 12, 세트 방 낮밤 12, 스프라이트 4, 복사본 약 12MB였다. 지금은 세트 방 낮밤 12, 스프라이트 4다. 옴보스에 있을 때는 옴보스 낮밤 12와 스프라이트 4다. JS 힙은 약 20MB로 문제가 없었다.
