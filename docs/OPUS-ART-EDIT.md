# 오푸스 · 직접 하는 그림 손질

[오푸스 입구로](OPUS-HANDOFF.md)

사용자가 직접 요청한 부분 손질에 쓰는 문서다. 아래에서 지금 손질할 부위·도구·채택 절차를 골라 읽는다. 매 프레임마다 전체를 다시 읽지 않는다. 패킹과 런타임 연결은 [스프라이트 적용](OPUS-SPRITE-INTEGRATION.md), 완료 검사는 [검증과 배포](OPUS-RELEASE-CHECKS.md).

## 직접 하는 그림 손질 (`tools/art/fix/`)

> **🛑 그림 손질에서 절대 하지 않는 것 (2026-10-17 호루스 비율 작업, 사용자: "123 절대 하지 말라고")**
> 1. **몸(또는 머리)을 한 방향으로만 줄이거나 늘리지 않는다.** 가로만·세로만 바꾸면 찌그러진다. 사용자가 "몸 두꺼움"이라고 해도 몸 폭만 줄이지 않는다. 몸은 사용자가 그 손질을 직접 시킬 때만 건드린다. 머리 배율은 늘 가로세로 같이(`headshrink.py`).
> 2. **시안 시트에서 시안마다 배율을 다시 맞추지 않는다.** 한 그림의 시안들은 모두 같은 배율로 나란히 놓는다(몸은 그대로, 바뀐 곳만 달라 보이게). "머리 높이를 같게" 시안마다 다시 키우면 머리를 줄일수록 몸이 커져 보여 몸을 늘린 것처럼 보인다. 기준(정지 정면 등)은 반드시 옆에 같이 둔다.
> 3. **몸이 머리 바로 밑에 붙은 자세(쭈그림·앉음·누움)에서 머리를 크게 바꾸지 않는다.** 머리 배율은 목 아래 70행에 걸쳐 1로 돌아오는데, 그 띠 안에 어깨·팔·무릎이 있으면 같이 당겨진다(-30 %에서 어깨가 안으로 끌림). 그런 그림은 단계를 작게(5 %씩) 보여 주고, 띠 안의 어깨·팔을 확대해 원본과 나란히 확인한 뒤 보낸다.
>
> 그리고: 이미 있는 도구(아래 표)를 먼저 쓴다(새 도구를 만들어 잘라 붙이다 얼굴을 깼다). 시안은 먼저 보여 주고, 사용자가 "채택·적용·ㄱㄱ"처럼 분명히 고른 것만 커밋한다("둘 다", "젤 낫다"는 채택이 아니다). 원본은 `sources/<이름>-비율전.png`로 남기고, 다시 할 때는 원본에서 만든다.

**새 동작 그림을 기존 그림에 맞출 때 (2026-10-18 무기 든 걷기·앞뒤 전투, 사용자 "합격"·"개굿")**
순서: 기준 고르기 → 색 → 크기 → 기준점 → 다른 그림과 대보기 → 보여 주고 채택만 커밋.
- **모양은 안 건드린다.** 늘이기·줄이기·워프 없음. 색은 마스크 안 픽셀 색만, 크기는 manifest 숫자(refVH)만, 아틀라스에서 가로세로 같은 배율로 한 번 줄인다 → 창·몽둥이가 휘지 않는다. 비율을 그림으로 고쳐야 하면 위 🛑 규칙대로 시안부터.
- **기준 그림 = 같은 방향:** 좌우는 전투 대기 0(좌·우), 앞·뒤는 일반 정지 앞·뒤(`chibi-refresh/final/<캐릭터>/idle`, 호루스 `horus-redraw-2026-10-14/png/horus-front|back-idle-0`).
- **색: 장마다 따로, 아래 "색을 옮기는 방식"으로.** (예전: 마스크 안만 밝기별 3톤 + 피부 부위별 세 번 `PART_ROWS` — 픽셀이 깨져 2026-10-18에 전부 폐기하고 다시 함.)
- **색을 옮기는 방식 (2026-10-18 소망, 사용자 "피부색 채택"):** 마스크 안 픽셀만 밝기별로 다르게 옮기면 얼룩·이음선이 생긴다(소망처럼 연한 피부는 마스크에 일부만 잡힘). **한 번에, 부드럽게** 옮긴다: `TONE_FLAT=1`(가운데 톤 차이 하나만) + 피부 `SKIN_SOFT=1 SKIN_PLAIN=1`(볼터치를 뺀 맨 피부색끼리 비교, 피부다운 정도만큼 옮김) / 머리 `HAIR_SOFT=1`(머리 마스크 둘레 3 px 안에서 어두운·노랗지 않은 정도만큼, 나무 무기·밝은 픽셀은 거의 안 움직임). 부위를 나누면 `PART_FEATHER=40`으로 경계를 섞는다(소망은 안 나눴다). 볼터치를 맨 피부로 치면 얼굴 전체가 시뻘개진다(사용자 "장난하냐"). **기준은 머리·피부 둘 다 정면 정지** — 옆 정지는 더 붉다. 소망은 인게임 스프라이트 전부를 `final/somang/idle/somang-front.png`에 맞췄다(87장, 원본은 각 폴더 `sources/색전/`). 원본에서 두 번 돌린다:
  - 머리: `TONE_FLAT=1 HAIR_SOFT=1 python3 tools/art/fix/tonematch.py 원본.png tmp.png <who> hair 기준.png`
  - 피부: `SKIN_TIGHT=1 SKIN_CORE=3 SKIN_PLAIN=1 TONE_FLAT=1 SKIN_SOFT=1 python3 tools/art/fix/tonematch.py tmp.png 결과.png <who> skin 기준.png`
  - 결과는 확대(최근접 4배) 원본/맞춤 나란히로 깨짐·붉음부터 보고, 바뀐 픽셀 지도(새−원본)로 머리·피부 밖(옷·금장식·무기)이 안 움직였는지 본다. 사용자 채택 뒤에만 넣는다.
  - **세트·호루스(0.9.86, 사용자 "싹다 합격"):** 인게임 전부(세트 88·호루스 98장)를 각자 정면 정지(`final/set/idle/set-front.png`, `horus-redraw-2026-10-14/png/horus-front-idle-0.png`)에. 예전 방식으로 색을 바꿨던 그림은 그 전 원본(`sources/*-색전.png`, `sources/색전/`, 호루스 오른 피격은 `sources/사용자수정/`)에서 다시 하고, 색 다음에 했던 머리 손질(호루스 옆 정지·걷기 91 %, 뒷모습 방석 94 %)은 manifest `edits`의 같은 값으로 `headshrink.py`를 다시 돌린다(모양이 픽셀까지 같은지 알파로 확인). 위 두 줄에 더한 옵션:
    - 세트 머리 `HAIR_HUE=25`: 빨간 머리는 "노랗지 않음"(b*<14) 조건에 하이라이트가 빠진다 → 색상각 25° 아래·채도 있는 것만 머리로.
    - 호루스 머리 `HAIR_ONLY_LARGEST=1 HAIR_INK=1` 뒤 `hairhl.py 결과 결과 기준`: 머리가 +5 밝아질 때 검은 외곽선이 회색이 되지 않게(밝기 이동을 L/가운데 L만큼).
    - 피부 `SKIN_SATMAX=0.38`(둘 다, 금장식 채도 0.6 제외), 호루스는 `SKIN_SATMIN=0.12 SKIN_GROW=1`(아이보리 킬트 주름·창날 밝은 면이 피부처럼 보여 같이 움직였다 → 피부 마스크에서 12 px 안만).
    - 보이는 피부가 손톱만 한 장은 같은 동작 다른 장에서 잰다 `TONE_FROM=그 장`(세트 뒷모습 줍기 1 → 0).
    - 정면 기준이라 세트 뒷모습은 머리가 3~6 어두워진다(뒷모습 그림이 원래 더 밝게 그려짐). 사용자가 그대로 채택.
  - **`tonematch.py` 옵션 전부**(환경 변수, 위에서 쓴 것; 왜 생겼는지는 파일 안 주석에도 있다):

    | 옵션 | 하는 일 | 생긴 까닭 |
    |---|---|---|
    | `TONE_FLAT=1` | 밝기별 3톤 대신 가운데 톤 차이 하나로 옮김 | 밝기마다 다르게 옮기면 얼룩 |
    | `HAIR_SOFT=1` | 머리 마스크 둘레 3 px 안을 머리다운 정도(어둡고 노랗지 않음)만큼 | 딱딱한 마스크 가장자리가 깨짐, 나무 무기 빠지게 |
    | `HAIR_HUE=도` | 머리다움을 색상각(도 아래)·채도로 판단(`HAIR_SOFT`와) | 세트 빨간 머리·하이라이트가 "노랗지 않음"에 빠짐 |
    | `HAIR_INK=1` | 밝기 이동을 L/가운데 L만큼(검은 선은 거의 그대로) | 호루스 머리 +5 때 외곽선이 회색 |
    | `HAIR_ONLY_LARGEST=1` | 머리 마스크에서 가장 큰 덩어리만 | 호루스 창대가 머리색이라 같이 잡힘 |

    | `SKIN_CORE=n` | 마스크 안쪽 n px에서만 잼 | 외곽선 옆·킬트 주름선이 그림자로 잡힘 |
    | `SKIN_PLAIN=1` | 볼터치 뺀 맨 피부(덜 분홍인 절반)끼리 비교 | 볼터치까지 재서 얼굴이 시뻘개짐 |
    | `SKIN_SOFT=1` | 피부다운 정도(밝음·따뜻함·조금 채도)만큼 옮김 | 연한 피부가 마스크에 일부만 잡혀 얼룩 |
    | `SKIN_SATMAX=s` | 채도 s 넘으면 안 옮김(0.38) | 금장식(채도 0.6)이 피부와 같이 바뀜 |
    | `SKIN_SATMIN=s` | 채도 s부터 피부(호루스 0.12) | 아이보리 킬트(0.08~0.1)가 같이 바뀜 |
    | `SKIN_GROW=1` | 피부 마스크에서 12 px 안의 피부다운 곳만 | 킬트 주름·창날 밝은 면이 같이 바뀜 |
    | `TONE_FROM=png` | 이 그림 대신 같은 동작 다른 장에서 톤을 잼 | 손톱만 한 피부가 분홍으로 쏠림(세트 뒷모습 줍기 1) |
    | `PART_ROWS`, `PART_FEATHER` | 한 부위(행)만, 경계를 n행에 걸쳐 섞음 | 부위별 색(지금은 안 씀) |
- **크기:** (장마다 흔들리면 아래 "머리 고정") 0번 장 머리를 기준 그림 머리에 `register.py`로 겹쳐(`--rows` 얼굴 띠, 기준은 사방 300–400px 늘린 캔버스) 배율을 찾고 겹친 그림(50 % 섞기)으로 눈·눈썹이 맞는지 본다(오차 숫자는 그림체가 다르면 커도 됨). 기본은 **방향마다 그 배율 하나**: 장끼리 머리 크기 차이는 그린 그대로("프레임 부드럽게"). 사용자가 장마다를 고르면 그대로(세트 걷기: 장마다 키 = 대기 키). refVH = 기준 refVH × 배율.
- **머리 고정 (2026-10-18 호루스 전투 앞 대기, 사용자 "프레임이 확확 흔들림" → 1안 "이게 낫다"):** 장마다 머리 크기·높이가 달라 0-1-2-1이 튀어 보이면, 장마다 얼굴(눈·눈썹 띠, 무기가 안 들어오게 자른 것)을 0번 장에 `register.py`로 겹쳐 배율 f와 자리를 찾고 겹친 그림(50 %)으로 눈이 맞는지 본다. refVH_k = refVH_0 × f, 기준점 = 얼굴이 0번과 같은 화면 자리에 오게(자른 칸 원점 c, 겹친 자리 o: pivot_k = c − f × (o − pivot_0)). 머리는 가만히, 몸·발이 조금 움직인다(1번 발이 기준선 아래로 조금). 머리 크기가 별 차이 없으면 자리만 맞춘다. 호루스 앞 대기: 1번 0.93(refVH 935.4), 2번 0.97(975.6).
- **기준점:** 좌우 = 옷(치마·킬트) 큰 덩어리 아래쪽 가운데, 높이 = 그 폭 안 가장 아래 행(샌들 바닥, 무기 끝은 빠짐). 전 장에 십자 표시 시트를 만들어 어긋난 장만 확대 눈금으로 고친다.
- **다른 그림과 대보기:** 게임 크기로 새 그림과 기존 전투 그림(좌우 대기·걷기·공격)을 같은 발바닥 선에 나란히, 머리·키·무기 길이가 방향 바뀔 때 튀지 않는지. 움짤은 좌→앞→우→뒤 대기·걷기·공격.
- **보여 주기:** 장마다 "기준 / 원본 / 맞춤" 시트, 장별 ΔE 표(머리 3톤·하이라이트·피부 3톤, 1 안팎), 게임 속도 움짤. **움짤·영상은 앱에서 재생이 안 되니 Artifact 페이지(GIF·mp4를 넣은 HTML) 링크로.**
- 손질 결과는 원본 폴더에 덮고 원본은 `sources/색전/`, 폴더 manifest에 장마다 sha256·refVH·pivot·edits(무엇을, 어느 기준에, 사용자 말).

사용자가 "머리 좀 키워", "얼굴 덜 넓적하게", "귀 줄여", "턱 이렇게(직접 그린 그림)"처럼 부분 손질을 시키면 오푸스가 픽셀로 한다. 0.9.35~0.9.39의 소망 잠 비율, 호루스 정면 잠 얼굴·귀·턱, 0.9.34의 세트 옆잠 머리 93 %·호루스 문양이 이렇게 했다. 원칙:

- **새로 그리지 않는다.** 바꿀 부분만 변형(워프)하고 나머지 픽셀은 원본 그대로 복사한다. 모든 워프는 출력 픽셀 → 원본 좌표 역매핑, 알파 곱한(premultiplied) 쌍선형 샘플, 알파 128 이상은 불투명·40 미만은 투명. 경계에 70행 정도 서서히 바뀌는 띠를 두어 잘린 자국이 없게 한다.
- **원본부터 연다.** 채택 png를 격자(`PIL`로 50px 선)나 4~5배 확대 크롭으로 보고 기준점(목, 턱, 얼굴선 좌표)을 읽는다. 0·1프레임 머리가 같은지 먼저 차이를 본다(같으면 같은 값을 그대로).
- **시안은 약·중·강 2~3개**를 `panels.py`로 "지금 / 시안 / 기준"과 함께. 숫자는 표로.
- 고르면: 전 그림을 `sources/<이름>-<무엇 전>.png`로 보관(사용자 그림도 `sources/`), 0·1프레임에 같은 값, manifest의 `sha256`을 다시 계산하고 `edits`에 "무엇을 몇 %로, 어디 기준, 원본 위치, 사용자 말"을 적는다. **manifest는 원래 들여쓰기 그대로(`json.dumps(m, ensure_ascii=False, indent=1)`)** — 다르게 쓰면 파일 전체가 바뀐 diff가 된다. 그다음 `pack-trio-motion.py`, 버전, 검증, 게임 캡처(`bed-pairs.js` 등)를 보낸다.
- 숫자: 스프라이트 원본 1px = `31.2 / referenceVisibleHeight / 16`칸(세트·호루스 576 → 0.0034칸, 소망 잠 523.6 → 0.0037칸). 침대 y는 클수록 아래. 머리를 키우면 머리 가운데(머리 위끝~턱)가 올라가니 그만큼 침대 y를 내린다(소망 0.9.35: 15.5px → +0.055칸).
