# 인연과 유대 — 확정 설계 (16번째 시스템, 0.9.63 구현)

사용자와 확정한 설계를 아래 순서대로 구현했다. UI 기준은 사용자가 정정한 드라이브 미리보기 **3장**이며, 원본 PNG 아트팩을 재사용했다. 적용: 0.9.63. [구현·검증·비교 보고](bond-ui/README.md).

**원칙: RP의 인연은 이어받고, 게임의 유대는 새로 쌓는다.**

- 인연의 기록(`s.bond.ties`)은 RP에서 실제로 일어난 일을 사용자가 고르거나 승인해 남긴 것이다.
- 게임 유대(`s.bond.<who>.pts`, 0~100)는 이 세이브에서 함께 한 일로만 오른다.
- 둘은 서로를 바꾸지 않는다.
  - 인연을 기록하거나 AI로 분석해도 유대 점수는 그대로다.
  - 유대가 100이어도 RP에 아무것도 만들지 않는다. 고백, 관계 변화, 프롬프트 주입 모두 없다.
- 유대 0은 "사랑이 없다"가 아니라 "이 세이브에서 함께 쌓은 일이 아직 없다"는 뜻이다.
- 게임 문구는 사실만 적는다(무엇을 건넸고 유대가 얼마 올랐는지). 감정과 대사는 RP에서 이어 간다.

## 1. 저장 (채팅마다, `chatMetadata.sand_feather`, 세이브 v11)

```
s.bond = {
  set:   { pts: 0, steps: {}, gifts: {} },   // steps { 20: 달성일 }, gifts { itemId: 처음 준 날 }
  horus: { pts: 0, steps: {}, gifts: {} },
  ties:  [],   // 인연의 기록 (상한 300)
  cand:  [],   // AI 후보, 승인 전 (상한 60)
  skip:  [],   // 제외한 후보의 지문
  scan:  { upTo: -1, chunks: [], carry: null, pending: [], failures: [], job: null },
  alias: { set: [...], horus: [...] },
  log:   []    // 오늘부터 쌓은 유대 = 동행 추억 수첩 (상한 200)
}
```
- v10 → v11은 빈 값을 채우기만 한다. 기존 RP나 데이터로 유대를 계산하지 않는다.
- 다른 채팅과 섞이지 않는다.
- 사용자 추가 지시: 검토하지 않은 후보는 상한 때문에 버리지 않는다. `cand` 60개 + `scan.pending` 초과 대기로 저장하고, 승인·제외할 때 다음 후보를 채운다. 대기가 있으면 다음 분석 요청을 잠시 멈추고 검토 후 재개한다.
- `scan.job`에 분석 커서·원문 지문·설정을 저장하고, `scan.failures`에 실패한 묶음을 남겨 다음 작업 뒤에도 재시도할 수 있다. 인연 기록 300개가 차도 기존 기록을 자동 삭제하지 않고 정리 후 승인하도록 알린다.
- 15종 기획서 D(동행 추억 수첩)의 `memories`는 `s.bond.log`로 대신한다(같은 것을 두 번 만들지 않음).

인연 기록 하나:
```
{ id, who: 'set'|'horus'|'both', title, summary, kind, when, where,
  src: [ { at, sendDate, quote, hash } ], origin: 'ai'|'manual', certainty: 'clear'|'check',
  edited: false, day, status: 'live'|'away'|'changed' }
```
- `both`는 기록 하나로 저장하고 세트·호루스 수첩 양쪽에 보인다.
- 중복은 인물과 상관없이 원문(`at` + `sendDate` + 인용)으로 막는다.

## 2. 게임 유대

| 얻는 법 | 유대 | 조건 · 반복 막기 |
|---|---|---|
| 선물 (평범 / 좋아함 / 특별 / 안 맞음) | +2 / +5 / +8 / +0 | 소망과 받는 사람이 같은 일행(앞장이나 동행)일 때만. 몇 번이든 줄 수 있지만 유대는 그 사람에게 그날 첫 선물만(`ledger` `bond:gift:<who>`). 두 번째부터 확인창: 「오늘은 이미 유대를 쌓았어. 선물은 소모되지만 유대는 오르지 않아」 |
| 낚시 · 요리 · 공부 | +2 | 동행이면 자동. `didAct` 한 군데에서 행동이 끝난 순간의 `party.lead` / `party.with`로 정한다. 소망과 그 사람이 둘 다 일행이어야 한다. 사람 × 활동 하루 한 번(`bond:act:<who>:<kind>`) |
| 작은 모험 완료 | +3 | 같음 |
| 두아트 | 정할 것 | 함께 간 사람(`r.comp`)과 앞장을 따로 판정 |
| 특별 공동 활동(단계 해금) | 정할 것 | 「함께하기」 버튼, 자기 키(`bond:special:<id>`). 그 안의 `didAct`는 일반 유대를 건너뛴다(중복 없음, 테스트로 확인) |

- 점수는 0~100 안에서만 움직이고 내려가지 않는다.
- 선물 선호도는 `data/bond.json` `gifts.<who>.{love, like, dislike, special}`(아이템 id 목록)에 둔다. 승인 전에는 비워 두어 모두 +2다. 값이 비싸다고 더 좋은 선물이 아니다.
- 선물은 누를 때 지금 상태로 다시 확인하고(물건, 일행, 오늘 횟수), 중복 클릭 잠금을 건 뒤 한 번에 처리한다(`takeUid`, `pts`, `log`, `facts`, `journal` 사실 한 줄).
- 단계: 0 기본, 20 선물 취향 단서. 40·60·80·100 내용은 따로 승인받는다(제안: 세트는 모래 언덕 대련·사막 모험 씨앗, 호루스는 관측 기록·높은 곳 단서). 기념품은 새 그림이 필요하다.
- 재사용: `facts.record` / `tally`(선물·함께·단계·인연 기록; 낚시·작은 모험 기록도 이때 추가), `journal`(RP로 꺼낼 사실 한 줄, 사용자가 「꺼내기」를 눌러야만), `daylog`(하루 결산에 "세트와 함께 낚시"), `ledger`(모든 하루 제한).

## 3. 인연의 기록 — 두 입구

### 3-1. 직접 기록하기
- 기존 「게임에 반영하기」의 문장 고르기를 그대로 쓴다.
- 고르는 곳에 「인연의 기록」을 더하고, 세트 / 호루스 / 둘 다를 고른다. 저장은 `s.bond.ties`에 `origin: 'manual'`로 한다. `picks`처럼 자동으로 지워지거나 20개로 잘리지 않는다.

### 3-2. AI로 인연 찾아오기 / 새로운 인연 동기화

**연결**
- 작은 모험이 쓰는 서랍의 AI 연결(`src/core/ai.js callConn`: 커스텀 API, Vertex)을 쓴다. 새 서비스나 키는 없다.
- 연결이 꺼져 있으면 버튼을 막는다. 시작 전에 "이 채팅의 RP 글이 설정한 AI로 보내져"를 한 줄 보여 준다.

**범위와 미리 보기**
- 기본은 **최근 300개**. 「전체」나 번호 범위도 고를 수 있다.
- 시작 전에 메시지 수, 글자 수, 보낼 토큰 어림(한글 1.5자=1토큰), 호출 수, 예상 시간을 보여 준다. 정밀 확인을 켰으면 그 호출도 넣는다. 사용자가 [시작]을 눌러야 실행한다.
- 실행 중에는 「n/N 묶음 · 후보 m개」와 「중단」이 있다. 묶음마다 저장하므로 다시 열면 「이어서 하기」가 뜬다.

**보내는 글**
- 지금 채팅만 보낸다. 지금 보이는 스와이프만, 숨김·시스템 메시지는 뺀다. 트래커와 마크업은 `plainText`로 지운다.
- 메시지마다 `[#번호 · 화자]`를 붙인다.

**묶음(청크)**
- 글자 수로 나눈다. 기본 약 2만 4천 자이고, 서랍에서 작게 / 보통 / 크게를 고른다.
- 앞 묶음의 끝 메시지 4개를 겹친다.
- 순서대로 보낸다. 시간순 이해를 위해서이고, 병렬로 보내지 않는다.

**이어 읽기 맥락(청크 사이)** — 두 칸으로 나눈다:
1. **확정 사실 장부**: 원문으로 확인된 현재 관계, 이미 일어난 중요한 사건과 약속, 인물들이 실제로 알게 된 주요 사실.
   - 항목마다 `{ fact, ref: 메시지 번호, quote }`.
   - 예: "소망과 세트는 연인이 되었다(#812: '…')". 원문에 그렇게 확정된 경우만 넣는다.
2. **진행 중 사건**: 묶음 경계를 넘어 이어지는 일.
   - 코드가 붙인 id(`e7`), 제목, 시작 메시지, 지금까지의 근거 번호.

맥락 규칙:
- AI가 추측한 감정·관계·해석은 넣지 않는다.
- 맥락의 모든 항목은 **코드가 인용을 원문과 다시 대조**해서 맞는 것만 다음 묶음에 넘긴다. 틀린 맥락이 뒤로 퍼지지 않게 하려는 것이다.
- 사용자가 승인한 인연 기록도 확정 사실로 함께 넘긴다.
- 길이: 장부 최대 40항목 · 약 4천 자, 진행 중 사건 최대 10개 · 약 1,500자.
  - 넘치면 AI가 "바뀐 사실로 대체"한다(예: 「연인이 되었다」가 「약혼했다」로).
  - 넘겨받은 장부를 다시 정리하게 하되, 근거가 없는 항목은 코드가 뺀다.
- 묶음 경계마다 그때의 맥락을 `scan.chunks[k].carry`에 저장한다. 중간 묶음을 다시 분석할 때 그 앞 맥락에서 시작할 수 있다.

**AI 규칙과 답**
- 원문에 실제로 일어난 일만 적는다. 계획·상상·꿈·가정·농담은 뺀다.
- 소망과 세트, 소망과 호루스, 셋이 함께한 사건만. 종류: 선물·물건 주고받기, 함께한 활동이나 여행, 약속, 원문에 확정된 관계 전환점, 셋의 추억.
- 인물은 문맥으로 구분하지만, 확실하지 않으면 `check`로 둔다. 감정은 새로 정하지 않는다.
- 같은 사건이 이어지면 새 사건을 만들지 말고 `continues: "e7"`로 이어 붙인다.
```json
{ "events": [ { "title": "", "who": "set|horus|both", "kind": "gift|trip|activity|promise|turning|together|event",
    "when": "", "where": "", "summary": "", "refs": [412, 413], "quotes": [ { "at": 413, "text": "원문 그대로" } ],
    "continues": "", "certainty": "clear|check" } ],
  "ledger": [ { "fact": "", "ref": 0, "quote": "" } ],
  "ongoing": [ { "id": "", "title": "", "from": 0, "refs": [] } ] }
```

**코드 검증** — 인용이 맞는 것과 해석이 정확한 것은 다르다. 인용이 맞아도 「정확함」으로 표시하지 않는다.
1. 인용을 원문과 대조한다(공백·문장부호는 정리하고 비교). 하나도 안 맞으면 버린다. 일부만 맞으면 `check`.
2. `refs`가 묶음 범위 밖이거나 없는 메시지면 버린다.
3. 인물: 인용이나 바로 앞뒤 메시지에 그 사람의 별칭이 실제로 있어야 한다. 없으면 `check`.
4. 요약에 마음·사랑·결심 같은 말이 있는데 인용에 그 말이 없으면 `check`.
5. **정밀 확인**(서랍 선택, 기본 켜짐): 묶음의 후보들을 앞뒤 ±6개 메시지와 함께 한 번 더 보내 "요약이 이 원문으로 뒷받침되는가, 빠진 전후 사정은 없는가"를 묻는다. 그렇다고 답한 것만 `clear`, 나머지는 `check`이고 이유를 붙인다. 후보가 있는 묶음당 한 번이다.
6. 길이·형식: 제목 24자, 요약 160자, 인용 3개 × 120자. 형식이 틀리면 그 묶음만 한 번 다시 묻고, 그래도 틀리면 건너뛰고 알린다.

**중복**
- 같은 메시지를 가리키는 후보, `continues`로 이어진 후보, 또는 ±3개 메시지 안에서 인물이 같고 제목이 비슷한(글자쌍 0.5 이상) 후보는 하나로 합친다. 근거는 합치고 확실성은 낮은 쪽을 따른다.
- 이미 등록된 기록과 같은 원문이면 「이미 있음」으로 표시한다. 제외한 후보는 다시 제안하지 않는다.

**후보 화면**
- 한 줄: 체크칸, 제목, 인물, 날짜·장소, 확실성. 표시는 「원문 근거 있음」 / 「확인 필요 + 이유」.
- 펼치면: AI 요약과 원문 인용(번호)을 다른 모양으로 보여 주고, 「원문 보기」(채팅에서 그 메시지로 스크롤)가 있다.
- 승인 전에 제목·인물·요약·날짜·장소를 고칠 수 있다. 고친 것은 `edited`로 표시한다.
- 하나씩 승인하거나, 체크한 것을 일괄 승인한다. 「확인 필요」는 일괄 승인에서 기본 해제다. 제외도 할 수 있다.

**증분 동기화**
- `scan.upTo` 뒤만 분석한다. 마지막 맥락에서 이어 가고, 앞쪽 4개 메시지를 겹친다.
- 묶음 지문(보낸 시각 + 본문)이 바뀌면 「바뀐 부분 n곳」을 알린다. 사용자가 고르면 그 묶음만 다시 분석하고, 그 뒤 묶음에는 「다시 확인 권장」을 표시한다.
- 자동 동기화는 서랍 선택이고 기본 꺼짐이다. 켜면 새 메시지가 40개 쌓였을 때 표시만 띄운다. 호출은 사용자가 누를 때만 한다. 매 답장마다 부르지 않는다.

### 3-3. 별칭
- 기본 별칭(띄어쓰기는 비교할 때 무시):
  - 세트: `세트`, `Set`, `세트님`, `세트 신`
  - 호루스: `호루스`, `Horus`, `호루스님`, `호루스 신`
- 「인연과 유대」 창에서 추가·수정·삭제한다. 채팅마다 저장한다(`s.bond.alias`).
- 누구인지 특정할 수 없는 말은 별칭으로 받지 않는다: 그, 그녀, 그분, 그이, 그 신, 그 남자, 신, 남자, 그대, he, him, the god 등과 한 글자 말.
- 그런 말로만 나온 사건은 AI가 문맥으로 판단하되, 코드 인물 확인(위 3번)을 통과하지 못하면 `check`다.

### 3-4. 원문 상태
- 채팅이 바뀔 때(답장, 스와이프, 수정, 삭제) 기존 `syncPicks` 자리에서 기록의 인용을 다시 확인한다.
- 결과는 연결됨 / 다른 스와이프에 있음 / 원문이 바뀜 셋이다.
- 기록은 자동으로 지우지 않고 사용자가 [남기기 / 지우기]를 고른다. 원본 채팅은 절대 고치지 않는다.

## 4. UI (그림은 사용자 아트팩 그대로)
- 들어가는 곳: 하단 「일행」 탭 세트·호루스 줄의 「인연」 버튼, 캐릭터 「자세히」 카드. 넓은 카드(`showCard({wide})`)로 연다.
- 카드 안: [세트 | 호루스] → 인연의 기록(「AI로 인연 찾아오기」·「새로운 인연 동기화」·「직접 기록하기」) → 유대 게이지 0~100 → 단계 20/40/60/80/100 → 선물 슬롯 + 「선물하기」 → 함께하는 활동 → 추억 수첩.
- 폰(899px 이하)은 세로, 데스크톱(900px 이상)은 왼쪽 인연 기록과 수첩, 오른쪽 유대·선물·활동 2열. 5테마 카드 틀 안에 아트팩 장식을 넣는다.
- 아트팩은 `data/art/ui/bond/`에 넣는다. 탭·초상, 게이지 틀·채움, 단계 표식(잠김·열림), 선물 슬롯, 인연 기록 카드·리본, 수첩 바탕, 활동 아이콘, 버튼에 쓴다. ZIP을 보고 자리를 맞춘다.
