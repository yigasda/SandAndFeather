## 가장 중요한 원칙

> 사용자는 **채택된 시안을 베이스로만 고치는 것**을 원한다. 마음에 든 그림을 계속 다듬는 작업이지, 같은 설명으로 비슷한 그림을 새로 만드는 작업이 아니다.

- 수정 대상은 설명이나 기억이 아니라 **실제 채택 파일**이다. 파일을 열어 보고, 그 파일을 편집 입력으로 삼는다.
- 요청한 부분만 바꾼다. 승인된 구도, 색, 가구, 얼굴, 머리, 몸, 그림체를 임의로 다시 디자인하지 않는다.
- “이것만”은 수정 범위를 제한하는 말이다. 안광 하나를 지우면서 동공 크기를 바꾸거나, 출구를 고치면서 가구를 옮기면 실패다.
- 참고 이미지는 사용자가 지정한 속성만 참고한다. 옷 참고를 얼굴·몸매·그림체 전체 교체로 해석하지 않는다.
- 새 수정본에서도 요청 밖 요소가 바뀌었다면 그 변화를 다음 베이스로 누적하지 않는다. 마지막 채택본에서 필요한 수정 부분만 가져온다.
- 합쳐 보여 달라는 요청은 기존 파일을 배치하는 작업이다. 합본을 새로 그려서 인물이나 장면을 바꾸지 않는다.
- 전체 재작성은 사용자가 해당 범위를 명시적으로 요청했을 때만 한다. 예: “호루스 머리통 전체”는 얼굴형·이목구비·귀·두상·머리카락 전체 수정 요청이었다. 몸과 다른 캐릭터까지 바꾸라는 뜻은 아니었다.
- 시안 품질을 그대로 유지한다. 원본 위에 단순 도형·단색·부자연스러운 그림자를 얹는 식으로 마무리하지 않는다.

## 채택 상태를 잊지 않는 법

**최신 파일 ≠ 채택된 파일 ≠ 게임에서 쓰는 파일.** 세 상태를 별도로 기록한다. main에 커밋하거나 Drive에 올린 사실도 사용자 채택의 증거가 아니다.

| 상태 | 의미 | 후속 작업 |
|---|---|---|
| 채택된 원본 | 사용자가 선택·승인한 실제 그림 | 요청한 국소 수정의 기준. 보존한다 |
| 수정 검토본 | 원본에서 요청을 반영해 새로 전달한 결과 | 자동으로 승인 처리하지 않는다. 승인된 요소만 계승한다 |
| 반려·교체본 | 사용자가 싫다고 했거나 후속본으로 대체한 결과 | 현행 적용 목록과 기본 입력에서 제외한다 |
| 게임 적용본 | 코드에서 실제로 읽고 있는 에셋 | 경로·매니페스트로 확인한다. 시안 전달만으로 적용 완료라 하지 않는다 |

베이스가 불분명하면 먼저 대화의 채택 표현, 파일 명세, 커밋과 실제 그림을 대조한다. 그래도 특정할 수 없을 때만 어떤 파일인지 좁혀 묻는다. 이미 정해진 취향이나 승인을 다시 묻지 않는다. 새 검토본에 답이 없다는 이유로 승인됐다고 추정하지 않는다.

## 작업 순서

1. `git status`, 현재 브랜치, 원격 변경과 인수인계를 확인한다. 오푸스도 같은 main에 작업한다. 다른 작업을 되돌리지 않는다.
2. 베이스 파일 경로와 채택 근거를 확인한다. 변경할 부분, 유지할 부분을 짧게 정한다. 여러 참고 이미지의 역할을 구별한다.
3. 원본은 보존하고 파생 작업 파일에서 수정한다. 그림 편집은 현재 사용 가능한 이미지 편집 도구에 **원본을 참조 입력**으로 제공한다. 매번 전체 장면을 독립 생성하지 않는다.
4. 편집 결과를 대조한다. 국소 수정이면 요청 영역 밖 변화가 없는지 확인한다. 필요하면 편집 도구가 만든 수정 부분만 원본에 합성한다. 생성 도구가 “유지했다”고 설명한 것만으로 검증을 대신하지 않는다.
5. 원본 크기, 투명도, 발 기준점, 프레임 정렬, 낮밤의 건물 위치 등 해당 작업에 필요한 조건을 확인한다. 원본과 픽셀 동일을 주장하려면 실제로 비교한다.
6. 원본과 수정본의 전후 비교 및 필요한 확대본을 만든다. 비교용 표기·화살표·좌표는 게임용 PNG에 넣지 않는다.
7. 파일별 용도와 상태, 변경 좌표, 검증 내용, 아직 적용하지 않은 부분을 문서에 적는다. 원본·게임용·검토용·생성 중간 파일을 구분한다.
8. 사용자에게 볼 수 있는 링크를 전달한다. 이어지는 피드백을 받으면 같은 채택 베이스에서 해당 부분만 다시 고친다.

이미지 결과는 Google Drive 링크를 포함한다. 사용자의 모바일 환경에서 인라인 이미지나 로컬 링크 확인이 실패한 적이 있다. 업로드 후 파일명·크기·링크를 확인한다. 이미지를 확인할 때는 필요한 한 장이나 작은 비교판부터 보고, 큰 이미지 여러 장을 무더기로 다시 읽지 않는다.

## 셋소호의 채택 기준

최종 외형의 근거는 [승인 원본 폴더](../art/chibi-refresh/approved/)와 [48장 목록](../APPROVED-IDLE-WALK-FILES.md)이다. 아래 설명은 파일을 찾고 잘못된 변경을 막기 위한 메모이며, 설명만으로 캐릭터를 재생성하라는 뜻이 아니다.

- 세 명의 몸 베이스는 호루스. 등신, 몸통, 손발 크기를 맞춘다. 특히 세트 측면의 배가 불룩해지거나 하체가 다시 길어지지 않게 한다. 머리 모양 때문에 보이는 외곽 크기 차이를 몸 비율 문제로 오해하지 않는다.
- 세트: 채택본의 긴 자주색 머리와 눈매 유지. 호루스와 맞춘 단순한 몸 디테일, 곧은 옆선, 짧은 차콜 치마가 현행 승인 방향이다. 대화 초반의 발목 치마 요구를 나중에 승인한 파일보다 우선해 되돌리지 않는다.
- 소망: 채택본의 눈매와 얼굴, 시스루뱅, 가슴 길이의 퐁실한 곱슬 끝, 흰 드레스와 흰 끈리본. 옷은 조금만 하늘하늘하게. 참고의 성인 체형이나 과한 볼륨까지 옮기지 않는다. 반묶음 등 세부는 최신 채택 파일과 후속 요청으로 확인한다.
- 호루스: 짧고 삐죽한 푸른 남색 머리. 검게 보이거나 북실하고 길어지거나 두상이 찌부되지 않게 한다. 피부는 반 톤 밝아진 뉴트럴 쿨톤. 웜하게 되돌리지 않는다.
- 호루스 눈은 채택본의 작은 동공·아래 안광 유지. 큰 위쪽 안광 제거가 동공 확대 요청은 아니다. 캐릭터 왼쪽 눈 문양의 방향별 비대칭을 지킨다. 좌우를 무조건 미러하지 않는다.
- **호루스 가슴천은 게임 스프라이트에서 제외하기로 사용자가 결정했다.** `review-chest-cloth/`는 미채택 참고 기록이며 적용 후보가 아니다. 승인된 무가슴천 원본을 사용한다.
- 걷기 0→1→2→1, 180ms. 호루스 정면만 360×400 원본 셀 기준 `(+1,0), (0,-1), (-1,0), (0,-1)`. 추가 회전 없음. 원본 1px와 게임 화면의 논리 1px는 다르다. 오프셋을 PNG와 렌더러 양쪽에 중복 적용하지 않는다.

## 맵 보정의 기준

- 채택된 장면의 구도, 색, 가구, 재질과 화풍을 유지한다. 실제 변경은 요청한 출구 부분으로 한정한다.
- 입구는 건물과 같은 구조·원근을 가져야 한다. 기둥 높이, 천장선, 벽 두께, 바닥선이 연결되어야 한다. 바닥 위에 놓인 레고 같은 작은 문틀은 반려됐다.
- 화분 사이 틈이나 단순한 그림 잘림으로 보이지 않게, 실제 통로의 그늘·문턱·바닥 연결을 보여준다. 눈에 띈다는 이유로 독립된 구조물을 덧붙이지 않는다.
- 낮밤 쌍은 같은 위치·형태로 보정한다. 밤에는 약한 등불을 쓸 수 있지만 문 위치·가구 배치를 별도로 재해석하지 않는다.
- 최종 그림 크기는 기본적으로 고정한다. **사용자가 가로 확장을 요청한 2026-10-11 연못 회랑은 예외: 원본 1448×1086을 (0,0)에 보존하고 오른쪽 484px를 추가해 1932×1086.** 우물 마당도 후속 요청으로 좌우 확장 허용: 원본1774×887→2638×887, 원본 오프셋(432,0). 출구 위치가 바뀌면 최종 이미지 좌표와 원본 오프셋을 함께 전달한다. 편집 사각형, 시각적 문턱, 제안 트리거, 제안 도착점을 구분한다.
- 아스트라는 미술 보정과 적용 자료를 맡고, 오푸스는 이 요청에서 충돌·출구·도착점을 연결한다. 이후 사용자가 역할을 바꾸면 그 지시를 따른다. 좌표 제안만 하고 실제 걸어봤다고 말하지 않는다.

## 현재 후속 작업 — 최신 반려와 수정 기준

우물 마당의 112·113번 통로도 사용자 반려: 가구 뒤에 떠 보였고 상단에 합성 흔적이 있었다. 현재는 원본1774×887을(432,0)에 두고 좌우432px씩 확장한2638×887 검토본이다. 새 양옆 공간에 가구와 분리된 출입구를 만들고 상단 구조 전체를 다시 그렸다. 원본의 접합부/상단 밖과 가구 보호 영역은 픽셀 동일. 116·117번이 현행 검토본이며 미채택·런타임 미적용. 연못 낮밤/동쪽 채택 해시는 유지했다.

치비 v1의 소망 머리·호루스 얼굴은 반려. 현행 `review-pocket-style-v2/`는 소망 다크브라운+곱슬 폭 축소, 호루스 승인 원본 얼굴·눈썹·눈매·피부색을 기준으로 보정한 정면 검토본이다. 호루스 피부는 승인 PNG에서 직접 추출한 색을 편집 입력에 사용했다. 예전 치비는 짧은 머리 참고만. 세트는 v1 그대로. 아직 미채택이며 승인48장과 런타임은 변경하지 않았다.

**추가 교훈:** 피부색을 기억으로 맞추지 말고 승인 파일에서 좌표와 RGBA를 추출한다. 캐디 유지에는 눈매·눈썹 각도·피부 명도/색도 포함된다. 소망은 DARK BROWN, 곱슬은 유지하되 옆 폭을 부풀리지 않는다. 입구가 가구 위에 떠 보이면 문틀만 키우지 말고 사용자가 허용한 확장 공간에 통행 바닥부터 만든다. 상단 입구처럼 전체 재작성이 허용된 곳은 지나치게 작은 보호 사각형으로 잘라 붙여 접합 흔적을 만들지 않는다.
