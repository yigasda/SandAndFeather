# 인연과 유대 — 0.9.63 구현·시각 비교

승인된 [BOND-PLAN](../BOND-PLAN.md)의 1~8 순서로 구현했다. 사용자 최종 정정에 따라 **Drive 미리보기 3장**을 조립 기준으로 사용했다. 새 이미지 생성이나 재작화 없이 기존 PNG와 추가 추출 픽셀을 사용했다.

## 실제 화면

## 직접 본 화면과 차이

- 320px에서 세트·호루스 이름이 한 줄로 보인다. 기록 아래에 게이지, 보상 상자, 선물, 활동, 깃털·수첩이 이어지고 창 내부를 내려서 볼 수 있다. 본문을 줄여 한 화면에 강제로 넣지 않았다.
- 1280px에서는 왼쪽 기록과 오른쪽 게이지·선물·활동이 구분된다. 깃털 안내와 수첩은 아래에 있다. 제목 장식·닫기·모서리가 창을 벗어나거나 다른 팝업의 잘림 마스크에 가려지지 않는 것을 확인했다.
- 금빛 프레임은 원본 모서리와 직선 부분을 분리했다. 제목 연꽃·새·앙크, 탭 발자국·새, 책·식물·선물·나뭇가지, 활동 그림, 깃털을 직접 확인했다. 연꽃과 책은 패널 폭에 맞춰 가로로 늘어나지 않는다.
- **원본과 완전히 동일한 화면은 아니다.** 공식 인물 초상화는 승인된 `data/art/portraits/*-bust.png`를 사용했다. 미리보기의 동물형 얼굴과 다르고, 승인 원본에 있는 밝은 바탕도 유지했다. 물건은 실제 가방의 승인 PNG이며 예시 삽화나 가짜 아이템을 등록하지 않았다.
- 기록에는 저장된 원문 사실과 날짜만 표시한다. 미리보기의 감정 문구·붉은 팔찌·별밤 삽화를 임의의 RP 기록에 붙이지 않았다. 기록 그림은 작은 책으로 통일했다. 분석/직접 기록/원문 관리 버튼은 실제 기능을 위해 추가되어 기록 영역이 미리보기보다 길다.
- 320px 활동 카드는 글자를 읽을 수 있게 2×2, 412px 이상은 4개 한 줄이다. 412px에서는 아이콘 위·글 아래이며, 참조의 아이콘 옆 글 배치와 차이가 있다. 원본 크기를 강제로 축소해 텍스트를 압축하지 않았다.
- 바깥 맵·HUD·하단 탭은 기존 게임이다. 참조에 그려진 다른 마을/HUD로 교체하지 않았다. 기존 다섯 테마의 배경·다른 팝업은 보존하고 인연 팝업만 원본 아트의 파피루스 색을 사용한다.

## PNG와 출처

- 보관: 원본 **39개** + 추가 추출·분리 **29개** = **68개**. 원본 39개는 ZIP과 바이트 단위로 같다.
- 실제 화면에서 요청된 Bond PNG: **39개**(원본 11개, 추가 추출 28개). 이 숫자는 원본 39개를 모두 사용했다는 뜻이 아니다. 공식 인물·아이템 PNG는 별도 재사용했다.
- 추가 29개: 미리보기에서 14개, 기존 추출 PNG의 부분 추출·알파 분리 14개, 원본 프레임 조각 조립 1개. 사용하지 않은 추가 파일은 보조 종이 조각 `record_paper.png` 1개다.
- [매니페스트](../../data/art/ui/bond/bond-ui-manifest.json): 파일별 원본·좌표·알파 처리·SHA256·화면 사용 여부.
- [누락 요소 점검표](element-checklist.md): 시각 요소별 구현 방식과 차이.
- [원본 보존 검사](checks/assets.json).

받은 ZIP에는 `SOURCE_ORIGINAL_UNCHANGED.png`가 없었다. 매니페스트의 원본명 `1000482501.png` 및 해당 시트명으로 Drive도 찾았으나 확보하지 못했다. 따라서 있는 PNG를 우선 쓰고 거기에 없는 작은 장식은 미리보기에서 추출했다. 시트 전체를 대조했다고 주장하지 않는다.

Drive의 미리보기 파일은 이름이 PNG지만 내용은 **JPEG**다. 책·식물·나뭇가지·깃털·새·발자국·닫기·작은 모서리에 원본의 번짐과 압축 흔적이 남는다. RGB는 그대로 두고 배경만 마스킹했다. 작은 장식은 화면에서 원본 이하 크기로 사용하며, 확대·선명화·새 그림으로 대체하지 않았다. 닫기와 종이 모서리는 원본의 배경을 포함해 같은 종이/프레임 위에 배치한다.

## 기능과 저장

- 세이브 v10→v11은 빈 `bond`를 추가한다. 맵·캐릭터·가방·기존 기록에서 점수를 소급 계산하지 않는다.
- 직접 기록/AI 후보 승인만 `ties`에 들어간다. `both` 기록은 하나를 저장해 양쪽에 보여 준다. RP 기록은 유대 점수를 바꾸지 않는다.
- 소망과 상대가 현재 일행일 때 낚시·요리·공부 +2, 작은 모험 완료 +3. 사람×활동×하루 제한을 중앙 `didAct`에서 적용한다. 두아트·특별 활동은 일반 유대를 중복 적용하지 않는다.
- 선물은 실제 UID를 다시 확인하고 저장 중 잠금을 건다. 하루 첫 선물만 +2(승인 전 선호도 목록은 비어 있음), 그 뒤에는 소비 확인을 받으며 +0. 물건·점수·사실·수첩·꺼낼 기록을 함께 반영한다.
- AI 연결은 기존 작은 모험 연결을 재사용한다. 최근 300/전체/범위/증분을 고르고, 비용·분량 어림을 본 뒤 직접 시작한다. 숨김/시스템 메시지와 마크업은 제외한다.
- 청크 순차 분석, 원문 대조, 기본 정밀 확인, 중복 병합, 별칭, 중단/재개, 원문 변경·실패 묶음 재시도. 인용 검증은 해석 정확도 보증이 아니므로 사용자 검토 단계가 항상 남는다.
- 후보는 검토 목록 60개와 `scan.pending`으로 모두 저장한다. 넘친 후보가 있으면 다음 분석 요청을 멈추고 검토 후 이어 간다. 300개 기록 상한에서도 자동 삭제 대신 정리 안내를 한다.
- 원문 수정/스와이프로 연결이 달라져도 승인 기록을 자동 삭제하지 않는다. 다른 채팅으로 이동하면 진행 중 응답을 새 채팅에 저장하지 않는다.
- 유대 20은 선호도 단서 자리. 40·60·80·100 특별 활동/보상과 두아트 유대량은 별도 승인 전이므로 임의로 만들지 않았다. 점수만으로 RP 감정·관계·대사를 만들거나 주입하지 않는다.

## 검증

- `node tools/bond/test.mjs`: 마이그레이션, 점수 분리, 일행/하루 제한, UID 중복 소비 방지, 인용 조작·대명사·감정 단정, 맥락 근거, 긴 단일 메시지 분할, 75개 후보, 이어 읽는 사건, 중단/재개, 실패 보존, 채팅 전환·분석 중 원문 수정.
- `tools/bond/ai-browser.cjs`: 실제 SillyTavern UI→`callConn`→로컬 가짜 AI. 시작 전 0회 호출, 추출·정밀 2회, 후보 60+15 저장, 두 번의 승인으로 75개 모두 기록, 점수 0 유지, 직접 기록 `both`, AI 꺼짐. [결과](screenshots/ai-verification.json).
- `tools/bond/browser.cjs`: **5테마×밝음/어두움×320/412/1280 = 30조합**. 창 경계·가로 넘침·이름 줄바꿈·프레임 잘림·열 수·내부 스크롤·탭·게이지 0/12/100·선물 버튼을 확인했다. 누락된 Bond 이미지 없음. [결과](screenshots/verification.json).
- 기존 검사: [낮밤/맵/이동](checks/map.json), [가방/일행/터치/기존 UI](checks/existing-ui.json), [테마·키보드·저장](checks/themes.json). 기존 맵 낮/밤 승인 그림의 검사 픽셀 차이는 0이었다.
- 실제 유료 AI 계정으로 RP 의미 판별 정확도를 측정한 것은 아니다. 호출·저장·검토 경로는 가짜 AI와 합성 원문으로 검증했다.
