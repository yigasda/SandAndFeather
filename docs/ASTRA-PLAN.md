# 아스트라 작업 계획 — 단계별

2026-10-11 사용자 정리. **위에서부터 순서대로, 아래로 갈수록 나중 일이다.** 한 번에 하나씩 진행한다. 한 단계 안에서도 시안 하나를 먼저 보여 주고, 사용자 확인을 받은 뒤 나머지로 넓힌다.

**지금 어디까지 왔는지는 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md) 4절 표에서 본다.** 이 계획서에는 단계와 기준만 적는다.

공통 원칙은 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md)를 따른다.
- 채택된 실제 파일을 베이스로 요청한 부분만 고친다.
- 최신 수정본, 사용자 채택본, 게임 적용본을 구분해서 기록한다.
- 게임 적용은 사용자가 파일을 묶어서 넘기면 오푸스가 한꺼번에 한다.

## 1단계 — 안채 마무리: 긴 회랑 끝통로 넓히기

안채는 거의 다 됐다. 수정만 남았다.

**문제.** 긴 회랑의 끝통로는 지금 끝 기둥 바깥으로 폭이 약 0.6칸(약 50px)뿐이다. 소망은 약 1칸 폭이라 통로에 들어가면 벽 밖으로 툭 튀어나와 보인다.

**요청.** 회랑을 가로로 조금만 늘려 좌우 입구를 넓힌다. **세로도 같이 맞춘다.**

**세로 높이 맞추기.** 세부맵 세로가 지금 세 종류다. 방·부엌·식사 공간·성소·열주 계단·지붕·우물 마당은 887px(11칸), 긴 회랑 5장은 724px(9칸), 연못 회랑은 1086px(14칸)이다. 폰 화면은 세로로 약 15칸이 보여서, 회랑에서만 위아래 검은 띠가 두껍고 그림이 납작하게 떠 보인다. 회랑을 넓힐 때 세로도 **887px(11칸)**으로 늘려 방들과 높이를 맞춘다. 위로는 천장·보를, 아래로는 바닥·난간을 이어 그리고, 기존 그림은 가운데에 픽셀 그대로 둔다. 위아래에 얼마씩 더할지는 그림에 맞게 정하되, 원본이 놓인 위치를 꼭 적는다. 연못 회랑(14칸)은 화면에 거의 맞고 카메라가 따라가므로 그대로 둔다.

| 대상 | 지금 | 비고 |
|---|---|---|
| 안쪽 복도 `exits-v2/inner-corridor-wide-v1.png` | 2172×724, 27×9칸 | **이것부터 먼저.** 확인받은 뒤 나머지 4장 |
| 중앙 회랑 `exits-v2/central-gallery-v1.png` | 2172×724 | |
| 동쪽 회랑 `exits-v2/east-gallery-v1.png` | 2172×724 | 사용자 채택본(항아리 제거)을 베이스로 |
| 서쪽 회랑 `exits-v2/west-gallery-v1.png` | 2172×724 | |
| 방문 회랑 `exits-v2/room-entrances-wide-v1.png` | 2172×724 | |

**오푸스가 게임에 맞추기 쉬운 조건.** 1칸은 약 80px이다.
- 기존 그림은 픽셀 그대로 두고 바깥만 넓힌다. 좌우에는 같은 폭을 더한다. 세로는 887px로 맞춘다. 원본은 (좌측 확장 폭, 위쪽 확장 높이)에 놓인다.
- 끝 기둥 바깥 통로 바닥이 **1.5칸(약 120px) 이상** 보이게 한다. 통로가 천장선 아래로 들어가는 깊이도 1칸 이상이면 걸어 들어가는 느낌이 산다.
- 늘리는 폭은 80px의 배수를 권장한다. 예를 들어 좌우 각 160px이면 2492×887, 31×11칸이다.
- 회랑은 밤 그림이 없다. 게임이 어둡게 처리한다. 낮 그림만 있으면 된다.
- 전달할 것: PNG, 늘린 폭과 높이, 원본 위치, 좌우 통로의 문턱과 통로 바닥 좌표(px). 문·아치(중앙 회랑 아치, 성소 문, 계단 통로, 방문 세 개, 아래 계단) 좌표도 새 그림 기준으로 적는다.

## 2단계 — 셋소호 동작 바리에이션

**베이스 정지12장·걷기36장 최종 채택 완료.** [final/](art/chibi-refresh/final/README.md)에서 캐릭터별16장을 사용한다. 세트 정지148, 소망 정지151, 호루스166(정면 정지·걷기105% 확대 포함). 사용자 요청으로 이전 시안·중복본은 삭제했다. git 기록으로만 복원하고 현행 자료와 섞지 않는다. 게임 적용은 별도다. 베이스를 다시 만들지 않는다.

**캔버스 규칙.** 기존 캔버스 규격을 참고한다. 규격을 참고한다는 뜻이며 이전 그림체를 재사용한다는 뜻이 아니다.
- 투명 PNG, 같은 배율.
- 정지 캔버스620×720, 발 기준점(310,662). 이전 규격의 기준 키는628px이다. 최종 정지는12장 공통 기준 키576px을 사용한다. 게임 표시 배율은 각 manifest의 referenceVisibleHeight를 따른다.
- 걷기는 360×400 셀 기준.
- 발 기준점이 모든 동작에서 같으면 게임에서 떨림 없이 바뀐다.

**진행 방법.** 동작 하나를 한 묶음으로 만든다(아래 "진행 순서"). 그리기 전에 [pose-guides](art/chibi-refresh/pose-guides/README.md)의 가이드를 깔고, 다 그리면 `tools/art/fit-scale.py`로 "맞음"을 확인한다.

**순서.** 2026-10-11 사용자와 오푸스가 조정했다. 위에서부터 한다.
1. **서 있기4방향·걷기4방향 완료.** 최종48장을 모든 후속 동작의 기준으로 사용한다.
2. **상호작용.** 문, 시장, 대화 어디서나 쓴다.
3. **생활 동작 전부.** 사용자가 생활 바리에이션은 다 넣기로 했다.
4. **전투.** 3단계 두아트 확장 때 줄인 목록으로 한다(2-C).
5. **달리기는 보류.** 게임에 달리기 기능이 없다. 달리기를 넣기로 하면 그때 그린다.

### 동작 명세 읽는 법 — 동작 하나를 시작하기 전에

동작은 이름만 보고 만들지 않는다. 아래 표의 칸을 모두 따른다. 표에 없는 동작을 요청받으면 같은 칸을 채워 사용자에게 먼저 확인받는다.

| 칸 | 뜻 |
|---|---|
| **누가** | 이 동작을 그릴 캐릭터. 생활 활동은 대부분 플레이어인 소망만 한다. 세트·호루스는 따라다니므로 장면용 동작만 그린다 |
| **방향** | 그릴 방향과 이유. 소망이 어느 쪽에서든 다가가는 동작은 4방향. 게임이 정해진 자리에 세우는 동작은 정한 방향 하나 |
| **프레임·재생** | 장 수와 재생 방식. **한 번**은 끝나면 서 있기로 돌아가고, **반복**은 멈출 때까지 돈다. 걷기처럼 0-1-2-1이면 그렇게 적는다 |
| **느낌** | 어떤 기분으로 하는지. 캐릭터마다 다르면 따로 적는다 |
| **핵심 자세** | 프레임마다 무엇이 보여야 하는지 |

**공통 규칙.**
- 캔버스는 정지와 같다: 620×720, 발 기준점 (310, 662), 기준 키 576.
- 그리기 전에 [pose-guides](art/chibi-refresh/pose-guides/README.md)의 같은 캐릭터·방향 가이드를 깔고 그린다. 다 그리면 `tools/art/fit-scale.py`로 "맞음"을 확인한다.
- **진행 순서 — 동작 하나를 한 묶음으로.** 가이드와 `fit-scale.py`가 크기·비율을 잡아 주므로 한 장씩 확인받지 않는다.
  1. 동작 하나의 **모든 캐릭터 × 방향 × 프레임**을 한 번에 그린다. 예: 상호작용이면 표에 적힌 누가·방향·프레임 전부.
  2. 보내기 전에 전부 `fit-scale.py`로 "맞음"을 확인하고, 정지·걷기와 나란히 놓은 비교 시트와 재생 GIF를 만든다.
  3. 묶음째 보낸다. 사용자가 고칠 장만 짚으면 그 장만 고친다.
  - **예외:** 앉기, 잠들기처럼 처음 그리는 자세 종류는 대표 1장을 먼저 보여 확인받고 묶음으로 넓힌다.
- **서 있지 않는 동작(눕기 등)의 기준점.** 캔버스와 배율은 정지와 같다(머리 크기가 같아야 한다). 발 기준점 대신 몸 가운데(누우면 배꼽 근처)를 기준점으로 정해 manifest에 적는다. 게임은 이 점을 침대 가운데에 놓는다.
- **좌우를 뒤집어 쓰지 않는다.** 호루스 얼굴 문양, 세트 앞머리처럼 좌우가 다른 곳이 있다. 왼쪽, 오른쪽을 각각 그린다.
- 게임은 동작을 재생할 때 캐릭터를 대상 쪽으로 돌려 세운다. 그래서 "방향"에 적힌 방향만 있으면 된다.

### 2-B 생활 동작 — 전부 넣는다

방향은 게임 맵의 실제 가구 배치를 보고 정했다. 그 자리에 캐릭터를 세우면 어느 쪽을 보게 되는지가 기준이다. 모든 동작은 위 "공통 규칙"을 따른다. 서 있지 않는 동작(쪼그려 앉기, 앉기, 눕기)은 머리 크기를 정지와 같게 두고, 몸은 접히는 만큼 낮아진다. 키를 맞추려고 머리를 줄이지 않는다.

**순서.** 줍기 → 텃밭 → 낚시 → 요리(게임에 이미 있는 활동부터) → 앉기·먹기·읽기 → 잠들기 → 감정·인사.

#### 줍기 / 조사하기
| 칸 | 내용 |
|---|---|
| 누가 / 방향 | 소망 / **4방향.** 바닥 물건은 어느 쪽에서든 다가간다 |
| 프레임·재생 | 2, 한 번(각 0.2초) → 서 있기 |
| 핵심 자세 | 0: **무릎을 굽혀 쪼그려 앉기 시작.** 허리만 숙이지 않는다. 무릎이 앞으로 나오고 엉덩이가 내려감. 1: **완전히 쪼그려 앉아** 한 손을 바닥에 뻗음. 다른 손은 무릎 위. 치마는 무릎 위로 모임 |
| 방향별 | 앞: 무릎이 양옆으로 보이고 손이 발 앞 바닥에. 뒤: 등이 둥글게 말리고 발뒤꿈치가 살짝 들림. 옆: 접힌 다리 옆선이 보이고 손이 진행 방향 바닥에 |
| 느낌 | 궁금해서 들여다봄. 고개를 살짝 기울임 |
| 키 | 쪼그려 앉으면 정지 키의 약 65~70%. 머리 크기는 그대로, 발은 발끝 선 위 |

#### 텃밭 가꾸기
| 칸 | 내용 |
|---|---|
| 누가 / 방향 | 소망 / 정면 하나(밭 앞에 아래를 보고 섬) |
| 씨 뿌리기 | 2, 한 번. 쪼그려 앉은 자세(줍기 1과 같은 다리)에서 0: 손을 오므려 씨를 쥠, 1: 손을 펴서 흩뿌림. 작은 씨앗 점은 효과로 따로 얹음 |
| 물 주기 | 2, 반복. 서서 두 손으로 물병을 앞으로 기울임. 0: 기울이기 시작, 1: 더 기울임. 물줄기는 효과로 따로 |
| 수확하기 | 2, 한 번. 쪼그려 앉아 0: 두 손으로 줄기를 잡음, 1: 몸을 살짝 뒤로 젖히며 뽑아 올림(손이 가슴 높이) |
| 느낌 | 즐겁고 부지런함. 수확할 땐 뿌듯한 얼굴 |

#### 낚시하기
| 칸 | 내용 |
|---|---|
| 누가 / 방향 | 소망 / **오른쪽 옆 하나.** 옴보스 선착장은 판자 길이 아래로 뻗고 양옆이 물이다. 판자 끝 오른쪽 가장자리에서 물을 보고 선다 |
| 기다리기 | 2, 반복(0.5초씩). 두 손으로 낚싯대를 쥐고 대 끝이 앞·아래 물 쪽으로. 0과 1은 대 끝이 살짝 오르내리는 차이만 |
| 당기기 | 2, 한 번. 0: 대를 확 들어 올리며 몸을 뒤로 젖힘(무릎 살짝 굽힘). 1: 대가 크게 휘고 두 손이 머리 높이 |
| 소품 | 낚싯대는 캐릭터와 같은 PNG에 그린다. 줄과 찌는 효과로 따로(물 위에 놓여야 하므로) |
| 느낌 | 기다릴 땐 느긋하고 졸린 듯, 당길 땐 깜짝 놀라며 힘줌 |

#### 요리하기
| 칸 | 내용 |
|---|---|
| 누가 / 방향 | 소망 / **뒷모습 하나.** 부엌 조리대와 화덕이 모두 벽쪽(위)에 있어 그 앞에 서면 등이 보인다 |

### 2-C 전투 — 줄인 목록, 3단계 두아트 확장 때

지금 게임의 두아트 전투는 카드 버튼 방식이다. 공격, 기술, 주문, 엄호를 고르면 적이 한 번 받아친다. 아무도 죽지 않는다. 그래서 버튼에 맞는 동작만 그린다.

| 동작 | 프레임·재생 | 핵심 자세 (세트 / 호루스 / 소망) |
|---|---|---|
| **전투 대기** | 2, 반복(숨 쉬듯 어깨가 오르내림) | 무릎을 살짝 굽히고 발을 어깨너비보다 넓게. 세트: 주먹을 쥐고 몸을 앞으로 숙인 채 씩 웃음. 호루스: 한 손을 앞으로 펴고 눈을 가늘게, 날개처럼 팔을 살짝 벌림. 소망: 두 손을 가슴 앞에 모으고 긴장했지만 물러서지 않음 |
| **기본 공격** | 3, 한 번: 0 준비 → 1 타격 → 2 회복 → 대기 | 세트: 0 주먹을 뒤로 당김, 1 몸 전체로 앞으로 내지름(뒷발 끝이 들림), 2 주먹을 거둠. 호루스: 0 손을 뒤로, 1 손날로 앞을 그음, 2 손을 거둠. 소망: 0 지팡이나 막대를 들어 올림, 1 앞으로 휘두름, 2 놀란 듯 자세를 바로함 |
| **고유 기술** | 3, 한 번 | 세트 **강타**: 0 두 손을 깍지 껴 머리 위로, 1 내리찍음(무릎이 크게 굽음), 2 일어섬. 호루스 **하늘에서 내려치기**: 0 무릎을 굽혀 도약 준비, 1 공중(발이 발끝 선에서 40px 떨어짐, 팔을 날개처럼 펼침), 2 착지하며 손을 내리침. 소망 **엄호**: 0 동행 앞으로 한 발 나섬, 1 두 팔을 벌려 막아섬(얼굴은 겁먹었지만 버팀), 2 팔을 내림 |
| **주문** | 2, 한 번 | 0 두 손을 가슴 앞에 모아 힘을 모음(눈 감음), 1 두 손을 앞으로 뻗어 보냄(눈 뜸). 세트는 붉은 모래, 호루스는 금빛 문양 효과가 따로 얹힌다. 손 모양만 그린다 |
| **피격** | 1, 한 번(0.3초) | 상체가 뒤로 젖혀지고 한 발이 뒤로 밀림. 눈을 질끈 감음. 세트는 이를 악물고 버팀(덜 젖혀짐), 소망은 크게 움찔 |
| **회복** | 2, 반복(빛 효과가 도는 동안) | 0 고개를 숙이고 숨을 고름, 1 고개를 들고 어깨를 폄. 싸움 중 음식을 먹거나 쉼터에서 체력이 찰 때. 빛 효과는 따로 |
| **지침** | 1, 머묾 | 한쪽 무릎을 꿇고 한 손으로 땅을 짚음. 고개를 숙이고 숨을 몰아쉼. 원정에서 물러날 때 |

- **누가.** 소망과 그날 같이 간 동행(세트 또는 호루스). 셋 다 그린다.
- **방향은 하나.** 적이 한쪽에 있으니 한 방향(오른쪽을 보는 옆모습)만 그린다.
- **재생.** 대기·회복은 반복, 나머지는 한 번 재생하고 대기로 돌아온다.
- **뺀 것.** 방어(소망 엄호가 대신함), 회피(대기 자세에 효과만 얹음), 부상·넘어짐·쓰러져 있음·일어나기(아무도 죽지 않으니 "지침" 한 장으로).
- 전투 화면에 캐릭터를 어떻게 보일지(카드 안 작은 무대 등)는 그리기 전에 오푸스와 사용자가 먼저 정한다.

## 3단계 — 두아트 확장: 맵 4개 + 몬스터 + 효과
**새 맵의 화풍.** 기존 세부맵과 같은 화풍과 퀄리티로 만든다. 시작 전에 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md) 7-1절의 기준 파일을 열어 맞춘다.


**입구 → 탐색 회랑 → 숨은 신전 → 귀환의 문**으로 이어진다. 처음에는 입구로도 돌아갈 수 있고, 사건을 마치면 신전 뒤편에서 귀환문으로 가는 길이 열린다.

| 맵 | 구성과 역할 |
|---|---|
| **① 경계 동굴** | 포켓몬 동굴처럼 굽은 길·암벽·계단. 간단한 첫 전투와 작은 곁길 |
| **② 두아트 회랑** | 가장 넓은 탐색 맵. 수로·무너진 열주·갈림길·지름길, 여러 몬스터 |
| **③ 숨은 신전** | 이야기와 핵심 전투의 무대. 셋소호와 적이 움직일 넓은 중앙 공간 |
| **④ 귀환의 문** | 사건 후 도착하는 조용한 출구 맵. 어두운 물가와 귀환문, 마지막 대화 자리 |

④는 거대한 미로보다 긴장이 풀리는 작은 맵이 어울린다. ① 경계 동굴 1차 시안이 이미 있다. 세로형 1024×1536이고, 기록은 [DUAT-EXPANSION-ART-V1.md](DUAT-EXPANSION-ART-V1.md)에 있다.

**몬스터.** 구성은 일반 몬스터 4종 + 수문장 2종 + 문지기 1종 + 보스 1종이다.
- **일반 몬스터:** 새로 만들지 않고 **지금 게임에 있는 일반 몬스터 4종**을 디자인한다. 이름과 수치는 `data/duat.json`의 `enemies`에 있다.
- **문지기:** 채택. 디자인 대상으로 유지한다. 게임의 `문지기 아펩의 비늘`(`boss`, 체력 16 / 공격 4) 자리다.
- **수문장 2종:** 새 디자인. 맵마다 길목을 막는 강한 적이다. 아래 표 참고.
- **보스:** 정체는 기존 메인 이벤트에 맞춘다.

| 맵 | 강한 적 | 모습 | 자리 |
|---|---|---|---|
| ① 경계 동굴 | **작은 수문장** — 예: 비늘에 물든 자칼 우두머리 | 비늘 때문에 커지고 사나워진 자칼 | 동굴 출구 앞. 첫 강적이라 공격 패턴은 단순하게 |
| ② 두아트 회랑 | **수문장** — 예: 검은 비늘의 석상 | 이마에 비늘이 박힌 거대 석상 병사 | 갈림길 끝, 지름길 문 앞 |
| ③ 숨은 신전 | **문지기 아펩의 비늘** (채택, 이름 유지) | 비늘을 갑옷처럼 두른 뱀머리 문지기 | 신전 문 앞 |
| ③ 숨은 신전 | **보스** | 기존 메인 이벤트에 맞춤. 아펩 본체는 아니다 | 중앙 무대 |
| ④ 귀환의 문 | 없음 | | 긴장을 푸는 곳 |

**아펩의 조각 — 공통 표식.**
- 아펩의 조각은 **보랏빛 검은 비늘 하나**로 통일한다. 강한 적의 몸 어딘가에 박혀 있다(가슴, 이마, 꼬리 끝 등). 비늘에서 검은 연기가 살짝 새어 나온다.
- 조각 자체를 몹으로 그리지 않는다. 비늘에 씌인 멀쩡한 강한 존재로 그린다. 이빨이나 비늘 한 조각만 덩그러니 있는 적은 만들지 않는다.
- 이름에 "아펩의 이빨"처럼 신체 부위를 그대로 쓰지 않는다. "비늘에 물든 ~", "검은 비늘의 ~"처럼 짓는다. 위 이름은 예시이고 확정이 아니다.
- 플레이하다 보면 강한 적마다 같은 비늘이 박혀 있다는 걸 알아채게 하는 복선이다.

**아펩 본체는 두아트 확장에 나오지 않는다.** 따로 대형 이벤트로 둔다. 예를 들어 라의 태양배를 타고 밤의 두아트를 건너면서, 배를 삼키려는 아펩을 세트가 막는 항해 같은 것이다. 신화에서 세트가 맡은 역할이다. 비늘들의 주인이 거기서 나온다.

체력이 높을수록 몸집과 위압감을 키운다. 일반 4종 < 수문장 < 문지기 < 보스 순서다. 실루엣과 움직임만 봐도 서로 구별되어야 한다.

몬스터마다 최소 대기·이동·공격·피격·소멸 동작이 필요하다. 셋소호와 같은 배율로 그리고, 발 기준점을 표시한다.

**효과.** 배경에 그려 넣지 않고 투명한 애니메이션으로 따로 만든다. 그래야 캐릭터 위치에 맞춰 재생할 수 있다.

| 효과 | 디자인 방향 |
|---|---|
| 기본 타격 | 짧은 베기·충격·돌가루 |
| 세트 주술 | 붉은 모래가 휘감기며 터지는 효과 |
| 호루스 주술 | 금빛 문양과 푸른 빛이 뻗는 효과 |
| 소망 기술 | 확정된 능력에 맞춰 색과 형태 결정 |
| 적의 저주 | 보랏빛 문양·검은 연기 |
| 회복·보호 | 부드러운 빛·보호막 |
| 적 소멸 | 몸이 작은 빛이나 모래 입자로 흩어짐 |

**제작 순서.**
1. ① 경계 동굴 시안을 확정한다.
2. 그 위에 몬스터 한 종(예: 모래 자칼)과 타격 효과를 얹어 크기를 확인한다.
3. 그 기준으로 나머지 맵 3개와 몬스터를 만든다.

이렇게 하면 예쁜데 캐릭터나 효과가 안 보이는 문제가 줄어든다.

## 4단계 — 새 지역
**새 맵의 화풍.** 기존 세부맵과 같은 화풍과 퀄리티로 만든다. 시작 전에 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md) 7-1절의 기준 파일을 열어 맞춘다.


| 맵 | 주된 역할 | 색과 분위기 |
|---|---|---|
| 옴보스 | 시장·밭·훈련·일상 | 지금 승인된 따뜻한 색 유지 |
| 두아트 | 밤의 원정·유물 | 먹빛·보라·차가운 빛 |
| 세트 신전 안채 | 생활·휴식·개인 물건 | 상아색·적갈색·따뜻한 불빛 |
| 붉은 사막 | 세트 첫 만남·탐사·별 | 붉은 모래·큰 암반·넓은 여백 |
| 베헤데트 | 호루스 첫 만남·집무·관측 | 흰 석회암·남청색·맑은 빛 |
| 나일 강가·갈대밭 | 낚시·사냥·배 여행 | 청록 물빛·회녹색 갈대 |
| 테베 | 시장·왕궁·공적 기록 | 황토·청록 차양·금빛 |
| 토트 신전 | 해독·지식·별 지도 | 파피루스색·회청색·남색 |

하위 장소도 전부 포함한다: 밤 언덕, 절벽 난간, 마른 골짜기, 날개 회랑, 별 관측대, 왕궁 알현실, 동쪽 별채.

- **이동:** 옴보스에서 안채와 사막으로는 걸어간다. 다른 지역은 강가에서 배로 간다. 베헤데트는 설정상 하늘 궁정이라 지상 나루에서 하늘로 올라가는 이동을 한 단계 둔다.
- **시기 변화:** 같은 건물에 인물·소품·출입 상태만 바꾼다. 휴대폰은 이미 회수해서 소망이 간직하고 있으므로, 현재 사막에 다시 묻힌 보물로 두지 않는다. 서쪽 별채는 건물이 아니라 거주자가 달라진다.
- **제작 순서:** 사막·베헤데트 → 강가와 여행 지도 → 테베 → 토트 신전. 안채와 지붕은 이미 게임에 들어가 있다.

## 매 단계 전달 방식

- PNG 경로, 크기, 낮/밤 여부를 적는다.
- 사용자 채택 여부는 사용자가 한 말 그대로 기록한다.
- 출구·문턱 좌표는 px로 적는다.
- 미리보기는 Drive 링크로 준다. 휴대폰에서 바로 열리게 하기 위해서다.
- 게임 적용은 사용자가 파일을 넘길 때 오푸스가 한다. 맵 크기, 충돌, 깊은 문 판정, 가림, 밤 전환, 저장 연결까지 같이 맞춘다.
