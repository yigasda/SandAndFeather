# 아스트라 작업 계획 — 단계별

2026-10-11 사용자 정리. **위에서부터 순서대로, 아래로 갈수록 나중 일이다.** 한 번에 하나씩 진행한다. 한 단계 안에서도 시안 하나를 먼저 보여 주고, 사용자 확인을 받은 뒤 나머지로 넓힌다.

**지금 어디까지 왔는지는 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md) 4절 표에서 본다.** 이 계획서에는 단계와 기준만 적는다.

공통 원칙은 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md)를 따른다.
- 채택된 실제 파일을 베이스로 요청한 부분만 고친다.
- 최신 수정본, 사용자 채택본, 게임 적용본을 구분해서 기록한다.
- 게임 적용은 사용자가 파일을 묶어서 넘기면 오푸스가 한꺼번에 한다.

## 1단계 — 안채 마무리: 긴 회랑 끝통로 넓히기

안채는 거의 다 됐다. 수정만 남았다.

**문제.** 긴 회랑의 끝통로는 지금 끝 기둥 바깥으로 폭이 약 0.6칸(약 50px)뿐이다. 소망은 약 1칸 폭이라 통로에 들어가면 벽 밖으로 툭 튀어나와 보인다.

**요청.** 회랑을 가로로 조금만 늘려 좌우 입구를 넓힌다. **세로도 같이 맞춘다.**

**세로 높이 맞추기.** 세부맵 세로가 지금 세 종류다. 방·부엌·식사 공간·성소·열주 계단·지붕·우물 마당은 887px(11칸), 긴 회랑 5장은 724px(9칸), 연못 회랑은 1086px(14칸)이다. 폰 화면은 세로로 약 15칸이 보여서, 회랑에서만 위아래 검은 띠가 두껍고 그림이 납작하게 떠 보인다. 회랑을 넓힐 때 세로도 **887px(11칸)**으로 늘려 방들과 높이를 맞춘다. 위로는 천장·보를, 아래로는 바닥·난간을 이어 그리고, 기존 그림은 가운데에 픽셀 그대로 둔다. 위아래에 얼마씩 더할지는 그림에 맞게 정하되, 원본이 놓인 위치를 꼭 적는다. 연못 회랑(14칸)은 화면에 거의 맞고 카메라가 따라가므로 그대로 둔다.

| 대상 | 지금 | 비고 |
|---|---|---|
| 안쪽 복도 `exits-v2/inner-corridor-wide-v1.png` | 2172×724, 27×9칸 | **이것부터 먼저.** 확인받은 뒤 나머지 4장 |
| 중앙 회랑 `exits-v2/central-gallery-v1.png` | 2172×724 | |
| 동쪽 회랑 `exits-v2/east-gallery-v1.png` | 2172×724 | 사용자 채택본(항아리 제거)을 베이스로 |
| 서쪽 회랑 `exits-v2/west-gallery-v1.png` | 2172×724 | |
| 방문 회랑 `exits-v2/room-entrances-wide-v1.png` | 2172×724 | |

**오푸스가 게임에 맞추기 쉬운 조건.** 1칸은 약 80px이다.
- 기존 그림은 픽셀 그대로 두고 바깥만 넓힌다. 좌우에는 같은 폭을 더한다. 세로는 887px로 맞춘다. 원본은 (좌측 확장 폭, 위쪽 확장 높이)에 놓인다.
- 끝 기둥 바깥 통로 바닥이 **1.5칸(약 120px) 이상** 보이게 한다. 통로가 천장선 아래로 들어가는 깊이도 1칸 이상이면 걸어 들어가는 느낌이 산다.
- 늘리는 폭은 80px의 배수를 권장한다. 예를 들어 좌우 각 160px이면 2492×887, 31×11칸이다.
- 회랑은 밤 그림이 없다. 게임이 어둡게 처리한다. 낮 그림만 있으면 된다.
- 전달할 것: PNG, 늘린 폭과 높이, 원본 위치, 좌우 통로의 문턱과 통로 바닥 좌표(px). 문·아치(중앙 회랑 아치, 성소 문, 계단 통로, 방문 세 개, 아래 계단) 좌표도 새 그림 기준으로 적는다.

## 2단계 — 셋소호 동작 바리에이션

**베이스 정지12장·걷기36장 최종 채택 완료.** [final/](art/chibi-refresh/final/README.md)에서 캐릭터별16장을 사용한다. 세트 정지148, 소망 정지151, 호루스173(168 피부색 유지·16장 머리/몸통 비율 수정 채택). 사용자 요청으로 이전 시안·중복본은 삭제했다. git 기록으로만 복원하고 현행 자료와 섞지 않는다. 게임 적용은 별도다. 베이스를 다시 만들지 않는다.

**캔버스 규칙.** 기존 캔버스 규격을 참고한다. 규격을 참고한다는 뜻이며 이전 그림체를 재사용한다는 뜻이 아니다.
- 투명 PNG, 같은 배율.
- 정지 캔버스620×720, 발 기준점(310,662). 이전 규격의 기준 키는628px이다. 최종 정지는12장 공통 기준 키576px을 사용한다. 게임 표시 배율은 각 manifest의 referenceVisibleHeight를 따른다.
- 걷기는 360×400 셀 기준.
- 발 기준점이 모든 동작에서 같으면 게임에서 떨림 없이 바뀐다.

**진행 방법.** 동작 하나를 한 묶음으로 만든다(아래 "진행 순서"). 그리기 전에 [pose-guides](art/chibi-refresh/pose-guides/README.md)의 가이드를 깔고, 다 그리면 `tools/art/fit-scale.py`로 "맞음"을 확인한다.

**순서.** 2026-10-11 사용자와 오푸스가 조정했다. 위에서부터 한다.
1. **서 있기4방향·걷기4방향 완료.** 최종48장을 모든 후속 동작의 기준으로 사용한다.
2. **상호작용.** 문, 시장, 대화 어디서나 쓴다.
3. **생활 동작 전부, 줄인 목록으로.** 기본 1장, 움직임은 게임이 만든다(2-B 원칙). 말풍선·효과는 2-D.
4. **전투.** 전투 화면 설계를 정한 뒤 동작마다 1장(2-C).
5. **달리기는 보류.** 게임에 달리기 기능이 없다. 달리기를 넣기로 하면 그때 그린다.

### 동작 명세 읽는 법 — 동작 하나를 시작하기 전에

동작은 이름만 보고 만들지 않는다. 아래 표의 칸을 모두 따른다. 표에 없는 동작을 요청받으면 같은 칸을 채워 사용자에게 먼저 확인받는다.

| 칸 | 뜻 |
|---|---|
| **누가** | 이 동작을 그릴 캐릭터. 셋 다 앞장설 수 있어 생활·전투 동작은 대부분 셋 다 그린다 |
| **방향** | 그릴 방향과 이유. 소망이 어느 쪽에서든 다가가는 동작은 4방향. 게임이 정해진 자리에 세우는 동작은 정한 방향 하나 |
| **프레임·재생** | 장 수와 재생 방식. **한 번**은 끝나면 서 있기로 돌아가고, **반복**은 멈출 때까지 돈다. 걷기처럼 0-1-2-1이면 그렇게 적는다 |
| **느낌** | 어떤 기분으로 하는지. 캐릭터마다 다르면 따로 적는다 |
| **핵심 자세** | 프레임마다 무엇이 보여야 하는지 |

**공통 규칙.**
- **표정은 작게 봐도 보이는 것만 바꾼다.** 게임에서 캐릭터 키는 약 31px라 얼굴이 아주 작다. 입 모양·눈썹 차이는 안 보인다. 바꾸는 것은 **눈 모양**(감은 눈, ^^ 웃는 눈, 동그랗게 뜬 눈, 반쯤 감은 눈, 찡그린 눈)과 **볼 홍조 진하기**다. 동작마다 표의 "표정" 칸을 따른다. 결은 캐릭터마다: 세트는 변화가 적게, 호루스는 단정하게, 소망은 가장 크게. 표정이 바뀌어도 눈 위치·크기·색과 얼굴 윤곽은 최종 정지 그대로다.
- 캔버스는 정지와 같다: 620×720, 발 기준점 (310, 662), 기준 키 576.
- 그리기 전에 [pose-guides](art/chibi-refresh/pose-guides/README.md)의 같은 캐릭터·방향 가이드를 깔고 그린다. 다 그리면 `tools/art/fit-scale.py`로 "맞음"을 확인한다.
- **진행 순서 — 동작 하나를 한 묶음으로.** 가이드와 `fit-scale.py`가 크기·비율을 잡아 주므로 한 장씩 확인받지 않는다.
  1. 동작 하나의 **모든 캐릭터 × 방향 × 프레임**을 한 번에 그린다. 예: 상호작용이면 표에 적힌 누가·방향·프레임 전부.
  2. 보내기 전에 전부 `fit-scale.py`로 "맞음"을 확인하고, 정지·걷기와 나란히 놓은 비교 시트와 재생 GIF를 만든다.
  3. 묶음째 보낸다. 사용자가 고칠 장만 짚으면 그 장만 고친다.
  - **예외:** 앉기, 잠들기처럼 처음 그리는 자세 종류는 대표 1장을 먼저 보여 확인받고 묶음으로 넓힌다.
- **서 있지 않는 동작(눕기 등)의 기준점.** 캔버스와 배율은 정지와 같다(머리 크기가 같아야 한다). 발 기준점 대신 몸 가운데(누우면 배꼽 근처)를 기준점으로 정해 manifest에 적는다. 게임은 이 점을 침대 가운데에 놓는다.
- **머리 크기는 어떤 자세에서도 정지와 같다.** 쪼그리거나 앉거나 누워 몸이 작아져도 머리는 줄이지 않는다. 자세를 캔버스에 맞추려고 그림 전체를 줄이지 않는다. 몸만 접혀서 키가 낮아진다. 확인: `action-check.py`의 머리 맞춤이 ×1.00~1.12(×1.15 넘으면 머리가 작다). 세트 줍기 182에서 머리가 ×1.2~1.36(약 1/6~1/4 작음)이라 다시 그렸다.
- **프레임마다 눈에 띄게 달라야 한다.** 2장짜리 동작에서 0과 1이 거의 같으면 게임에서 한 장처럼 보인다. 몸 전체가 움직이는 동작(쪼그리기, 앉기, 당기기)은 0과 1의 키가 정지 키의 6% 이상 다르고 윤곽이 크게 바뀌어야 한다(`action-check.py`의 윤곽 차이 12% 이상). 손만 움직이는 동작(손 뻗기)은 작아도 되지만 손 위치는 분명히 달라야 한다.
- **0은 정지에서 이어지는 중간 단계다.** 첫 장에서 이미 끝 자세가 되면 정지 → 0이 툭 끊겨 보인다. 0은 정지와 마지막 장의 **중간쯤**이다. 예: 줍기 0은 무릎을 굽히며 내려가는 중(정지 키의 약 80~86%), 1은 완전히 쪼그림(65~75%). 0의 키가 마지막 장보다 낮거나 같으면 실패다. 채택된 기준: 소망 181, 호루스 182.
- **캐릭터 고유 외형은 어떤 자세에서도 그대로다.** 자세 때문에 머리카락을 새로 만들거나 늘리지 않는다. 특히 **호루스는 짧은 삐죽머리이고 뒷머리(목·어깨로 내려오는 머리)가 없다**([기준](art/chibi-refresh/notes/horus-hair-short.jpg)). 누워도, 옆모습이어도 머리카락은 귀 높이에서 끝나고, 삐죽 머리의 길이·개수는 정지와 같다. 옆모습을 그릴 때 머리를 위아래로 늘리지 않는다(잠들기 187에서 호루스 옆머리가 길어지고 목·어깨로 머리가 흘러내려 다시 그렸다). **호루스 머리는 평범한 남자 짧은 머리가 아니다.** 하이큐 이와이즈미처럼 위·바깥으로 뻗친 짧은 삐죽머리다: 머리 둘레 전체에 끝이 뾰족한 삐죽이 여러 개 사방(위·옆)으로 뻗고, 정수리 쪽이 높게 솟아 볼륨이 위로 있다. 옆머리도 삐죽하게 귀 윗부분까지 덮고, 앞머리는 이마 위에 작은 뾰족한 삼각형들이 아래로 몇 개 내려온 들쭉날쭉한 선이다. 어두운 남색 바탕에 밝은 파랑 하이라이트, 검은 외곽선. **하지 말 것:** 가르마 있는 단정한 머리, 매끈하게 빗어 넘긴 머리, 둥근 바가지·스포츠머리처럼 윤곽이 매끈한 머리, 납작한 정수리, 목·어깨로 내려오는 뒷머리. 그리기 전에 [기준](art/chibi-refresh/notes/horus-hair-short.jpg)과 최종 정지를 열고, 삐죽이 끝의 개수·길이·방향을 맞춘다.
- **머리 모양·크기는 정지 머리를 겹쳐서 맞춘다.** 기울거나 누운 머리는 `python3 tools/art/head-check.py --guide --who <누구> --view <방향> --at x,y --angle 도 --out <폴더>`로 정지 머리를 그 자리·기울기에 흐리게 깐 가이드를 만들어 그 위에 그린다. 다 그린 뒤 `head-check.py <png들> --out <폴더>`의 시트(빨강 = 정지 머리 윤곽)에서 머리카락·얼굴이 윤곽 밖으로 넘치거나 모자라지 않은지 본다.
- **팔다리 길이는 정지·걷기와 같다.** 굽힌 팔, 머리 뒤로 올린 팔, 뻗은 다리도 위팔·아래팔·다리 길이와 굵기는 정지와 같다. 굽혀서 짧아 보일 수는 있어도 길어지면 실패다(세트 상호작용 175, 잠들기 187 팔). `python3 tools/art/onion.py <정지.png> <그림.png> --out <파일>`로 겹쳐서 손끝·팔꿈치 위치를 본다.
- **몸의 중심선.** 정면·뒷모습에서 곧게 앉거나 누운 몸은 머리 가운데, 배(기준점), 두 발 사이 가운데가 한 세로선 위에 있다. 다리가 한쪽으로 비스듬히 빠져 몸이 쏠리면 실패다(잠들기 187 세트·호루스). 모로 웅크린 자세(소망 180)처럼 일부러 기운 자세만 예외. `action-check.py`의 "몸 쏠림"으로 확인한다.
- **같은 동작의 다른 캐릭터는 채택된 기준 그림의 구도를 따른다.** 시점, 기울기, 원근으로 줄어드는 정도, 머리 위치를 기준 그림과 같게 하고 팔다리 자세와 느낌만 캐릭터대로 바꾼다. 예: 잠들기는 소망 180, 줍기는 소망 181. `onion.py <기준.png> <그림.png> --anchor-a x,y --anchor-b x,y`로 기준점을 맞춰 겹쳐 본다.
- **프레임은 외곽선이 바뀌어야 한다.** 다음 프레임을 앞 프레임의 안쪽 명암·선만 고쳐서 만들지 않는다. 움직이는 부분(숨 쉬는 가슴·어깨, 그 위의 머리카락과 손)의 **바깥 외곽선이 실제로 움직여야** 게임에서 두 장으로 보인다. `onion.py <0.png> <1.png> --out <파일>`의 "윤곽 차이"가 3% 아래이고 바운딩 박스가 같으면 실패다(잠들기 187: 1.2~2.6%). `action-check.py`의 "외곽선 같음"으로도 걸린다.
- **보내기 전 동작 흐름 확인:** `python3 tools/art/action-check.py <png들> --out <폴더>` — 캐릭터·방향마다 정지 | 0 | 1을 나란히 놓고 키, 머리 맞춤, 윤곽 차이를 적는다. "볼 것 없음"이 아니면 시트를 보고 고친다. 정지 → 0 → 1 → 정지 GIF도 같은 속도로 직접 본다. 같이 돌릴 것: `skin-check.py`(피부색), `onion.py`(0↔1, 왼쪽↔뒤집은 오른쪽, 기준 그림↔새 그림), 기울거나 누운 머리는 `head-check.py`. 이 시트들을 결과와 같이 보낸다.
- **좌우를 뒤집어 쓰지 않는다.** 호루스 얼굴 문양, 세트 앞머리처럼 좌우가 다른 곳이 있다. 왼쪽, 오른쪽을 각각 그린다.
- **피부색·피부톤은 최종 정지·걷기를 그대로 따른다.** 새 동작의 피부는 같은 캐릭터·같은 방향의 최종 정지와 걷기(`final/<누구>/idle`, `walk`)에서 스포이트로 뽑은 색만 쓴다. 기본색, 그림자색, 볼 홍조, 외곽선 색, 명암 단계 수와 위치가 모두 같아야 한다. 더 밝게·어둡게·노랗게·붉게 바꾸지 않고, 생성 결과의 피부색을 그대로 두지 않는다. 보내기 전에 정지·걷기와 같은 배율로 나란히 놓고 얼굴·팔·다리 피부를 확대해 비교하고, 색이 다르면 최종 팔레트 색으로 다시 칠한다. 상하좌우 네 방향 모두 확인한다. 숫자 확인: `python3 tools/art/skin-check.py <png들> --out <폴더>`.
- **팔 길이·굵기·손 크기는 좌우가 같다.** 왼쪽과 오른쪽은 뒤집어 쓰지 않고 각각 그리지만, 팔의 길이, 굵기, 손 크기와 모양, 뻗는 각도는 같은 프레임끼리 똑같아야 한다(거울에 비춘 것처럼). 정면·뒷면에서 양팔도 같은 길이다. 한쪽만 길거나 짧으면 실패다(세트 175에서 오른쪽 팔이 길어 다시 그렸다). 보내기 전에 왼쪽 그림을 좌우 반전해 오른쪽 위에 겹쳐 팔·손 윤곽을 비교한다. 비교용으로만 반전하고 반전한 그림을 보내지 않는다.
- 게임은 동작을 재생할 때 캐릭터를 대상 쪽으로 돌려 세운다. 그래서 "방향"에 적힌 방향만 있으면 된다.

| 소품 | 낚싯대는 캐릭터와 같은 PNG에 그린다. 줄과 찌는 그리지 않는다 |
| 표정 | 기다리기 **반쯤 감은 눈**(느긋·졸림), 당기기 **눈을 동그랗게** |
| 결 | 세트는 한 손으로 대충 쥐고 기대듯, 호루스는 두 손으로 곧게, 소망은 두 손 꼭 쥐고 신나게 |

#### 요리하기 — 3장
| 칸 | 내용 |
|---|---|
| 누가 / 방향 | 셋 다 / **뒷모습 하나**(부엌 조리대·화덕이 벽쪽) |
| 장 | 1장: 한 손에 국자를 들고 냄비를 젓는 팔꿈치가 등 뒤에서도 옆으로 보임, 다른 손은 냄비 손잡이 |
| 게임이 하는 것 | 젓는 흔들림(좌우로 살짝), 김 효과 |
| 표정 | 뒷모습이라 얼굴이 안 보인다. 머리 기울기로 신남을 보인다 |

#### 먹기 / 마시기 — 3장 (앉기와 이어서)
| 칸 | 내용 |
|---|---|
| 자리 | 식사 공간 식탁에서 **캐릭터마다 자리를 정한다:** 소망은 오른쪽 방석(왼쪽을 봄), 호루스는 왼쪽 방석(오른쪽을 봄), 세트는 앞 방석(뒷모습). 먹기는 그 방향 하나씩만 |
| 장 | 1장: 같은 캐릭터·방향의 **앉기 그림을 그대로 베이스로** 팔과 얼굴만 바꾼다. 잔이나 음식을 든 손이 입 가까이. 다리·몸·머리카락은 앉기와 픽셀이 같아야 한다 |
| 게임이 하는 것 | 앉기 장과 이 장을 번갈아 보여 2프레임 반복처럼 만든다. "냠" 효과 |
| 결 | 소망은 두 손으로 잔을 감쌈, 세트는 한 손으로 크게, 호루스는 단정하게 |
| 표정 | **^^ 웃는 눈**, 볼 홍조 조금 진하게. 세트(뒷모습)는 고개를 젖혀 마시는 모양으로 |

#### 기뻐하기 · 놀라기 · 쑥스러워하기 — 9장
| 칸 | 내용 |
|---|---|
| 누가 / 방향 | 셋 다 / **정면 하나**, 감정마다 1장 |
| 기뻐하기 | 소망: 두 주먹을 쥐고 위로, 발꿈치 살짝 듦. 세트: 씩 웃으며 팔짱. 호루스: 작게 미소 짓고 고개를 끄덕인 모양. 표정 **^^ 웃는 눈**. 통통 튀는 건 게임이 한다(그림은 발끝 선 위) |
| 놀라기 | 몸이 움찔 뒤로, 어깨가 올라감. 소망: 두 손을 가슴 앞에 모음. 세트: 한 발 앞으로 나서며 경계. 호루스: 눈을 가늘게 뜨고 한 손을 앞으로. 표정 **눈을 동그랗게**(호루스는 가늘게) |
| 쑥스러워하기 | 시선을 옆 아래로 피함. 소망: 두 손을 앞에서 꼼지락. 세트: 뒷머리를 긁음. 호루스: 고개를 돌리고 팔짱. 표정 **볼 홍조 진하게**, 눈은 옆으로 |
| 쓰임 | 기쁨: 좋은 걸 찾음·등급 오름·수확. 놀람: 두아트 적 등장·낚시 입질. 쑥스러움: 대화·이벤트 |

#### 읽기 — 2장
| 칸 | 내용 |
|---|---|
| 누가 / 방향 | 소망, 호루스 / **정면 하나**, 서서 두루마리를 두 손으로 펼쳐 들고 고개를 살짝 숙임(별 관측, 서고). 책상 앞 읽기는 걸상 앉기(뒷모습)를 쓴다 |
| 표정 | 집중한 눈. 소망은 고개를 갸웃 |

#### 텃밭·손 흔들기 — 그리지 않는다
- 씨 뿌리기·수확: 줍기(쪼그린 자세) + 씨앗·풀 효과, 수확 뒤 기뻐하기.
- 물 주기: 상호작용(손 뻗기) + 물줄기 효과.
- 손 흔들기: 말풍선 👋.

### 2-D 말풍선 아이콘·효과 — 아스트라가 그린다

캐릭터 그림이 아니라 그 위에 얹는 작은 그림이다. 셋이 같이 쓴다. 화풍은 최종 스프라이트와 같은 도트, 외곽선 색과 굵기도 맞춘다. 게임에서 아이콘은 머리 위에 약 10~12px, 효과는 그 자리에 작게 보인다.

| 묶음 | 그릴 것 | 규격 |
|---|---|---|
| 말풍선 아이콘 8개 | `!` `?` `♥` `♪` `💤` `👋` `💧`(땀) `💢`(화남) — 작은 흰 말풍선 안에 | 각 128×128 투명 PNG, 말풍선 꼬리가 아래 가운데 |
| 생활 효과 | 씨앗 흩뿌림, 물줄기, 김(요리), "냠"(음식 조각·반짝), 발견 반짝임, 낚싯줄+찌 | 각 128×128 또는 필요한 만큼, 투명 PNG. 반복이 필요한 것(김, 물줄기)은 2장 |
| 전투 효과 (전투 때) | 타격 번쩍, 회복 빛, 세트 붉은 모래, 호루스 금빛 문양 | 같은 규격 |

한 판(시트)에 모아 그리고, 각각 잘라 `effects/` 폴더에 이름을 붙여 낸다.

### 2-C 전투 — 줄인 목록 (전투 화면 설계를 사용자·오푸스가 먼저 정한 뒤에)

지금 두아트 전투는 카드 버튼 방식이다(공격, 기술, 주문, 엄호 → 적이 한 번 받아침, 아무도 죽지 않음). **셋 다, 오른쪽을 보는 옆모습 하나, 동작마다 1장.** 움직임은 게임이 그림을 움직여서 만든다.

| 동작 | 장 | 그림 (세트 / 호루스 / 소망) | 게임이 하는 것 |
|---|---|---|---|
| **대기** | 1 | 무릎을 살짝 굽히고 발을 넓게. 세트: 주먹을 쥐고 앞으로 숙여 씩 웃음. 호루스: 한 손을 앞으로 펴고 눈을 가늘게. 소망: 두 손을 가슴 앞에 모으고 긴장했지만 버팀 | 숨쉬기 |
| **기본 공격** | 1 | 치는 순간. 세트: 몸 전체로 주먹을 내지름(뒷발 끝이 들림). 호루스: 손날로 앞을 그음. 소망: 막대를 앞으로 휘두름 | 앞으로 내지르기, 타격 번쩍 |
| **고유 기술** | 1 | 세트 강타: 두 손 깍지로 내리찍음(무릎이 크게 굽음). 호루스: 팔을 날개처럼 펼친 공중 자세. 소망 엄호: 두 팔을 벌려 막아섬(겁먹었지만 버팀) | 호루스 점프 높이, 효과 |
| **주문** | 1 | 두 손을 앞으로 뻗어 보냄, 눈 뜸 | 붉은 모래 / 금빛 문양 효과 |
| **지침** | 1 | 한쪽 무릎을 꿇고 한 손으로 땅을 짚음, 고개 숙임 | |
| 피격 | 0 | 대기 그림 | 흔들림 + 빨갛게 번쩍 |
| 회복 | 0 | 대기 그림 | 빛 효과 |

**합계 15장**(셋 × 5). 표정은 그 장 안에: 공격·기술은 힘준 눈(세트는 씩 웃음), 지침은 찡그린 눈.

## 3단계 — 두아트 확장: 맵 4개 + 몬스터 + 효과
**새 맵의 화풍.** 기존 세부맵과 같은 화풍과 퀄리티로 만든다. 시작 전에 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md) 7-1절의 기준 파일을 열어 맞춘다.


**입구 → 탐색 회랑 → 숨은 신전 → 귀환의 문**으로 이어진다. 처음에는 입구로도 돌아갈 수 있고, 사건을 마치면 신전 뒤편에서 귀환문으로 가는 길이 열린다.

| 맵 | 구성과 역할 |
|---|---|
| **① 경계 동굴** | 포켓몬 동굴처럼 굽은 길·암벽·계단. 간단한 첫 전투와 작은 곁길 |
| **② 두아트 회랑** | 가장 넓은 탐색 맵. 수로·무너진 열주·갈림길·지름길, 여러 몬스터 |
| **③ 숨은 신전** | 이야기와 핵심 전투의 무대. 셋소호와 적이 움직일 넓은 중앙 공간 |
| **④ 귀환의 문** | 사건 후 도착하는 조용한 출구 맵. 어두운 물가와 귀환문, 마지막 대화 자리 |

④는 거대한 미로보다 긴장이 풀리는 작은 맵이 어울린다. ① 경계 동굴 1차 시안이 이미 있다. 세로형 1024×1536이고, 기록은 [DUAT-EXPANSION-ART-V1.md](DUAT-EXPANSION-ART-V1.md)에 있다.

**몬스터.** 구성은 일반 몬스터 4종 + 수문장 2종 + 문지기 1종 + 보스 1종이다.
- **일반 몬스터:** 새로 만들지 않고 **지금 게임에 있는 일반 몬스터 4종**을 디자인한다. 이름과 수치는 `data/duat.json`의 `enemies`에 있다.
- **문지기:** 채택. 디자인 대상으로 유지한다. 게임의 `문지기 아펩의 비늘`(`boss`, 체력 16 / 공격 4) 자리다.
- **수문장 2종:** 새 디자인. 맵마다 길목을 막는 강한 적이다. 아래 표 참고.
- **보스:** 정체는 기존 메인 이벤트에 맞춘다.

| 맵 | 강한 적 | 모습 | 자리 |
|---|---|---|---|
| ① 경계 동굴 | **작은 수문장** — 예: 비늘에 물든 자칼 우두머리 | 비늘 때문에 커지고 사나워진 자칼 | 동굴 출구 앞. 첫 강적이라 공격 패턴은 단순하게 |
| ② 두아트 회랑 | **수문장** — 예: 검은 비늘의 석상 | 이마에 비늘이 박힌 거대 석상 병사 | 갈림길 끝, 지름길 문 앞 |
| ③ 숨은 신전 | **문지기 아펩의 비늘** (채택, 이름 유지) | 비늘을 갑옷처럼 두른 뱀머리 문지기 | 신전 문 앞 |
| ③ 숨은 신전 | **보스** | 기존 메인 이벤트에 맞춤. 아펩 본체는 아니다 | 중앙 무대 |
| ④ 귀환의 문 | 없음 | | 긴장을 푸는 곳 |

**아펩의 조각 — 공통 표식.**
- 아펩의 조각은 **보랏빛 검은 비늘 하나**로 통일한다. 강한 적의 몸 어딘가에 박혀 있다(가슴, 이마, 꼬리 끝 등). 비늘에서 검은 연기가 살짝 새어 나온다.
- 조각 자체를 몹으로 그리지 않는다. 비늘에 씌인 멀쩡한 강한 존재로 그린다. 이빨이나 비늘 한 조각만 덩그러니 있는 적은 만들지 않는다.
- 이름에 "아펩의 이빨"처럼 신체 부위를 그대로 쓰지 않는다. "비늘에 물든 ~", "검은 비늘의 ~"처럼 짓는다. 위 이름은 예시이고 확정이 아니다.
- 플레이하다 보면 강한 적마다 같은 비늘이 박혀 있다는 걸 알아채게 하는 복선이다.

**아펩 본체는 두아트 확장에 나오지 않는다.** 따로 대형 이벤트로 둔다. 예를 들어 라의 태양배를 타고 밤의 두아트를 건너면서, 배를 삼키려는 아펩을 세트가 막는 항해 같은 것이다. 신화에서 세트가 맡은 역할이다. 비늘들의 주인이 거기서 나온다.

체력이 높을수록 몸집과 위압감을 키운다. 일반 4종 < 수문장 < 문지기 < 보스 순서다. 실루엣과 움직임만 봐도 서로 구별되어야 한다.

몬스터마다 최소 대기·이동·공격·피격·소멸 동작이 필요하다. 셋소호와 같은 배율로 그리고, 발 기준점을 표시한다.

**효과.** 배경에 그려 넣지 않고 투명한 애니메이션으로 따로 만든다. 그래야 캐릭터 위치에 맞춰 재생할 수 있다.

| 효과 | 디자인 방향 |
|---|---|
| 기본 타격 | 짧은 베기·충격·돌가루 |
| 세트 주술 | 붉은 모래가 휘감기며 터지는 효과 |
| 호루스 주술 | 금빛 문양과 푸른 빛이 뻗는 효과 |
| 소망 기술 | 확정된 능력에 맞춰 색과 형태 결정 |
| 적의 저주 | 보랏빛 문양·검은 연기 |
| 회복·보호 | 부드러운 빛·보호막 |
| 적 소멸 | 몸이 작은 빛이나 모래 입자로 흩어짐 |

**제작 순서.**
1. ① 경계 동굴 시안을 확정한다.
2. 그 위에 몬스터 한 종(예: 모래 자칼)과 타격 효과를 얹어 크기를 확인한다.
3. 그 기준으로 나머지 맵 3개와 몬스터를 만든다.

이렇게 하면 예쁜데 캐릭터나 효과가 안 보이는 문제가 줄어든다.

## 4단계 — 새 지역
**새 맵의 화풍.** 기존 세부맵과 같은 화풍과 퀄리티로 만든다. 시작 전에 [ASTRA-HANDOFF.md](ASTRA-HANDOFF.md) 7-1절의 기준 파일을 열어 맞춘다.


| 맵 | 주된 역할 | 색과 분위기 |
|---|---|---|
| 옴보스 | 시장·밭·훈련·일상 | 지금 승인된 따뜻한 색 유지 |
| 두아트 | 밤의 원정·유물 | 먹빛·보라·차가운 빛 |
| 세트 신전 안채 | 생활·휴식·개인 물건 | 상아색·적갈색·따뜻한 불빛 |
| 붉은 사막 | 세트 첫 만남·탐사·별 | 붉은 모래·큰 암반·넓은 여백 |
| 베헤데트 | 호루스 첫 만남·집무·관측 | 흰 석회암·남청색·맑은 빛 |
| 나일 강가·갈대밭 | 낚시·사냥·배 여행 | 청록 물빛·회녹색 갈대 |
| 테베 | 시장·왕궁·공적 기록 | 황토·청록 차양·금빛 |
| 토트 신전 | 해독·지식·별 지도 | 파피루스색·회청색·남색 |

하위 장소도 전부 포함한다: 밤 언덕, 절벽 난간, 마른 골짜기, 날개 회랑, 별 관측대, 왕궁 알현실, 동쪽 별채.

- **이동:** 옴보스에서 안채와 사막으로는 걸어간다. 다른 지역은 강가에서 배로 간다. 베헤데트는 설정상 하늘 궁정이라 지상 나루에서 하늘로 올라가는 이동을 한 단계 둔다.
- **시기 변화:** 같은 건물에 인물·소품·출입 상태만 바꾼다. 휴대폰은 이미 회수해서 소망이 간직하고 있으므로, 현재 사막에 다시 묻힌 보물로 두지 않는다. 서쪽 별채는 건물이 아니라 거주자가 달라진다.
- **제작 순서:** 사막·베헤데트 → 강가와 여행 지도 → 테베 → 토트 신전. 안채와 지붕은 이미 게임에 들어가 있다.

## 매 단계 전달 방식

- PNG 경로, 크기, 낮/밤 여부를 적는다.
- 사용자 채택 여부는 사용자가 한 말 그대로 기록한다.
- 출구·문턱 좌표는 px로 적는다.
- 미리보기는 Drive 링크로 준다. 휴대폰에서 바로 열리게 하기 위해서다.
- 게임 적용은 사용자가 파일을 넘길 때 오푸스가 한다. 맵 크기, 충돌, 깊은 문 판정, 가림, 밤 전환, 저장 연결까지 같이 맞춘다.
