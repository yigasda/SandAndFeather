## 2. 채택 몹 10장 — 지금은 추가 제작 보류

원본: [몹/하위몹/고대장치](../몹/하위몹/고대장치/) · [크기·해시·채택 기록](../몹/하위몹/고대장치/manifest.json).

| 파일 접두사 | 디자인 | 채택 상태 파일 |
|---|---|---|
| `ring` | 고리형. 세 석판이 둘러싼 청록 핵·금속 고리와 아래 앙크 추 | `idle`, `prepare`, `attack`, `hit`, `disappear` 각 1장 |
| `hourglass` | 모래시계형. **윗돌의 큰 눈**, 중앙 청록 핵과 청동 장치, **작은 아래 앙크 돌** | 같은 5상태 각 1장 |

예: `hourglass-prepare.png`. 2종 × 5상태 = **10장**. 접두사는 파일 식별자이며 게임 데이터 ID·최종 몹 이름 확정과는 별개다.

### 다시 제작할 때 반드시 유지할 기준

- 원신 매트릭스는 부유·분리되는 고대 장치라는 발상만 참고했다. 삼각 몸체·분리 창·보라색 핵·문양을 복제하지 않는다. 실제 디자인은 해당 맵의 사암·청동·금색·청록 장치에서 가져온다.
- **맵과 같은 위에서 내려다보는 3/4 투시.** 돌 윗면이 보이고 아랫면이 과하게 드러나지 않아야 한다. 정면 제품 렌더처럼 보이던 초기 시안은 기준으로 쓰지 않는다.
- **기존 세부맵 수준의 도트.** 큰 픽셀 덩어리·계단진 외곽선·제한된 명암으로 표현한다. 미세한 균열·가는 반사광·매끈한 그라데이션을 늘려 일반 일러스트처럼 만들지 않는다. 정교함보다 맵에서의 일치가 우선이다.
- 실제 채택 몹과 맵을 열어 비교한다. 반려된 세밀한 시안이 아니라 현재 GitHub PNG를 생성 참고로 사용한다.
- 준비는 부품을 모으고 긴장을 드러냄, 공격은 부품을 열어 핵을 드러냄, 피격은 살아 있는 상태에서 부품이 흔들림, 소멸은 핵이 꺼지고 부품이 분리되는 상태로 구분한다. 투사체나 큰 효과는 따로 처리한다.

### 그림 채택과 게임 적용을 구분

10장은 채택 원본이다. 캔버스 크기·기준점·상태 간 배율을 게임용으로 정렬하는 일은 별도이며 manifest도 이를 명시한다. 이미 완성된 아틀라스나 검증된 애니메이션이라고 말하지 않는다.

좌우 반전, 둥둥 떠 있기, 확대·축소는 대화에서 검토한 구현 방향이다. 기하학형 몹의 반전은 조명과 문양을 확인한 뒤 사용하고, 부유는 충돌 기준점과 분리한 그리기 위치·그림자로 표현한다. 반복 확대·축소만으로 준비·피격 동작을 대체하지 않는다. 실제 구현은 최신 필드 전투 계획과 사용자 지시를 따른다.

## 3. 나머지 몹은 재개할 때 정리할 것

[PLAN 3단계](ASTRA-PLAN.md)의 기존 일반 4종·수문장·문지기 설정을 출발점으로 삼되, 확장된 7개 맵에 맞춰 디자인한다. 고대장치 2종은 이미 사용자가 추가 채택했다. 옛 “일반 4종만”을 이유로 제외하지 않는다.

- 일반 몹: 그림자·모래 자칼·갈대 사이 뱀·아미트의 새끼는 기존 데이터의 대상. 신규 시각 디자인 완료로 간주하지 않는다.
- 나머지 방의 몹 배치·추가 종수·이름·능력치는 전부 확정된 것이 아니다. 특히 석상 수문장과 문지기를 어느 방에 둘지는 최신 적용 계획과 함께 확인한다.
- 강한 적의 공통 단서는 몸에 박힌 **보랏빛 검은 비늘 하나와 약한 검은 연기**. 비늘 조각만 덩그러니 있는 생물을 만들지 않는다.
- 아펩 본체는 이번 최종 보스가 아니다. 별도 대형 이벤트용 설정을 유지한다.
- 귀환의 문은 전투 없는 공간이다. 효과 묶음도 이번 10장 채택에 포함되지 않는다.

## 4. 저장·전달과 재개 절차

1. 최신 main을 받아 [현재 상태](ASTRA-DRAW-STATE.md)와 이 문서를 확인한다. 몹 보류를 해제하거나 다음 큰 작업을 지정한 사용자 지시가 있는지 먼저 확인한다.
2. 맵 작업이면 [MAP](ASTRA-MAP.md), 몹 작화면 [SPRITE](ASTRA-SPRITE.md)와 PLAN 해당 절, 게임 적용이면 [필드 전투 계획](DUAT-FIELD-COMBAT-PLAN.md)과 OPUS-HANDOFF를 읽는다. 오래된 호루스 재작화로 돌아가지 않는다.
3. 필요한 **채택 이미지 자체를 열고** 비교한다. manifest로 파일과 버전을 식별한다. 본 적 없는 자료를 봤다고 기록하지 않는다.
4. 새 그림은 사용자 지정 범위만 만들고 비교한다. 채택본은 보존하며 수정본과 반려본을 구분한다. GitHub 채택 폴더에는 채택한 PNG만 넣는다.
5. Drive 전달은 **최상단에 작업별 폴더를 만들어** 올린다. 스프라이트 폴더 안에 맵을 넣거나 최상단에 파일들을 흩뿌리지 않는다. ZIP 없이 PNG와 필요한 미리보기를 전달한다.
