기준: 사용자 지시 2026-10-19(레이튼식 전용 퍼즐 화면, 15부터, 높이 x·y·z 보류), [퍼즐 기믹 전달서](consult/desert/puzzle-mechanisms-2026-10-19.txt) 2026-10-19(OPUS 사막 계획서 퍼즐 부분 추출본). 원문의 제안·권장·미정은 확정으로 올리지 않는다. 정답·배치·보상을 새로 만들지 않는다.

> **2026-10-19 변경:** 15·16 빛 퍼즐은 실제 맵에서 걸으며 조작한다(사용자 지시, [전달서 v2](consult/desert/puzzle-mechanisms-v2-inworld-2026-10-19.txt)). 아래 15 전용 화면은 **기능 시제품**으로만 남긴다. 설계안 3개: [DESERT-PUZZLE15-DESIGNS.md](DESERT-PUZZLE15-DESIGNS.md). 문양·상형문자 같은 논리 퍼즐은 전용 화면을 쓸 수 있다.

## 방식

| 종류 | 어디서 | 예 |
|---|---|---|
| 조작 퍼즐 | **전용 퍼즐 화면**: 맵의 장치 앞에서 말 걸기 → 퍼즐만 크게 보이는 카드, 닫으면 그 자리 맵 | 거울(15·16 반사판), 문양(09·13·14), 상형문자, 19 관측 고리 |
| 이동 퍼즐 | **맵 안**: 캐릭터가 걸어서 | 17·16 운반석 집기·꽂기·회수, (압력판은 원문에 구체 퍼즐이 없어 만들지 않음) |

- 전용 화면은 카드(`src/ui/popups.js`)다. 열린 동안 캐릭터 이동·말 걸기·필드 전투(`window.js frame`: 카드가 열리면 이동과 onFrame 팩을 건너뜀)가 멈춘다. 화면 밖을 눌러도 닫히지 않는다(`modal`). 닫기 버튼으로만 맵에 돌아간다.
- 조작 상태는 채팅마다(`s.puzzles[puzzleId]`), 조작할 때마다 저장. 닫았다 다시 열면 이어서. **처음으로**는 조작만 처음으로, 해결 기록(`solvedEver`, `solvedDay`)과 보상 수령(`claimed`)은 그대로.
- 화면을 연 채팅이 바뀌면(채팅 전환) 옛 화면의 조작은 무시하고 화면을 닫는다(chatId·상태 객체 대조).
- 광선 경로·점등은 저장하지 않고 상태에서 다시 계산한다(`src/packs/puzzle/optics.js`, 순수 함수).

## 15 열주홀 반사광 입문 (`desert.colonnade.mirror`)

- 맵: `desert_colonnade`(15). 채택 그림 그대로, T1E·T2·16 출입은 아직 없음(시험 이동으로만). 받침 앞 바닥(1248, 605)에서 말 걸기.
- 전용 화면은 위에서 본 평면 100×60: x는 그림 그대로(그림 x ÷ 1774 × 100), 위쪽이 위층 테라스와 뒷벽. 광원(오른쪽 놋쇠 입구, 왼쪽으로 쏨) → 받침 위 반사판 → 위층 뒷벽 고리 수신부. 테라스의 기둥 받침 두 개는 벽(빛을 막음), 빛의 길 밖.
- 반사판: 누를 때마다 45° (`/` → `—` → `\` → `|`). 양면 반사. 시간 제한·자동 회전·봉인석 없음.

| 상태 | 반사판 | 빛 | 결과 |
|---|---|---|---|
| 0 (처음) | `/` | 아래로 꺾여 아래 벽 | 꺼짐 |
| 1 | `—` | 옆면이라 지나가 왼쪽 벽 | 꺼짐 |
| 2 | `\` | 위로 꺾여 수신부 | **켜짐 = 해결** |
| 3 | `\|` | 되돌아가 오른쪽 벽 | 꺼짐 |

- 해결: 수신부가 켜지는 순간 `solvedEver = true`, `solvedDay = 게임 날`. 맵의 고리 수신부에 빛(지금 켜져 있을 때). **문·보상은 정해진 것이 없어 붙이지 않았다**(`claimed` 비어 있음).
- 검사: `node tools/st-test/puzzle-optics.mjs`(순수 13개: 네 상태 해답표, 정답 하나, 수신부 앞 벽, 반사 공식, 평행, 끝점, 순환, 무한선), `node tools/st-test/desert-b2.cjs`(게임 14개, 터치, 영상).

## 필요한 추가 그림 (최소, 지금은 임시 도형)

채택 배경은 다시 만들지 않는다. 퍼즐 화면의 임시 도형을 바꿀 때만:

| # | 그림 | 상태 | 쓰는 곳 |
|---|---|---|---|
| 1 | 반사판 머리(청동판, 위에서 본 모양) | 1장(코드가 45°씩 돌림) 또는 4방향 4장 | 퍼즐 화면 |
| 2 | 반사판 받침(위에서 본 원판) | 1장 | 퍼즐 화면 |
| 3 | 광원(놋쇠 입구, 위에서) | 1장 | 퍼즐 화면 |
| 4 | 수신부 고리 | 꺼짐·켜짐 2장 | 퍼즐 화면 |
| 5 | 퍼즐 화면 바닥(열주홀 바닥·테라스, 위에서) | 1장 | 퍼즐 화면 |
| 6 | 맵의 수신부 켜짐 | 고리 부분만 작은 패치 1장(배경과 정렬) | 맵(지금은 코드 빛) |

1~5가 없어도 퍼즐은 돌아간다. 6은 지금 코드로 그린 부드러운 빛이다.

## 16 빛 우물 결합 퍼즐 설계안 (두 방식 연결, 확인받을 것)

원문 초기 상태(제안): M1 활성 / M2 비활성 / S1 비어 있음 / K1 바닥(입구 근처) / R1 꺼짐 / 벽감 닫힘.

- **맵 안**(걸어서): K1(운반석)을 집어 S1(소켓)에 꽂는다. 돌의 위치는 하나뿐: 바닥 / 들고 있음 / 소켓 중 하나(`stoneLocations`). 꽂으면 M2가 켜진다.
- **전용 화면**(반사판 앞에서): M1·M2를 돌린다. 화면은 맵의 돌 상태를 **읽기만** 한다. M2가 꺼져 있으면 화면에 M2를 흐리게 그리고 "받침이 비어 있다" 표시, 누르면 돌릴 수 없다는 안내.
- 한 퍼즐 상태(`s.puzzles['desert.lightwell.main']`)에 `orient`(화면이 씀)와 `stones`(맵이 씀)를 같이 둔다. 둘 다 같은 해석기로 R1을 다시 계산한다.
- R1이 처음 켜지면 `solvedEver` → 벽감 열림(영구, 원문 권장안). 벽감 안 보상 수령은 맵에서 따로(`claimed[rewardId]`), 보상 내용은 미정.
- 처음으로(화면): 반사판 각도만. 돌은 맵에서 다시 집는다. 유적을 나가면 돌은 지정 위치로(사용자 추천안).
- 정해야 할 것: M1·M2·S1·K1·R1의 실제 그림 위 위치, 반사판 상태 수, 벽감 보상.
